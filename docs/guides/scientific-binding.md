# Scientific input binding in AI Research

AI Research accepts ordinary scientific language, such as “分辨率设置为0.8” or
“set the clustering resolution to 0.8.” The Interpreter associates the request
with Registry operations, parameters and captured source roles. Agent binds the
actual supplied values and recorded identities. Native scientific tools retain
parameter validity, algorithms and defaults.

Source-scoped native parameters on a BAM or external-fragments task bind to the
exact original attachment in its captured raw declaration. Its derived native
registration does not replace that identity or extend the parameter to a
downstream matrix, another file, or another input port.

## Canonical research preparation

A clear scientific objective reaches planning even when an external file or an
existing grouping field is missing. The Interpreter captures explicit researcher
values; it leaves requested UI field selection to Preparation on the actual
consumer source. A planned upstream grouping or representation connects through
its registered output instead of becoming a researcher field question.

Native declarations keep method scope: an explicitly requested `function_name`
uses the same registered `native_function` identity, while literal/evidence quote
the researcher's actual words. Canonical API names do not replace quoted Chinese
or other natural language. Keeping other native defaults leaves kwargs omitted;
it does not apply the clustering policy selector to unrelated operations.

The scientific preparation consolidation registers a selected-operation callback on
ToolSpec. The coordinator invokes that callback with the selected operation and
exact task context; package rules stay in scientific owners. The callback returns
applicable bindings, typed Requirements or a scientific diagnostic. Source roles
and physical encodings are Registry metadata. Existing uploads and authenticated
accepted outputs share a bounded observation adapter. An explicit byte-transparent
producer can expose the identical existing file; ordinary future transformations
remain symbolic.

Registered producers expose guaranteed grouping keys, representations, retained
slots/counts and mapping reference identity when relevant. Consumers can connect
those properties without asking researchers to name Agent-created fields. Presence
checks on existing graph slots establish native schema prerequisites only; runtime
still validates graph compatibility and numeric results. DPT requires a valid
source root or an explicit root_cell naming a selected observation. Row adaptation
invalidates inherited graph/root assumptions.

Parameter compilation and final admission use the same exact consumer/value
projection. Original quoted declarations and normalized owner vocabulary retain
separate provenance. Step/source/function scope and explicit native defaults remain
binding; an independent operation's omitted setting is not assigned its sibling's
value.


Preparation explanations use the same exact UI choice labels and the reduced
active answer ledger. A selected field remains visible as resolved while a later
resource requirement is pending; this presentation grants no new binding or
execution authority. Attachment use follows exact registered member identities
across source groups rather than reusing a positional source index.

The Web history exposes **Recheck preparation** for an unsubmitted task. Uploading
an absent source and rechecking captures new offers while preserving original
source pins. Recheck performs no science. If READY, **Run prepared analysis** is a
separate exact authorization, checked again before scientific reservation. A stale,
consumed or changed-base token cannot execute.

Unavailable ASW for required epiScanpy cluster counts retains the real failed Run,
accepted inputs and immutable admitted intent. Its current question uses canonical
Requirement/Answer controls, with the failed-Run reference held by the existing
prerequisite owner. An explicit count continues only that native operation, without
another ASW scan, Interpreter or Planner call. Direct Native Functions retains its
zero-provider failure behavior.

The uncommitted SPP-1R1 ownership migration is recorded in the
[continuation report](../../../agent-data/acceptance/scientific-plan-preparation/spp-1/repair-1/continuation-2/REPORT.md).
The [SPP-1R2 report](../../../agent-data/acceptance/scientific-plan-preparation/spp-1r2/REPORT.md)
records subsequent regression, integration and independent review evidence. Earlier
reports preserve their original findings; controlled software tests do not establish
live browser, provider or general scientific qualification.

Every legitimate research intake question has an Interaction-owned preparation
task, including missing-file, role, configured-resource, raw-source, annotation
and EpiZoo declarations. The public turn exposes `preparation_task_id`, including
questions with no offered files. A clear ordinary objective acquires its Candidate
before missing external-input Requirements, even without uploaded files. Specialized
raw/biological declaration intake can still precede acquisition when its task is
not yet sufficient to plan. A normalized wire-v4 Candidate is acquired once and
retained in the same task.
An explicit unsupported model response is terminal during candidate acquisition,
as it is during full-plan parsing; it does not trigger schema repair or a second
semantic call. Existing recovery for actual malformed candidates remains bounded.

Exact choices and grounded textual answers append scoped answers through the
canonical reducer. Questions, answer identity and replay belong to preparation;
Registry and scientific owners retain source validation, resource qualification,
method legality and original declaration grounding. Typed requirements distinguish
missing information from invalid graphs before an executable plan exists.

Replay uses the selected candidate's data references, exact source identities and
owner-declared dependencies. A source declaration follows registered dataset
lineage, not every input on which an output depends. Source-bound changes invalidate
affected component answers while preserving independent ones and immutable history.
Offered accepted context is not a declaration of every visible dataset.

Explicit `resume_task_id` revalidates a captured task in a new Interaction. It checks
consumed file bytes, selected resources and accepted context; qualified direct
source pins are checked against their recorded bytes. Changed consumed authority
returns INVALID. Restoring exact bytes permits a new explicit recheck. Missing external-input
Requirements can recapture explicitly supplied offers. Resume never acquires another
candidate or executes science, even when preparation becomes READY. It cannot
retry a task already submitted through SessionTurn. A consumed active Revision
change requires selecting the original scientific context under the existing
Revision owner; preparation does not grant a historical-context bypass.

An explicit resume captures newly available configured/shared references through
the existing resource discovery owner. It preserves prior definitions and selected
identities; replacing a captured definition produces INVALID under the same task.
Qualified model catalogs use the same explicit recapture: an omitted model may
be added later, while prior deterministic selections and explicit model identities
remain pinned. A rejected changed definition stays historical evidence and cannot
poison a later restoration of the exact catalog. Model completion is scoped to
the selected EpiZoo operation through its existing resource owner.
Saved rows do not reopen the current resource library during historical decoding.
Unchanged numeric declarations retain their original utterance through resume.
Independently missing members of the same kwargs object can be answered separately.
An exact member token binds only that member; grounded text binds the members
actually supplied, leaving other requirements unresolved.

Direct source pins are checked before READY and again after output selection,
before reservation. A changed source cannot be substituted by answering a pending
parameter. These pins include consumed secondary and nested multi-lane input files;
unconsumed offers and auto-bound model/reference closures retain their existing
owners. A file disappearing during candidate acquisition produces an ordinary
preparation integrity failure. Its attempted path is retained without a hash; restoring
the file later cannot supply an original byte identity or authorize that candidate.
Interrupted preparation uses the existing explicit recovery interface.
Recovery before reservation may close the interrupted response, after which explicit
task resume can recheck READY without execution. An already reserved scientific
turn stays under the Run owner and cannot be retried through preparation resume.

Competing answers are checked at the existing Session write boundary. A captured
losing answer receives a saved conflict response; historical validation checks its
exact captured question without requiring it still to be the newest question.
READY does not erase a later output-selection or execution-admission failure;
the status retains that error and states that scientific execution has not started.
If first acceptance rejects source drift after native execution, its saved failure
response is reused exactly. Response preparation does not regenerate or overwrite
that durable rejection, and no Revision is accepted by retrying presentation.

Strict compilation and preflight still precede atomic scientific reservation.
Accepted parameter evidence follows the same task ancestry and active answer
ledger. Repeated consumers retain their own declared values; planned and actual
values are checked exactly, including numeric types, without reopening science.
Native Functions remains direct and zero-provider. Genuine native-failure/ASW
parameter continuation and result-scoped edits retain their existing owners.
Historical pending records remain readable; retired source/resource/species answer
routes grant no new execution authority.

## Values and scope

Structured file/result selections and parameter entries are authoritative. A
model duplicate cannot override them or force their values through text grounding.
Explicit text declarations retain exact evidence spans. A unique numeric token,
quoted string, canonical choice or supported JSON value inside a unique verbatim
association quote can correct a mismatching model candidate. Multiple numeric
values in that quote require clarification; narrowing the association quote is
part of interpretation. Values are never clipped or replaced by defaults.

Boolean declarations support explicit true/false, yes/no, 是/否 and 开启/关闭.
Structured native kwargs keep independent member evidence. Number words and
arbitrary prose descriptions of lists/objects are not a general parsing language;
when exact mechanical recovery is unavailable, a local input question is used.
Semantic synonyms for scientific methods and categorical descriptions still rely
on interpretation. This is bounded value binding, not universal language accuracy.

A qualitative request such as finer clustering has no invented numeric value.
The Interpreter preserves the execution objective and requests only the relevant
Registry argument or native kwarg member. The input control shows available native
default information and uniquely relevant recorded prior settings. Defaults and
prior settings are descriptive; they do not preauthorize a new value. A genuinely
omitted optional parameter follows the existing scientific owner default without
a question. Eligible omitted clustering values use the bounded ASW policy described
in the [native analysis guide](native-scatac-analysis.md).

Function, dataset port/source and captured plan step identify consumers. The same
argument name does not authorize transfer across datasets or native functions.
Accepted parameter reuse carries the selected result's recorded function identity.
A parameter with several matching operations produces a step-scoped requirement.
Selecting a step reanalyzes the same semantic candidate and original objective.

FASTQ, BAM and fragment objectives can include explicit downstream scientific
values, such as MACS3 effective genome size or native clustering kwargs. Raw
intake retains them through the same Registry parameter and exact-text binding
owners. It does not restrict them to the import tool. Source composition still
protects dataset paths and output locations; a parameter alone selects no tool,
supplies no derived dataset and grants no execution authority. The compiled plan
must consume each accepted declaration at its actual registered operation.

## Local continuation

Canonical Interaction preparation contains the original task, immutable candidate
reference, predecessor and exact scoped answers. Requirements identify the selected
step, Registry port, argument and optional native member. The older prerequisite
record remains live only for actual native-failure parameter continuation.
Good declarations, including sibling kwargs, stay admitted. The source metadata,
accepted result references, requested outputs and original utterance remain owned
by the existing continuation chain. Partial answers update only pending fields.

Parameter entries and file/step choices use the existing typed submissions.
They may have an empty utterance; no synthesized sentence or extra Interpreter
call represents the click. Ordinary planning happens once when still needed.
Selection of an operation in the captured candidate requires no second Planner call.
Clarifications reserve no scientific SessionTurn or Run. Preparation failures
remain distinct from failed native execution.

Captured annotation species and UMAP choices retain their annotation meaning
when the original objective starts from FASTQ, BAM or fragments. The enclosing
raw prerequisite does not turn an annotation choice into a reference-resource
selection. Exact offered membership and the pending question identity still bind
the click; the ordinary continuation preserves the original raw sources.

Native reference choices accumulate by their registered component ports in the
same pending task. Selecting a genome retains an earlier independent gene
annotation choice; selecting a different provider for the same port replaces
that component. The canonical answers pin consumer-scoped selections separately from the
source declaration receipt. A reference choice does not declare the source assembly. Conflicting
components and unassociated FASTA/FAI inputs still require correction.

When annotation or reference preparation asks a question after a wire-v4 candidate
is parsed, the canonical preparation record retains that candidate once. Exact
UI answers append typed deltas and reanalyze it through the shared compiler and
scientific owners without another model planning call. An unrelated addition to
the offered resource catalog does not itself require semantic regeneration. Final
selected resource identity and input-integrity checks remain authoritative.
Historical `native_semantic_candidate`, `native_resource_plan` and accepted plan
records remain readable; those fields are not written for new pending candidates.

An empty-body exact button answer carries its identity in the structured choice.
A later textual answer captures its own real utterance while retaining the same
pending objective and files. New captures record this boundary's version so old
questions and historical failures keep their original captured meaning. Capturing
a prerequisite offers context to interpretation; it does not turn an unrelated
new request into an answer or relax ordinary nonempty request validation.

The wire-v4 response schema projects the compiler's registered source channels
within the visible planning scope. It retains portless upstream references when
each compatible producer has one valid port. If any compatible producer has
multiple ports, that consumer requires an explicit port, including mixed scopes.
No compatible producer means no upstream source variant. The compiler still
validates every selected producer, port and scientific dependency.

Files retain captured resource IDs, hashes and source order. Role selection binds
actual offered files to Registry ports. Resource component selection and accepted
Revision/prior-output validation retain their existing owners. Names, extensions,
dimensions and model guesses establish neither biological metadata nor scientific
correspondence. Missing identities fail without silent source substitution.

## History and Native Functions

Saved pre-consolidation rejection/parameter/species records have isolated readers;
new questions use scoped parameter slots. Selected step declarations preserve their
original text spans and gain a step identity only through the captured plan choice.
Historical displayed prose and accepted scientific outputs are not rewritten.

Native Functions remains a fully structured zero-provider interface. It does not
enter this conversational binding flow. Executor, native process ownership,
RunStore, NativePublication, SessionTurn, Revision and downloads remain shared.
Stage 2 result editing continues from the exact selected Revision and accepted DAG.

for representative tests, real Firefox/official-provider execution, startup failures,

changes the submitted value or selects an execution step.

## Bounded clustering selection

Scientific Clustering Parameter Selection now uses one bounded ASW scan for the
six eligible native clustering functions. Explicit researcher values, structured
UI overrides and result edits take precedence. `parameter_selection=native_defaults`
respects a researcher request for installed defaults. The compiler applies the
ASW policy only after method selection and deterministic value binding; the LLM
neither invents candidate values nor plans individual candidate executions.

If ASW cannot recommend a required epiScanpy kmeans/hc count, its scientific Run
remains failed with retained diagnostics. The Interaction captures the same scoped
`kwargs.num_clusters` question used for missing native defaults. Admitted intent
and failed Run/SessionTurn identities remain immutable. A structured numeric answer
uses the exact prepared task and accepted input references, with a new Run and
direct native count binding; no provider chooses the value or repeats planning.

Selected effective parameters are ordinary accepted result values. Result edits
pin these before applying changes, preserving exact step/source scope, Revision
continuation and unaffected upstream reuse. An internal clustering metric alone
cannot establish a universal biological optimum. Native Functions remains
unoptimized. The [acceptance report](../../../agent-data/acceptance/scientific-clustering-parameter-selection-2026-11-11/REPORT.md)
separates real native science, scripted planning, focused tests and limitations.

## Interpreter context and ordinary clarification

The Interpreter receives a Registry-derived intent inventory: every capability,
its purpose/input roles and every native function name. Full kwarg metadata expands
for explicit tool, package, function or parameter references and captured pending
questions. This projection does not route execution or change the Planner's full
Registry contracts, native defaults, compiler checks or package neutrality.

The current response schema specializes the existing proposal grammar to captured
source, result, candidate, resource and question offers. Parameter clarification
choices come only from a current parameter question, not the entire Registry.
Large exact offer sets use lossless finite membership patterns to stay within the
provider's global enum budget. Independent admission still checks associations,
source bytes, question scope/version, grounding and accepted authority.

An unspecified operation can remain `clarify/ambiguous_subject` without creating a
Task. Recent ordinary clarification utterances and actual saved questions are read
through the existing immutable previous-turn link; they are conversation context,
not scientific evidence, source selection or an accepted-result predecessor.
Failed interpretation retains the user's utterance without granting accepted
intent. A precise follow-up enters the existing canonical preparation lifecycle;
an unrelated objective receives its own task and explicit source bindings.
Terminal invalid interpretation is saved truthfully without a model retry. Its
structured error remains visible without a language-specific fallback. Saved
historical displays stay exact.
Native Functions and result-scoped structured edits retain their direct paths.


## SPP-1F source, options and conversational delivery

Canonical declaration continuation resolves an omitted source through the actual
Registry consumer's existing role/member binding. Explicit sources, source bytes,
accepted outputs, consumer ports and question versions remain exact. An attachment
catalog alone grants no source selection, and multiple eligible sources remain
ambiguous. A later explicit first selection may use a newly supplied source through
the existing immutable-prefix and authorized-append source owner; the initial
unselected offers do not exclude it. Textual offered-field answers and exact UI selections append the same
captured requirement identity; neither reacquires the semantic candidate.

The common question contract offers shallow, private-name-filtered source fields
from the selected consumer's source and registered axis. Existing production
observation parameters use `obs`. The contract also represents `var` fields and
scalar `uns` keys when a consumer explicitly registers that applicability;
nested metadata is not an arbitrary scientific option. Current parameters without
that Registry metadata retain their existing declaration/clarification behavior.
Field names confer no biological identity or preference, even when only one field
is offered. Counts are never loaded to populate field options. Bounded field
lists disclose incompleteness and continue to accept explicitly named fields
through the existing source and scientific checks.

Reference-dependent Gene Activity preparation observes conventional H5AD assembly
claims (`uns.assembly`, `var.genome`, `uns.source.assembly/reference`) without
reading X. Observations retain their exact source hash, origin and completeness;
they are dataset-supplied claims, not independent certification. A valid researcher
assembly can supply an unknown fact. Conflicting positive claims, including
same-lineage raw declarations, cannot be silently replaced. Unknown assembly does
not match an installed GTF merely because its species is human. Reference label
equivalence still requires the resource owner's exact qualified FASTA, FAI and
ordered-contig identity evidence. Supplied GTF paths/hashes and explicit resource
choices undergo the same applicability and integrity checks. Unrelated operations
and Native Functions retain their own existing prerequisites; mapping a sequence
source can legitimately select its reference without a preexisting coordinate
assembly. When a selected data dependency actually descends from Chromap mapping,
the exact planned FASTA input and its qualified FAI association can establish the
downstream assembly. This is recorded as planned reference provenance, not a
completed mapping or a rewritten FASTQ declaration. Saved binding replay reads
recorded identities rather than requalifying current source files.

Ordinary conversational scientific completion uses the existing grounded response
and review owners, including when the Interpreter returned an empty delivery list
or the researcher requested a result file. The explicit `files_only` delivery
intention suppresses explanatory prose. Response generation receives the current
utterance, relevant conversation and explicit language instructions, while
scientific identifiers remain exact. There is no language table, classifier or
translation branch. Deterministic actions/resume/status use structured facts and
need no extra prose completion. Clarification and failure explanations use the
same response owner. Previously saved presentations remain immutable.

The [SPP-1F report](../../../agent-data/acceptance/scientific-plan-preparation/spp-1f-2026-11-17/REPORT.md)
records bounded offline checks and independent review. It does not establish
final SPP-1 live acceptance or authorize Git publication.

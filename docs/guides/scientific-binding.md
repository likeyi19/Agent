# Scientific input binding in AI Research

AI Research accepts ordinary scientific language, such as “分辨率设置为0.8” or
“set the clustering resolution to 0.8.” The Interpreter associates the request
with Registry operations, parameters and captured source roles. Agent binds the
actual supplied values and recorded identities. Native scientific tools retain
parameter validity, algorithms and defaults.

## Values and scope

Structured file/result selections and parameter entries are authoritative. A
model duplicate cannot override them or force their values through text grounding.
Explicit text declarations retain exact evidence spans. A unique numeric token,
quoted string, canonical choice or supported JSON value inside a unique verbatim
association quote can correct a mismatching model candidate. Multiple numeric
values in that quote require clarification; narrowing the association quote is
part of interpretation. Values are never clipped or replaced by defaults.

Boolean declarations support explicit true/false, yes/no, 是/否 and 开启/关闭.
Structured native kwargs keep independent member evidence. Number words and
arbitrary prose descriptions of lists/objects are not a general parsing language;
when exact mechanical recovery is unavailable, a local input question is used.
Semantic synonyms for scientific methods and categorical descriptions still rely
on interpretation. This is bounded value binding, not universal language accuracy.

A qualitative request such as finer clustering has no invented numeric value.
The Interpreter preserves the execution objective and requests only the relevant
Registry argument or native kwarg member. The input control shows available native
default information and uniquely relevant recorded prior settings. Defaults and
prior settings are descriptive; they do not preauthorize a new value. A genuinely
omitted optional parameter follows the existing scientific owner default without
a question. No automatic resolution optimizer is provided.

Function, dataset port/source and captured plan step identify consumers. The same
argument name does not authorize transfer across datasets or native functions.
Accepted parameter reuse carries the selected result's recorded function identity.
A parameter with several matching operations uses the existing prepared-plan step
selection. Selecting a step reuses that plan and the original objective.

## Local continuation

The existing Interaction prerequisite contains the original turn, most recent
binding turn, resource context digest and bounded missing field handles. Its
admitted parameter slots describe exact Registry/function/member/source scopes.
Good declarations, including sibling kwargs, stay admitted. The source metadata,
accepted result references, requested outputs and original utterance remain owned
by the existing continuation chain. Partial answers update only pending fields.

Parameter entries and file/step choices use the existing typed submissions.
They may have an empty utterance; no synthesized sentence or extra Interpreter
call represents the click. Ordinary planning happens once when still needed.
Selection of an already prepared step plan requires no second Planner call.
Clarifications reserve no scientific SessionTurn or Run. Preparation failures
remain distinct from failed native execution.

Files retain captured resource IDs, hashes and source order. Role selection binds
actual offered files to Registry ports. Resource component selection and accepted
Revision/prior-output validation retain their existing owners. Names, extensions,
dimensions and model guesses establish neither biological metadata nor scientific
correspondence. Missing identities fail without silent source substitution.

## History and Native Functions

Saved pre-consolidation rejection/parameter/species records have isolated readers;
new questions use scoped parameter slots. Selected step declarations preserve their
original text spans and gain a step identity only through the captured plan choice.
Historical displayed prose and accepted scientific outputs are not rewritten.

Native Functions remains a fully structured zero-provider interface. It does not
enter this conversational binding flow. Executor, native process ownership,
RunStore, NativePublication, SessionTurn, Revision and downloads remain shared.
Stage 2 result editing continues from the exact selected Revision and accepted DAG.

## Separate next phase

Scientific Clustering Parameter Selection is not implemented by this consolidation.
Any later automatic method must preserve explicit researcher values, structured UI
overrides, result-scoped edits, exact Revision continuation and unaffected upstream
reuse. Selection applies only when a parameter is genuinely unspecified or the
researcher explicitly requests optimization. Its method, selected value, evaluation
criterion and actual native execution must be recorded. An internal clustering
metric alone cannot establish a universal biological optimum.

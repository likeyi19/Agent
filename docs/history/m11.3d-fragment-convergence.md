# M11.3d — Fragment convergence, FASTQ migration and v1 retirement

Fragment-layer convergence: FASTQ, BAM and external fragment inputs now converge
on verified producer-neutral `scatac-fragments.v2`; transitional fragments v1 is
retired from the current runtime. The existing fifteen scientific tools remain.
M11.4 cell selection/QC and M11.5 cell-by-cCRE are not implemented.

## Base and initial blast-radius audit

Implementation began on clean `main` at
`157b67c7e318f891b04eb41d123ec506e22c22d1`
(`Implement Milestone 11.3c BAM fragment preprocessing`), aligned with
`origin/main`. The read-only audit preceded implementation and classified the
fragment v1 references as follows:

| Classification | Occurrences and decision |
| --- | --- |
| Historical documentation | M11.2 and M11.3a–c records in AGENTS and milestone documents retain their original scientific and validation history, with explicit supersession notices. Current README/AGENTS architecture changes to v2 only. |
| Current production dependency | FASTQ artifact assembly, closed manifest validation, independent verifier, public result/recovery, registry semantic port, evidence/report and Application tests migrate together. No old result or receipt is reinterpreted. |
| Compatibility-only dependency | Common reader v1 dispatch/adapter and tests that required legacy acceptance are removed. They are replaced by explicit retirement tests. |
| Removable after migration | `scatac_fragments_manifest.py` and `scatac_fragments_verifier.py` are deleted. Scientific record validation/FASTQ verification move to the current producer modules; the obsolete outer artifact identity/validator do not survive. |
| Shared helper dependency | BAM, external and generic v2 verification used the old verifier's BGZF decoder/tabix query helpers. Those exact source-neutral helpers move to `_fragment_io.py`; consumers import them directly. No fake v1 runtime remains. |

Unrelated version-1 contracts are current dependencies, not fragment v1
compatibility: raw intake, reference/context, index/backend/profile identities,
producer records, receipt envelope schemas, evidence schemas and historical
run-state schema loading. Their version numbers remain unchanged.

## Current FASTQ artifact and result

`prepare_scATAC_fragments` keeps its public arguments and compact result fields.
Successful results now require `artifact_schema_version=2` and
`contract_version="scatac-fragments.v2"`; strict validation rejects old result
values. The ToolSpec producer port uses `scatac_fragments.v2`, matching the BAM
and external ports. No new tool, compiler branch, source inference, routing,
workflow completion, or planner ceiling increase is introduced. V4 stays default.

Each publication contains a v2 `manifest.json`, a fixed `profile.json`, a closed
`production.json`, and per-namespace `libraries/<namespace>/fragments.tsv.gz`
and `.tbi` files. The public tool additionally owns its durable receipt/envelope.
Both private-stage and final-envelope relocation update only owned absolute
profile/record locators and the physical manifest digest. Portable v2 identity
is unchanged by that relocation. Files and directories are fsynced before atomic
publication; private staging paths never remain in published resource locators.

The producer record has artifact type `agent.fastq-fragment-production`, schema
1 and contract `fastq-fragment-production.v1`. This is the first version of a
new producer record, not a retained schema-1 fragment artifact or adapter.
The profile binds the existing qualified `chromap-atac-agent-support-v1` policy.

## Scientific invariance and verification

Chromap remains upstream v0.3.2, commit
`5bd17e1f1c50805e76904efd021603cb6a1b6e23`, with support patch SHA-256
`8d862e77d59213aa19b3fbc5f6014585a4b5f414f3e29143b68513ffd961df33`
and qualified executable SHA-256
`7ba402d0d69d08fedd525a4de83a4dd749670e88d4de507c236b07f03a285649`.
The fixed mapping/index flags, whitelist/correction rules, thread count one,
Chromap-only +4/−5 shift, duplicate-group support, numeric/reference ordering,
bgzip compression level six/thread one and TBI policy are unchanged. FASTQ
continues to serialize five columns with no strand; the v2 manifest explicitly
records strand absence.

FASTQ producer verification checks exact profile/record/resource cross-bindings,
revalidates intake/context/reference/index/whitelist/backend identity, and uses
the independent FASTQ fragment parser for complete BGZF CRC/EOF decoding,
whitelist membership, syntax/order, stream digest, exact summaries, contig
inventory and full-contig/narrow tabix queries. It additionally recomputes
encoded source hashes and the existing complete decoded FASTQ scans, then runs
generic v2 verification and checks resource snapshots. Generic integrity alone
cannot authenticate a forged producer claim: self-consistent v2 forgeries of
scan, whitelist, role or index identities are rejected by the FASTQ verifier.

Verification does not rerun Chromap or independently reconstruct alignment,
barcode correction or upstream biological history. Resume/evidence require the
bound source/reference/context/index resources and packaging tools, but no
Chromap executable discovery or another alignment. Fresh decoded/source scans
add IO cost. Consistency assumes trusted local filesystems; hostile filesystem
race hardening remains deferred.

Current v2 bounds remain 8 MiB per manifest, at most 4096 libraries and 4096
source entries across the whole manifest. FASTQ counts each selected physical
role file plus intake/context entries per library against that existing source
bound; it rejects an excessive source count before alignment. The producer
record has its own 8 MiB read bound. These are current v2 representability limits,
not a promise to preserve every former v1 maximum-size grouping. No limits are
raised, no sources are silently omitted, and no overflow is routed to v1.

## Recovery and intentional retirement

New runs bind `prepare-scatac-fragments-fastq-v2`. Receipt envelope schema remains
1 because its field structure is unchanged; its policy, publication identity and
manifest digest bind current v2 behavior. Exact publication-before-checkpoint
recovery verifies the final v2 artifact without another aligner call.

Current reader, generic validator/verifier and FASTQ verifier reject a recognizable
schema-1 fragment envelope with `FRAGMENTS_CONTRACT_RETIRED`. Non-UTF-8 legacy
encodings fail the current strict v2 parser; no legacy decoder is retained.
Old FASTQ result values fail
strict result validation. An old-policy receipt presented at a current lookup
fails `FRAGMENTS_RECOVERY_MISMATCH`; an old publication at a different policy's
identity is unavailable to current recovery. Persisted old runs have incompatible
recovery provenance and are unsupported. There is no automatic schema detection
that upgrades artifacts, no rewrite, no migration command and no dual recovery.

Historical M11.2/M11.3a–c documents remain factual about their checkpoints. Their
old compatibility promises are intentionally superseded. Git history preserves
historical runtime behavior; post-M11.3d code does not support old fragment v1
artifacts or guarantee their persisted runs can resume.

## Shared semantics and the M11.4 input boundary

| Property | FASTQ | BAM | External adoption |
| --- | --- | --- | --- |
| Current artifact | v2 | v2 | v2 |
| Reference and identity | Exact bundle, species/assembly, ordered contigs; namespace + barcode across all routes | Same | Same |
| Coordinates | Zero-based half-open, shifted once by Chromap | Zero-based half-open, Agent +4/−5 under declared unshifted source | Source intervals preserved; history declared |
| Support | Chromap-generated paired mappings in accepted cell-level duplicate group, including representative | Individually eligible primary pairs at the exact shifted key | Admitted source read-pair support, preserved by conservation verification |
| Strand | Absent | Absent | Absent or preserved `+`, `-`, `.` under explicit profile |
| Scientific qualification | Pinned alignment/correction/index policy and FASTQ verifier | Corrected-CB pairing/MAPQ/Tn5/exact-key policy and independent transformation verifier | Explicit 10x profile and independent complete source/conservation verifier |
| Common guarantees | Exact positive integers, deterministic canonical order, BGZF/TBI, stream/physical identities and producer provenance across all routes | Same | Same |

Equal integer support is not a claim of equal physical interpretation. No route
claims called/QC-passed cells, TSS, FRiP, cCRE matrices or EpiZoo results.

M11.4 may consume only:

```python
from agent.tools.data.scatac_fragment_reader import open_verified_fragments
from agent.tools.data.scatac_fragments_v2_verifier import FragmentVerificationRuntime

view = open_verified_fragments(
    manifest_path, expected_sha256=manifest_sha256,
    runtime=FragmentVerificationRuntime(),
)
reference = view.manifest['reference']
contigs = view.contigs
for library in view.libraries:
    provenance = library.provenance
    support_meaning = library.support_meaning
    for record in view.iter_fragments(library.namespace):
        # namespace, contig, start, end, barcode_identifier, support, strand
        pass
```

`reference` exposes manifest path/SHA-256, portable reference identity,
species/assembly and ordered-contig SHA-256. `contigs` is an ordered tuple of
`(name, length)`. Each immutable library has namespace, record/support/barcode
summaries, strand mode, copied provenance and support meaning. Records are frozen
`FragmentRecord` values; `cell_identity` is the namespace/barcode tuple, not a
cell-calling result. Iteration is deterministic within an explicitly selected
namespace, bounded by BGZF buffers/one record; consume to exhaustion for the
complete stream digest check or close for the final mutation check.

`view.verification` exposes manifest identity, resource snapshots,
`artifact_content="verified"`, `bound_resource_identities="verified"`,
`producer_profile_qualification="not_established"` and
`producer_history="not_verified"`, plus `check_unchanged()`.
Generic reader verification does not execute or dispatch to a scientific
producer. Producer-specific verification is the upstream authority established
by the registered producer and its orchestration/evidence verification. M11.4
must not treat a generic view of arbitrary files as proof of producer science.
It needs no FASTQ roles, Chromap, BAM pairing/CB/CR or external encoding parser;
scientifically relevant support provenance remains available as metadata.
No M11.4 consumer or origin-based downstream algorithm is added here.

## Validation record

The qualified synthetic checks use the existing pinned local patched Chromap
and real bgzip/tabix; no biological dataset or checkpoint enters Git.
A separate base-code comparison on identical FASTQ inputs yielded identical
BGZF and TBI bytes, six canonical records and exact total support 815 (including
weights 255, 256 and 300 plus correction). All prior scientific manifest fields
matched the new producer record exactly, excluding only the added encoded-source
field and the replaced outer artifact contract/identity.

The joint real synthetic test produces the same common
`(library_0, chrTiny, 104, 195, ACGTACGTACGTACGT, 1, None)` record through FASTQ,
BAM and external routes using the same reference. Each route retains its own
producer verification, provenance kind and support definition. The common reader
uses no producer-format branch.

Focused retirement tests prove clear rejection without execution or rewriting;
self-consistent provenance forgeries prove generic integrity is insufficient.
Validation completed before the broad/full regression closeout:

- Initial migrated contract/reader/planning checks: 116 passed.
- FASTQ/v2/external regression: 460 passed, 26 gated skips.
- Final qualified migration, joint convergence, integration, runtime and
  Application checks: 32 passed. This includes both layouts, real compressed
  input, support above 255, direct/inspect execution, resume and exact recovery.
- Base comparison: byte-identical BGZF/TBI and preserved scientific fields.
- Shared BGZF/tabix helpers and independent FASTQ stream parser: unchanged AST;
  pinned science modules and BAM/external producers: unchanged bytes.

Affected regression passed **2789 tests**, with 27 gated skips and three existing
louvain/Scanpy/Numba dependency warnings (407.58 seconds). Final full lightweight
regression passed **3084 tests, 81 skipped, 7 warnings** (447.56 seconds).
The full-suite warnings are existing louvain/Scanpy deprecations, the disabled
Numba TBB layer and deliberate duplicate-observation fixtures. Gated biological,
model, provider and optional integration checks remain skipped unless separately
enabled; the qualified FASTQ migration/joint checks above were explicitly run.

Validation commands used `PYTHONDONTWRITEBYTECODE=1`, `PYTHONPATH=src`, the
`agent` Conda environment, and `/tmp` Numba/Matplotlib caches. The qualified run
additionally enabled `RUN_CHROMAP_QUALIFICATION=1` with the existing explicit
`AGENT_CHROMAP_QUALIFICATION_RECORD`. The final full command was
`conda run --no-capture-output -n agent python -m pytest -q`.

`git diff --check` and whitespace checks for all newly added files passed.
Initial test failures exposed stale corruption fixtures that updated only the
outer manifest; updating both v2 and producer-record bindings preserved their
intended independent stream/tabix verification checks. No scientific mismatch
or unresolved correctness defect was found. No commit or push was performed;
implementation remains an unstaged diff on the expected base.

Biological acceptance, production full-genome Chromap index provisioning and
M11.4/M11.5 remain deferred. No broader BAM/external profile, CRAM/SAM, checksum UX,
cell calling, QC or downstream matrix/model capability is included.

## Scientific decision and intentional supersession

M11.5a explicitly supersedes the old M11.1/README proposal that each overlap should
use fragment support/count when present. The replacement is
`canonical-fragment-record-overlap-counts.v1`, defined by immutable
`MatrixScienceProfile` in `scatac_matrix_contract.py`; its SHA-256 covers the
complete canonical profile dictionary. The compatibility label remains
`matrix_semantics="fragment_counts"`, but the full profile is mandatory.
The frozen profile SHA-256 is
`fb7d8f48728e6b71a833fd7024de9d05e0782ea4096d3b31f1aa861245b76394`.

For selected cell c and full-reference cCRE j:

```text
X[c,j] = sum over canonical v2 records r belonging to c of
         1[ r.chrom == j.chrom and max(r.start,j.start) < min(r.end,j.end) ]
```

Use the term **canonical fragment-record count**. Support is ignored; no support
expansion, new deduplication, Tn5 shift, endpoint/center projection, fractional
weighting or binarization occurs. Records independently contribute to every
distinct overlapping cCRE. Repeated cell/cCRE contributions sum as exact integers.
Overlapping/nested cCREs are separate columns. Row sums may exceed record depth.

Coordinates are zero-based half-open and overlap is strand-independent. For
cCRE `[10,20)`, `[0,10)` and `[20,25)` do not overlap; `[9,11)`, `[12,15)`,
`[5,25)`, `[10,20)` and `[19,21)` do. No chromosome aliases or clipping.

Canonical record identity for incidence checks is `(namespace, ordinal)`, where
ordinal is the zero-based position in that library's **complete** canonical v2
stream, before selecting cells or sorting a projection. A backend integer label
may reversibly map to that identity. A repeated `(record identity, column index)`
incidence is an error, not another contribution or a silently coalesced duplicate.
Different canonical records can share coordinates, particularly strand-distinct
external records. Their multiplicity is preserved. Changing only strand labels
without changing multiplicity must not change counts; collapsing two records
into one is not an equivalent input.

FASTQ support counts qualified Chromap duplicate-group mappings, BAM support
counts individually eligible exact-key pairs, and external support preserves
source-producer read-pair support. These are not a universal biological weight.
Equal admitted geometry and multiplicity, selection and reference must produce
equal logical matrices despite producer/support/provenance differences. This
does not equate upstream alignment/filtering/deduplication policies. Unique
molecules, original sequencing depth, PCR-expanded counts and universal historical
EpiZoo/EpiAgent training-matrix equivalence are not claimed. Historical EpiAgent
code sums support when supplied; a local EpiZoo cancer script counts overlap rows.

## Upstream and axis authority

Only freshly verified `scatac-fragments.v2`, `scatac-cell-selection.v1` and the
exact `scatac-reference-bundle.v1` may authorize a future matrix. Generic v2
verification alone does not qualify producer science. Selection verification
includes existing QC/source/producer/resource qualification. No new selection,
threshold evaluation policy, cell calling or barcode discovery defines rows.

The supplied fragments manifest path/SHA must equal selection's
`qc_lineage.arguments.fragments_manifest_path/sha256`. Verify QC/selection
scientific identities and the exact bound parent reference manifest/hash and
portable reference identity. Compare source snapshots across each operation.
An absent selected tuple is an error. A present selected tuple with no overlap
is a valid zero row. Namespace is not biological replicate, sample or condition.

Read `selected.tsv.gz` in its authoritative sequence and require contiguous
`matrix_row_index` from zero. Preserve its canonical reversible `scatac-cell.v1`
rendering and original namespace/barcode. Never regenerate order with sorting,
`np.unique`, fragment encounter order or backend output. The selected digest is
SHA-256 of `agent.ordered-selected-cells.v1\0` followed by each exact
`namespace<TAB>barcode<LF>`; the domain alone defines the empty selection.
`selected_axis_identity` validates provided indices/IDs and computes this digest;
it does not replace fresh selection verification or establish fragment presence.

The reference BED defines exact full feature membership, names, coordinates and
column order. Preserve all zero columns. Do not merge cCREs or apply retained
EpiZoo indices. Each canonical name is `chrom:start-end`; duplicate names fail;
exact FAI contig membership and bounds are mandatory. The ordered-feature digest
is the existing SHA-256 UTF-8/LF encoding. Tiny explicit bundles remain legal
fixtures, not certified full model vocabularies.

## Numeric, sparse and H5AD contract

Values are nonnegative signed int64. Check every accumulation and entry/row/total
sum before narrowing; fail on overflow, never wrap, saturate or change dtype.
CSR indices/indptr may use any exactly representable integer width. Require valid
offsets/bounds, sorted unique column indices and strictly positive stored values.
No silent duplicate summation or explicit zeros. Empty rows retain equal adjacent
offsets. Empty selection is `(0,n_full_ccre)` with offsets `[0]`.

Future `matrix.h5ad` is the only persistent matrix payload:

| Element | Required content |
| --- | --- |
| X | Canonical int64 CSR; full authoritative shape |
| obs_names | Exact selected canonical rendered IDs |
| obs | namespace, barcode_identifier, matrix_row_index |
| var_names | Exact full canonical reference names |
| var | chrom, start, end, matrix_column_index |
| uns | matrix_semantics, matrix_profile_id, matrix_profile_sha256, species, assembly, coordinate_system, ordered_selected_sha256, ordered_feature_sha256, logical_matrix_sha256 |

Axis index/coordinate columns are exact integers; biological metadata is not
inferred. `.uns` uses the reference's `zero-based-half-open` coordinate label.
No `.raw`, duplicate counts layer, complete upstream manifests or full QC tables.
The H5AD cannot contain its own final byte hash. Full provenance lives outside it.

Outer `agent.scatac-cell-by-ccre`, schema 1 / `scatac-cell-by-ccre.v1` is an
IO-free closed validation contract in `scatac_matrix_contract.py`. It binds the
full profile/hash, species/assembly, three exact upstream manifest paths/hashes/
scientific identities/contracts, row/column digests, logical matrix digest, shape,
nnz, total count, zero-row count, matrix path/size/SHA/CSR/int64, backend profile/
runtime identity, diagnostics, readiness and its own domain-separated identity.
The full upstream manifests are transitively bound, not copied. Structural
validation must never be reported as scientific verification.
The pointer field `identity_sha256` maps exactly to upstream
`fragments_identity_sha256` for fragments, `identity_sha256` for selection, and
`reference_identity_sha256` for reference. It is never substituted with a byte
hash. All three pointer `manifest_sha256` fields separately bind physical bytes.

The layout is `manifest.json` + `matrix.h5ad`, with the existing lifecycle envelope
when integrated later. No MTX, NPZ or second persistent sparse matrix. Runtime
scratch is private, bounded and cleaned. Full construction must be CPU/disk based,
without whole-intersection DataFrames, full COO allocation or densification.

## Logical matrix identity and diagnostics

Reuse the exact M8 `agent.regulatory-sparse-matrix.v1` encoding locally without
refactoring M8: domain + canonical JSON header containing shape, `dtype="int64"`,
`semantics="fragment_counts"` + LF; for each row, uint64 big-endian nnz, all uint64
big-endian column indices, then all int64 big-endian values. Explicit cross-checks
compare M8 and M11.5a. Physical index width, compression and chunking are excluded.
Profile/axis/upstream identities bind separately. A count redistribution can
preserve both marginal sums while changing this digest.

Artifact-level diagnostics are exact:

* `n_selected_fragment_records_total`: all records belonging to selected cells,
  on every admitted contig, not just QC contigs.
* `n_selected_fragment_records_overlapping_any_ccre`: each such record counted
  once if it overlaps one or more full-reference cCREs.
* `fraction_selected_fragment_records_overlapping_any_ccre`: reduced exact
  numerator/denominator, or null with `NO_SELECTED_FRAGMENT_RECORDS` at zero
  denominator. No binary floating authoritative ratio.

These are diagnostic only: not FRiP, cell calling or QC selection. They do not
change rows. No new per-cell QC/report expansion is required.

## BEDTools qualification boundary

`bedtools-ccre-record-incidence.v1` uses a separate pinned runtime record, with
the installed BEDTools v2.30.0 binary SHA:
`770cdb969bd7dea9ceb34925753601f9871514247cf436ee101c513e4611f77c`.
Binary and linked-library identity/version checks precede scientific execution.
The pinned runtime identity is
`d0ad0ca6374dc2d7c209344be8bde8805ba64742974307c1abe653dbe9619dde`.
The command is:

```text
<explicit-qualified-executable> intersect -sorted -g genome.tsv
    -a selected-fragments.bed -b ccres.bed -wa -wb -f 1e-12 -F 1e-12
```

The exact verified FAI dictionary becomes two-column `name<TAB>length<LF>` in
FAI order, not an unchanged five-column FAI. BED4 labels reversibly map to
authoritative fragment/column identities. Only private projections sort by FAI
rank/start/end/ID. No strand or support enters either projection. Repeated
backend incidences and malformed returned coordinates/IDs fail.

This runtime profile admits positive contig lengths at most 1,000,000,000 bases.
The explicit tiny fractional thresholds are below one base throughout that
range; one-base overlap therefore qualifies even for admitted long intervals.
This is a **backend qualification bound**, not a change to the broader signed-
int64 reference coordinate contract. Larger references fail this profile and
need new qualification, not clipping or a hidden backend fallback.

M11.5a's internal harness admits at most 10,000 records per projection and 10,000
contigs, bounds each encoded input to 4 MiB and each line to 64 KiB, polls stdout
at 16 MiB and stderr at 64 KiB, limits an intersection probe to 30 seconds, and
cleans a private temporary directory on failure/cancellation/timeout.
Polling bounds can overshoot between checks; they are not OS disk quotas.
The harness deliberately uses bounded in-memory projections/incidence identities;
it is not production-scale matrix construction or a throughput/RSS qualification.
Future production must stream/external-sort with explicit resource checks.

Tests cover all seven boundaries, distinct/nested/overlapping features, repeated
records, multiple hits, unusual FAI order, empty streams, one-base overlap at the
admitted billion-base range, duplicate incidence rejection, deterministic sorting,
bad runtime/input, output limits, subprocess failure and active cancellation cleanup.

## Independent verification, lifecycle and future acceptance

M11.5b's verified claim requires complete independent reconstruction from exact
freshly verified selection/QC/fragments and reference sources. Independently
enumerate all overlaps without production BEDTools output/helper, independently
aggregate in bounded disk-backed storage, and compare every canonical sparse row
and logical identity. A per-contig augmented interval index is a candidate.
Do not trust production summaries, sampled entries, or row/column sums alone.
No second H5AD need be published. The contract/digest checks added here do not
implement or claim that future verification.

Durability receipt recovery is conceptually separate. M11.5c must follow the
existing accepted lifecycle's fresh-verification requirements where applicable;
this freeze does not impose full scientific reconstruction on every routine
resume path. No lifecycle, recovery identity or executor is changed in M11.5a.
Future PLAN_ONLY must perform zero fragment/selection/reference/runtime IO and
no interval subprocess or H5AD creation. Full verified publication must be atomic,
with exact input/profile/runtime bindings and cancellation-safe private scratch.

Freeze M11.5b acceptance fixtures for independently qualified FASTQ, BAM and
external producers with identical selected geometry/multiplicity, selected order
and reference, but deliberately different support/provenance. Require identical
row/column order, values, logical digest, zero rows and diagnostic numerator/
denominator. H5AD bytes and provenance may differ. Include support-only changes,
strand-label changes without multiplicity changes, nested/touching cCREs, repeated
cell/cCRE contributions, multiple hits, namespace collisions, zero rows and empty
selection. Rehashed duplicate-incidence and equal-marginal count-redistribution
forgeries must fail **independent** source reconstruction. M11.5a only qualifies
the mechanics/identity needed for these future complete tests.

Generic matrix validity is separate from downstream readiness. Zero rows persist;
empty selection publishes a valid empty matrix with `no_selected_cells`. The
existing feature-space validator rejects empty inputs; EpiZoo rejects empty/zero
rows and cells with no retained cCREs. Neither permits mutating raw rows to make
them ready. Nonempty output can enter `validate_scATAC_feature_space` using X,
`fragment_counts`, explicit species/assembly and var coordinates (its API uses
`zero_based_half_open`). No bypass is needed. Pseudobulk requires separate explicit
biological metadata. EpiZoo filtering, frequencies, TF-IDF, ranking, tokenization,
embedding and inference remain downstream, including model/runtime/memory checks.
No training-distribution equivalence or biological preprocessing acceptance.

## APIs and authority

`agent.tools.data.scatac_cell_by_ccre.build_cell_by_ccre` accepts keyword-only
`fragments_manifest_path/sha256`, `selection_manifest_path/sha256`,
`reference_manifest_path/sha256`, `output_dir`, `bedtools_path`, and optional
`MatrixLimits`. `output_dir` is the final artifact directory, not an automatic
run directory. Existing destinations fail; no overwrite or implicit resume.

`agent.tools.data.cell_by_ccre_verifier.verify_cell_by_ccre` accepts the matrix
manifest path, mandatory `expected_sha256` and `bedtools_path`, optional limits
and scratch parent. It returns bounded verification evidence and resource timing;
it does not return or publish another matrix.

Selection verification freshly verifies its QC, upstream fragments, producer
profile and reference qualification through the existing verifier chain. Exact
caller fragment path/hash must match that lineage; reference path/hash/logical
identity must match the fragments and selection. Common v2 verification and
reference source reinspection also run. Existing QC runtime/catalog or explicit
synthetic opt-in requirements apply. No matrix execution silently qualifies QC.
The existing producer authority distinctions and history limits remain intact.

Only verified selected sidecar row indices define rows. Although M11.4c currently
fixes those tuples in ASCII order, their rendered IDs can have a different lexical
order; a test proves the constructor preserves sidecar order. It never invents an
alternative selection ordering. Only the full reference BED row indices define
columns. Species changes metadata/reference instance, not either counting engine.
No Fang2021 H5AD reader enters matrix construction.

## Production and resource bounds

1. Copy selected identities into SQLite with unique `(namespace,barcode)` lookup,
   explicit authoritative row indices and a presence bit. Copy full reference
   columns with their original index and FAI contig rank. These are scratch tables.
2. Stream every canonical library record, assigning its ordinal before selection.
   A disk table binds a unique surrogate BED ID to `(namespace,full-stream ordinal)`
   and row/coordinates. Track selected identity presence; absent identities fail.
3. SQLite B-tree indexes, maintained during insertion, provide coordinate-order
   scans for temporary BED4 projections. No Python population sort or custom
   external sorter is used. Output columns keep original reference indices.
4. Use the unchanged qualified `bedtools-ccre-record-incidence.v1` invocation:
   `intersect -sorted -g genome.tsv -a a.bed -b b.bed -wa -wb -f 1e-12 -F 1e-12`.
   The genome file follows verified FAI order. Binary/libraries/profile are pinned
   by M11.5a qualification. Both pipes are drained with polling and cancellation;
   stdout has backpressure, a bounded pending line and no full intersection file.
   Stderr is counted, capped at 64 KiB and discarded.
5. Validate both returned coordinates/IDs and positive-base overlap. SQLite's
   primary key `(fragment_id,column_index)` rejects repeated incidences. A separate
   `(row,column)` table accumulates checked Python integer increments, preserving
   distinct canonical records irrespective of support or strand. Final row and
   total sums are also checked against signed int64.
6. Scan counts in authoritative row/column order into one standard H5AD CSR.
   At most one sparse row is held, bounded by full feature width; no complete COO,
   dense matrix, population incidence list or cell-by-cCRE dictionary is created.

Default operational ceilings are 2,000,000 features, 10,000,000 selected cells,
100 GiB private matrix scratch, and 24 hours. Feature/selected ceilings can be
lowered; increasing these two compiled memory ceilings is rejected. Failure never
truncates data or changes science. SQLite uses an 8 MiB page cache, no mmap,
disposable journal-free scratch, and a hard page-count ceiling at half its scratch
allowance. Indexed scans avoid large temporary SQL sorts. Reference duplicate
validation retains the existing M11.1 feature-name set; its memory is proportional
to the bounded full reference, not selected cells or incidences.

Scratch/time accounting runs at bounded checkpoints (4,096 records/contributions
or HDF5 chunks, plus pipe polls). File buffers/metadata can cause bounded overshoot
between checks; this is not an OS filesystem quota or hard RSS limiter. The
verifier receives only the remaining matrix scratch allowance. Existing upstream
verifiers retain their own resource policies and private temporary directories;
reported matrix scratch excludes those upstream allocations. Process RSS includes
them and the Python/scientific runtime. No GPU or new dependency is used.

The private stage and exclusive sibling publication lock are cleaned on success,
error and cooperative cancellation. BEDTools is terminated/reaped on cancellation
or parser/resource failure. This is the repository's trusted local filesystem
model, not protection against malicious concurrent filesystem replacement.

## H5AD, identity and publication

The final directory contains exactly `manifest.json` and `matrix.h5ad`.
H5AD uses normal AnnData encodings: CSR `X` with int64 data; `obs` has exact
rendered index, namespace, barcode_identifier and matrix_row_index; `var` has full
canonical coordinate names, chrom, start, end and matrix_column_index. Bounded
`uns` contains only the nine frozen semantics/profile/species/assembly/coordinate
and logical axis/matrix identity fields. Empty ancillary mappings contain no
payload. There is no `.raw`, counts layer, second matrix, inferred replicate or
sample metadata, or embedded upstream manifest. Tests read it with AnnData.

The frozen closed manifest binds each upstream physical manifest hash and logical
identity, exact row/feature identities, profile and runtime identities, physical
H5AD bytes, shape, nnz, total, zero rows and diagnostics. The existing canonical
serialization and manifest identity functions are unchanged. The matrix digest
uses the exact M8 `agent.regulatory-sparse-matrix.v1` encoding, cross-checked against
`replicate_pseudobulk._matrix_digest_and_nnz`. Compression/chunking and physical
CSR index width do not change it. Physical H5AD and manifest hashes remain separate
from scientific matrix identity.

Independent verification must pass on the complete staged artifact before fsync
and atomic rename. No receipt, durable recovery policy, Planner or Application
integration is added. As with existing local publication, hard process death can
leave private staging/lock files; M11.5c owns durable recovery, not this milestone.

Empty selection still receives required upstream and runtime verification, full
`var`, shape `(0,n_features)`, offsets `[0]` and empty data/indices. No matrix
intersection or interval reconstruction runs; executable qualification may invoke
`--version` and upstream QC retains its own verification. Selected identities that
are present but have no overlap remain zero rows; all zero columns remain.

Diagnostics count all selected canonical records and those overlapping at least
one cCRE, once each regardless of overlap multiplicity. The ratio is exact/reduced,
or null with `NO_SELECTED_FRAGMENT_RECORDS`. It is not FRiP, filtering or cell calling.

## Independent verifier

The verifier imports no production counting module. It reloads verified upstream
sources and mechanical axes in a new SQLite database. It independently spools
selected source records by contig and constructs a balanced implicit interval tree
for one contig at a time. Sorted start/end/column plus subtree maximum end require
32 bytes per feature. The maximum-end augmentation is essential: nested and long
intervals are not lost by a simplistic start-coordinate search. Each query visits
all eligible subtrees and independently accumulates unit counts in a separate
canonical disk table. It consumes neither BEDTools incidences nor production counts.

Every H5AD row, column identity and sparse entry is compared to reconstructed
content. It rejects duplicate/unsorted columns, zeros, negatives, invalid offsets,
shapes and dtypes, external/soft HDF5 links and extra payload mappings. Complete
canonical counts are also hashed and all manifest summaries/diagnostics compared.
No sampling or row/column-sum-only check confers verification.

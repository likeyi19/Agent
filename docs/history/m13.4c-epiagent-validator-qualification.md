## Authoritative direct-annotation interface

The local README and `demo/Zero-shot annotation using EpiAgent-NT.ipynb` explicitly
identify EpiAgent-B for brain and EpiAgent-NT for other tissues. NT is the explicit
non-brain choice for this PBMC qualification, not an inferred runtime decision.
The published input resources are human/hg38; mouse compatibility is not established.

The direct path is:

1. `epiagent.preprocessing.global_TFIDF(adata, cCRE_document_frequency)`.
2. `epiagent.tokenization.tokenization(adata)`.
3. `epiagent.dataset.CellDataset` and `collate_fn`.
4. `epiagent.model.EpiAgent_supervised`.
5. `epiagent.inference.infer_cell_types`.

The demo builds a vocabulary of 1,355,449 tokens (1,355,445 cCREs plus four reserved
IDs), 18 layers, embedding dimension 512, eight heads, 8,192 rank embeddings and
28 output classes, with FlashAttention enabled. The classifier is a 512→256→128→28
MLP with GELU, layer normalization and dropout; inference calls `eval()`. Native
inference uses CUDA autocast, and returns softmax `predicted_probabilities` and
class indices under `predicted_labels` (the docstring's key descriptions differ
from actual code), plus optional embeddings. It does not return raw logits.

The demo checkpoint is `model/EpiAgent-NT/EpiAgent-NT.pth`. It is absent locally;
only B/NT label JSON files exist in those model directories. The project checkpoint
directory contains the EpiZoo checkpoint, not the NT checkpoint. No matching named
NT checkpoint was found in the bounded project-file search. Unrelated research
checkpoints were not substituted. Thus no NT checkpoint SHA-256, strict load or
GPU runtime qualification can be claimed. The README's official Google Drive
folder was identified; no download was pursued after the input smoke failure.

The label JSON order is **not** classifier index order. The demo fits sklearn
`LabelEncoder`, giving sorted unique classes. The complete 28-index mapping is
retained in `class-index-to-label.json`. Relevant entries are B cell=1, Myeloid
cell=13, T cell=26; Few-cells type=7. There is no explicit NK class, nor separate
CD4/CD8 T classes. No NK→T or NK→Few-cells remapping is justified merely to obtain
concordance. Broad M13-versus-model mappings and group comparison were not frozen
because prediction qualification stopped earlier.

The demo also applies `filter_rare_cell_types(..., threshold=0.005)` after native
inference. This cohort-dependent reassignment is distinct from native predictions;
it was neither executed nor adopted as a validator policy. A future qualification
must preserve raw native outputs and explicitly scope any optional postprocessing.

Document frequency is finite positive float64 with 1,355,445 entries. EpiAgent
copies AnnData, multiplies counts by reciprocal row totals and reciprocal global
frequency, then applies log1p scaling. Tokenization sorts nonzero TF-IDF entries
in descending order and offsets column indices by four. The authoritative
implementation densifies one cell at a time; the complete matrix is never
densified by the qualification.

`CellDataset` has actual default `is_random=True` despite its docstring saying
False. Above 8,190 feature tokens it samples without replacement and preserves
selected rank order; otherwise an explicit `is_random=False` uses leading ranks.
It adds CLS=1 and SEP=2; the collator pads with 0. The demo uses maximum length
8,192, batch size eight, no shuffle, four workers. Determinism depends on explicit
NumPy/PyTorch/worker seeds and runtime settings; classifier determinism and 24 GB
GPU feasibility were not qualified. Empty token sequences would still produce
special-token-only model input, which is not valid accessibility evidence.

Fragment-record counts are scientifically plausible for investigation: the
upstream constructor sums unit overlap contributions when input has no support
column, while another branch weights by the provided support count. This does
not prove equivalence to all historical training matrices or corpus preparation.
No binarization, peak conversion, feature reordering or imported EpiZoo/MAESTRO
preprocessing is justified by that observation. Semantic usefulness remains
unqualified until valid native preprocessing and inference are demonstrated.

## Four-cell smoke failure and stop decision

The actual upstream functions were imported directly and called on the first four
preserved cells, retaining the canonical int64 values. No EpiAgent-specific
formula was reimplemented. Row sums were 14,920; 6,293; 15,321; 12,846.
`np.reciprocal` on these integer row sums returned `[0, 0, 0, 0]`.
`global_TFIDF` consequently produced zero nonzeros; native tokenization produced
four empty sentences. The functions completed without raising, but the scientific
smoke check correctly failed the nonempty-evidence requirement.

The upstream constructor produces float32, whereas this canonical contract is
int64. This is a concrete dtype-sensitive input incompatibility, not proof that
canonical count semantics are inherently inappropriate. A future explicit,
qualified dtype boundary or upstream reciprocal fix may address it. Neither a
silent cast nor a local TF-IDF replacement was applied in this task. Input
immutability passed, including the full source H5AD hash after execution.

Following the task's stop condition, no classifier smoke, full 1,119-cell inference,
probability artifact, cell-level comparison, group distribution or validator
component was fabricated. In particular, no claims about B/myeloid agreement,
T/NK disagreement, sparse-group heterogeneity or predictions for unresolved cells
can be made. The lack of an explicit NT NK class is an additional comparison
limitation, not evidence against primary NK assignments.

# M15.4 — Typed intent deltas and bounded natural-language navigation

Development baseline: accepted M15.2/M15.3 commit
`82471e8ee8c0b62fba769769af8697721c63e17b`. No reset, staging, commit or push.
This milestone adds application interaction semantics only. Scientific tools,
algorithms, authority schemas, verifier ownership, registry and EpiZoo are unchanged.

## API and architecture

```python
outcome = app.sessions.respond(
    "analysis", "turn-7", "Set the TSS threshold to 7 and rebuild the matrix",
    interpreter=turn_model,
    expected_generation=state.generation,  # optional caller CAS
)
```

`turn_model` implements the existing `complete(prompt=..., response_schema=...)`
model interface. The application's configured scoped-v4 Planner still composes
scientific workflows. The interpretation model is an explicit separate injection;
there are no live-provider correctness dependencies or automatic provider setup.

The result is `TurnOutcome(kind, status, clarification)`, with no artifact paths,
run IDs, or revision hashes. The existing session/debug and scientific provenance
APIs retain exact internal identities. Existing one-shot `run`, `resume`, `cancel`
and explicit session APIs do not pass through this interaction layer.

The flow is:

```text
capture metadata → interpret once → admit exact intent
  ├─ Clarify → durable structured outcome
  ├─ Navigate → existing generation-checked switch
  └─ Execute → M15.3 frozen context → existing scoped Planner
                → admitted-effect check → existing application execution
                → existing authority/evidence/presentation → conditional activation
```

`_AdmittedPlanner` is a delegating admission adapter. It forwards the existing
Planner's normal planning/recovery/diagnostic callbacks, does not create or rewrite
plans, and checks only the permitted effects after the Planner returns. This also
lets the session select the actual Planner-chosen step IDs before execution;
there are no hard-coded step names, first-match routing or inferred DAG edits.
A normal application instance sharing the configured registry/executor and
workspace executes the returned plan. There is no incremental execution engine.

## Typed decision and numerical admission

The closed wire envelope is `turn_schema_version: 1` plus `decision`. Variants:

- `Execute(base, operation, target, delta)`.
- `Navigate(relation)`.
- `Clarify(reason, choices, value_required)` as the structured application result.

An `IntentDelta(parameter, operation, literal, evidence)` selects an offered
parameter and one of `set`, `add`, or `subtract`. The model must quote an exact
complete command clause from the current utterance and its literal verbatim.
Unknown fields, duplicate JSON keys, unknown parameters, unoffered operations,
invented identities and unsupported decision shapes fail closed.

Initial command admission deliberately supports a small English vocabulary:
`set/try <parameter> to/= <number>`, `increase <parameter> by <number>`, and
`decrease <parameter> by <number>`. Natural labels include “TSS threshold”, “TSS”,
“min_tss”, and the other listed selection-parameter aliases. These are interaction
aliases, not new scientific parameter definitions. More general linguistic forms
clarify rather than guessing.

The evidence must be an actual clause in this utterance. The verb, connector,
operator and literal must agree. Negated/conditional commands, unsupported extra
clauses, percentages, formulas, invented values and missing amounts are not
admitted. “Make the TSS threshold stricter” cannot supply a numerical value.
A generic “threshold” cannot stand in for one of several parameters. “It” requires
an explicit parameter focus recorded by the current revision's admitted turn;
otherwise it clarifies. This is bounded operand admission, not a general NLP or
mathematical-expression engine.

Arithmetic uses `Fraction`, never binary floats. The resulting value is passed
to the existing registered `ArgumentSpec.validate`; conversation code introduces
no scientific bounds, threshold defaults or selection comparisons. Editable
parameters are derived from the selection tool's `scientific_parameter` metadata
and must have an exact persisted accepted value (including explicit null).
Unspecified optional fields are not invented or automatically enabled.

All unchanged parameters come from the exact accepted selection's persisted
resolved arguments. The execution adapter checks them again against that source and recomputes the
admitted delta from its persisted value before allowing the planning request.
The Planner cannot drop, add or alter these parameters. A delta produces a new
request and plan; old plans and parameter records remain unchanged.

## Initial capability and target scope

The admitted interaction profile is the mature QC-selected canonical path:
`select_scATAC_cells`, with optional `build_scATAC_cell_by_ccre`. This is an
application capability bound, not a second scientific registry. Scientific
contracts and all 23 tools remain unchanged. Other operations are not silently
converted into this profile.

There is **no new durable “maintain matrix” target**. Each turn authorizes its
own target. A parameter change defaults to selection only. Matrix rebuilding
requires an explicit build/rebuild clause. “Keep this selection and rebuild the
matrix” has no delta and executes matrix production only. Contradictory selection-
only and matrix requests clarify. Existing matrix presence alone never authorizes
new work.

A prior matrix's exact locator may be retained as a configuration-recipe pointer
in interaction metadata, so a later explicit rebuild can recover its accepted
reference path/hash without asking the user to repeat it. This pointer does not
retain the old matrix as a current output, authorize rebuilding, or grant authority.
The scientific matrix owner validates the resulting reference/fragment/selection
compatibility normally. No recipe discovery or “latest matrix” search exists.

New active outputs are explicitly composed from exact compatible F/Q plus the
new selection and, only if requested, new matrix. Matrix-only work explicitly
retains the accepted selection. The M15.3 lineage validator remains authoritative;
a stale matrix is not copied into a selection-only revision.

## Frozen state and durability

An optional `AnalysisSession.interactions` sequence records `Interaction` values:
turn ID, current utterance, captured base revision/generation, private bounded
metadata snapshot, interpretation status and immutable admitted intent. It reuses
the existing checksummed, locked, atomic session snapshot; no second store or
conversation-memory service is added. Old snapshots omit this field and retain
their original serialization.

Snapshots contain at most current, parent and previously-active revisions, each
with at most 32 explicit output locators and one editable selection operation.
The public projection contains relation labels, operation handles, existing
parameter values and recipe availability, never source IDs/paths/hashes or authority
payloads. Private snapshot relations and output sets are checked against the
captured navigation history/revisions when decoding session state.

Metadata capture and interpretation do not validate artifact contents. Only an
admitted execution constructs the M15.3 scientific context and checks source
identity, authority and integrity. Session membership and intent never prove
scientific validity.

Admitted intent includes a deterministic request/run association before scientific
planning. The scientific `SessionTurn` receives the captured base, request anchor,
actual selected output steps and explicit retention before execution. An admitted
delta is immutable across Planner repair/failover; interpretation is not repeated.
Repeated turn IDs with the same utterance reconcile existing state without
resubmission; conflicting utterances fail closed.

An interruption before a resumable scientific plan exists does not authorize a
silent replay of interpretation/submission. Once the plan exists, ordinary
application `resume` restores its M15.3 references and authorities. Explicit
`complete_presentation` and storage-only session `recover` retain M15.2 semantics.
A retry of `respond` reports that durable state without another model call.

## Navigation and branching

The bounded relations are current, parent, previous-active and generic previous.
Previously-active means the source of the last navigation transition that actually
changed the active pointer. Parent means the revision's recorded parent. Generic
“previous/earlier version” or “go back one version” is admitted only when the
available parent/previous-active candidates identify one revision. A provider may
not silently choose parent to bypass that ambiguity.

Explicit natural navigation uses the existing `switch` API and changes no
scientific artifacts. It performs one interpretation call, zero scientific
Planner calls, zero production, zero owner reconstruction, zero artifact-integrity
work and zero presentation. A fresh process reconstructs these relations entirely
from session metadata.

An explicit combined navigation/change first validates the delta against the
chosen frozen historical base, then performs the authorized generation-checked
navigation, then plans new science rooted in that base. If later science fails,
that explicitly selected historical revision remains active. This is two explicit
actions, not an inferred rollback. Separate rollback followed by a new delta creates
a sibling branch; the previous child remains intact.

Concurrent navigation does not rebase a running delta. Its completed child keeps
the captured parent and becomes stale if the generation check loses. A navigation
CAS conflict fails before that navigation or dependent science. Parsing/admission,
Planner, production and verification failures do not activate a new revision.
Presentation failure leaves scientific success available for explicit completion.

## Clarification and deferred scope

Clarification is a durable non-scientific turn with bounded reason/choice/value
metadata. It creates no AgentPlan and leaves the active pointer unchanged.
Examples include missing amount, ambiguous parameter/revision, unknown operation,
invalid resulting value and ungrounded operand. A later self-contained reply such
as “Set TSS to 7” uses current durable state; no transcript replay is required.
There is no rich clarification prose generator or ellipsis-memory system.

M15.5 remains deferred: result Q&A, evidence/state answers, “what changed”, biological
interpretation, explanation, synthesis and post-execution LLM rendering.

# M15.5 — Evidence-grounded conversational state and result responses

## Baseline and boundary

Continue from accepted M15.4 commit
`1a344c790bc8322484d368c4d222cc95fa4bfbeb` without rebuilding the M15.2–M15.4
architecture. M15.5 adds application presentation only. The registry, scientific
contracts, authority schemas, scientific algorithms, verifier ownership,
EpiZoo and one-shot application results are unchanged. No live provider is
required for acceptance. No commit or push is requested.

The initial reviewed response profile is the existing canonical
fragments → QC → explicit selection → canonical matrix interaction profile.
Other scientific outputs fail closed as unsupported projections. This is not
an interpretation system for biology, annotation markers, arbitrary tables,
figures, pathways or resource quality.

## Public contracts

```python
from agent.application import Answer

# Read-only and structured: zero interpreter and scientific Planner calls.
response = app.sessions.answer("analysis", Answer("thresholds"))
print(response.text)

# Natural question: one bounded classification, no scientific Planner.
response = app.sessions.respond(
    "analysis", "question-1", "What did you reuse?", interpreter=model,
)

# Explicit comparison; no implicit globally-latest selection.
response = app.sessions.answer("analysis", Answer("comparison", "parent"))
# Opt in to IDs and hashes only when wanted.
response = app.sessions.answer("analysis", Answer("provenance", technical=True))
```

`Answer(intent, relation="current", technical=False)` extends the closed
Execute/Navigate/Clarify union. Intents are `version`, `matrix`, `selection`,
`thresholds`, `changes`, `execution`, `reuse`, `comparison`, `provenance`,
`verification`, and `unsupported`. Relations are `current`, `parent`,
`previous_active`, and `previous`. Comparison requires a historical relation.
The version-1 wire envelope remains closed, including an exact boolean technical
flag. Normal text omits raw IDs, paths and hashes. Technical answers explicitly
opt in; natural requests must ground that opt-in in their utterance.

`TurnOutcome` adds `text` and optional `facts` without changing the original
kind/status/clarification fields. Low-level run/resume/cancel/session operations
have no mandatory response rendering. There is no new CLI mode. Natural answers
persist their admitted intent and captured revision relation as an `Interaction`
with terminal `answered` status. They create no scientific turn/run, do not change
generation, and do not change parameter focus or the active output set. Structured
answers are read-only and do not create an interaction.

Only current utterance plus the existing bounded public context reaches the
interpreter. No transcript, arbitrary artifact, response text, authority payload
or RunStore dump reaches a response model: there is **no response model**.
Persisted answers contain no prose. Duplicate natural answer IDs re-project the
captured revision without reinterpreting; they identify it as historical if a
later navigation changed the active pointer.

## Reviewed facts and authoritative sources

`response_facts.TurnResponseFacts` is an immutable application projection, not a
second AnalysisEvidence schema or new authority. Its constituent records are:

| Fact | Source and admission |
| --- | --- |
| Revision ordinal, identity, current/historical status | Checksummed session and explicit revision list/active pointer |
| Output roles and exact bindings | Explicit revision locators; whole accepted-step digest; existing `binding_for_locator` and schema-2 authority admission |
| Selection parameters | Exact accepted resolved arguments validated by existing registry ArgumentSpecs; absent optional arguments stay absent |
| Parameter/output changes | Two explicit validated revisions; no artifact-content comparison |
| Registered tool attempts, successful verification events, recovery events | Exact originating run trace; not inferred from plan membership |
| Consumed prior outputs | Exact PriorOutputRefs, accepted resolved arguments, historical-resolution trace and validated accepted source authority |
| Retained outputs | Explicit revision outputs originating in another run; distinguished from consumed inputs |
| Bounded lineage | Exact reviewed matrix→selection/fragments, selection→QC and QC→fragments path/SHA pairs |
| Matrix reference identity | Exact accepted matrix resolved reference SHA; no reference-file interpretation |
| Evidence identity | Verification intent hashes the originating turn's pinned evidence files against completion digests |

`AnalysisSessions._validate_revision` validates the whole originating run-result
anchor before any factual rendering. Every explicit output locator and accepted
binding is then validated. Missing runs, changed result/step identities, invalid
lineage, missing accepted authority and corrupt required evidence fail closed:
“I cannot establish that from the current verified state.” No automatic resume,
scientific reconstruction or artifact repair occurs to answer a question.

Evidence contributes its **pinned identity**, not arbitrary scientific claims.
The conversational projection never calls evidence composition or standalone
scientific verification. Other intents do not require evidence bytes and do not
pretend to validate them. Metadata checksums are distinct from scientific artifact
integrity; answers do not freshly certify current raw sources or complete artifacts.

## Truthful execution and reuse

The historical records contain exact tool attempts and authority-bound references,
but not comprehensive counts of production calls, owner reconstruction, owner
verification or presentation reuse. Those fields remain `None` (unknown), never
zero by inference. The integrity field describes the accepted execution contract,
not a newly observed count or a claim about current artifact bytes.

Normal answers say which tools had recorded attempts and which prior accepted
outputs were consumed. They can state that no upstream production **step** was
included. They explicitly say historical production/reconstruction call totals
were not recorded. They never call this a cache or infer owner reconstruction
avoidance merely from an absent upstream step. Same-run recovery events are
separate from cross-run prior-output consumption and retained output identities.

Acceptance instrumentation separately observes real production bodies, owner
verification entry wrappers, undecorated owner reconstruction/verification bodies,
scientific artifact-integrity functions, metadata loads, application presentation
and deterministic text rendering. These measured test counts are not fabricated
as durable historical facts in the API.

## State, comparison and wording

`responses.render` consumes only reviewed facts. Version numbers are stable
session-list ordinals, not raw IDs. Current thresholds come from the active
selection, never old messages. An upstream-only revision has no selection
thresholds; a selection-only revision has no matrix. An inherited matrix recipe
is configuration and never becomes an active matrix in a response.

`changes` describes the selected revision versus its parent, not the most recent
chat utterance or the globally newest run. `comparison` explicitly resolves the
parent or previously active revision. Generic previous requires a single distinct
candidate; otherwise it returns the bounded parent/previous-active clarification.
No cell counts, biological differences, marker claims or dataset-quality judgments
are inferred from parameter/output differences.

`render_execution` uses the exact completed scientific turn's revision and run.
It names changed parameters, traced tool execution, consumed accepted inputs and
retained outputs. Selection-only summaries explicitly say the historical matrix
is absent. Concurrently stale completions say they are historical, not active.
Repeat-turn summaries re-project current authoritative records.

`render_navigation` names the actually selected version and states that navigation
ran no scientific computation; a repeated old navigation does not claim its
version is still active. Clarification text uses bounded offered choices and
human labels. If “TSS” is already uniquely grounded, only its missing value is
requested. Unsupported biology/marker questions state the layer's limitation
without asserting that a label exists or reading candidate evidence files.

## Restart and mini-conversation

Both BAM-produced and external-fragment tiny accepted DAGs exercise:

1. Establish threshold 6 with a matrix.
2. Set threshold 7 and explicitly rebuild the matrix.
3. Ask version, matrix, selection, thresholds, rerun/reuse, why QC did not rerun,
   provenance, verification basis, latest change and previous-version comparison.
4. Start a fresh Python process; answer all supported categories from persistence,
   replay the admitted comparison without an interpreter, navigate to the previous
   version and read threshold 6.
5. Create a selection-only sibling; verify no historical matrix is described as
   active. Visit the other sibling and return; require clarification for ambiguous
   previous, and honor explicit parent versus previously active comparisons.

Separate acceptance covers matrix-only rebuild summaries, structured answers,
minimal clarification, frozen answer replay, unsupported questions, absent
selection, session corruption, missing run, changed result, rehashed invalid
locator, and required evidence digest mismatch. No assistant-message memory is
needed. Production/owner profilers surround informational paths.

# M11.2c — canonical FASTQ fragments data layer

This slice consumes accepted M10/M11.1/M11.2b artifacts and produces independently
verified canonical fragments. It adds no ToolSpec, Planner/compiler, Runtime,
evidence/reporting, cell calling, QC, or cCRE projection. Existing accepted
M11.2b files remain byte-identical. No commit or push is part of this slice.

## Private API and authority

```python
from agent.tools.data._fragments_binding import FragmentInputs
from agent.tools.data._fragments_common import FragmentsRuntime
from agent.tools.data.fastq_fragments import prepare_fastq_fragments
from agent.tools.data.scatac_fragments_verifier import verify_fragments

# Every path/digest is supplied explicitly from the accepted artifact pointers.
inputs = FragmentInputs(
    intake_path, intake_sha256,
    context_path, context_sha256,
    reference_path, reference_sha256,
    index_manifest_path, index_manifest_sha256,
)
runtime = FragmentsRuntime(qualified_chromap_absolute_path)
result = prepare_fastq_fragments(inputs=inputs, runtime=runtime,
                                output_dir=fresh_managed_output_directory)
verify_fragments(result['manifest_path'], runtime=runtime,
                 expected_sha256=result['manifest_sha256'])
```

The output directory must be normalized, absolute, absent, and have an existing
parent. The runtime fields are explicit executable configuration, never request
science or LLM options. Default packaging executables are the pinned local
`/usr/bin/bgzip`, `/usr/bin/tabix`, and `/usr/bin/sort`; no PATH lookup, fallback,
rebuild, download, or arbitrary flags are supported. Another packaging build
requires explicit qualification and a reviewed identity change.

The lightweight result contains status, manifest path/hash, artifact/schema/
contract versions, species, assembly, library count, fragment-record count, and
total support. The detailed authority remains the manifest.

## Preflight and M10 source verification

First load/hash the four artifacts, validate exact context/intake/group bindings,
and require selected FASTQ groups to be partitioned exactly once by the context.
Species/assembly must agree (`human/hg38`, `mouse/mm10`). Reference/index binding
includes exact manifest hash, reference portable identity, FASTA/FAI/ordered
contigs, qualified backend, actual index bytes, and k17/w7 policy. FASTQ requires
raw sequence, whitelist-required policy, and a verified 1..32-base whitelist.
Mixed/unsupported layouts and unrepresentable role/path lists fail closed.

There is no new file-discovery or layout-inference implementation. M10 evidence
provides layout/read-meaning projections; its existing `_reconstruct` repeats
bounded selection, discovery, observations, declarations, and canonical manifest
comparison. This rechecks the complete intake inventory, including groups omitted
by an explicit context subset. It remains bounded raw observation, not a full
raw-file hash. A directory's changed selected inventory is detected by the same
M10 discovery rules. Reference reinspection also checks the bundle's cCRE and
optional annotation identities; neither is used for alignment or overlap counting.

The M10 `group:<sha256>` ID is mechanically projected to the accepted private
Chromap adapter's digest-only group identifier. The full M10 ID is preserved in
the fragments manifest. Canonical group sorting remains identical because every
M10 group ID has the same fixed prefix. No biological grouping is inferred.

## Full-stream FASTQ scan

Every selected group's genomic mate 1, mate 2, and barcode streams are scanned
in lockstep to clean EOF. Both plain and gzip content are supported, following
M10's content detection. Concatenated gzip members must decompress completely;
CRC errors and truncation fail. I1 is excluded from alignment/full synchronization
but remains included in M10 reinspection and source-change snapshots.

The scan retains at most one four-line record per selected role. It reuses M10's
line-size limit, LF/CRLF handling, printable sequence/quality rules, header and
repeated `+`-header rules, and `/1`/`/2` normalization. Normalized ID tokens are
compared exactly across roles; no ID vectors are retained. Barcode records must
match the selected whitelist length and contain uppercase A/C/G/T/N. More than
one N is not repaired by Agent; the accepted Chromap correction/filter policy
decides its outcome.

Per-group diagnostics record complete record count, SHA-256 of concatenated
32-byte M10 normalized-ID hashes, and three SHA-256 values covering exact decoded
record bytes, including line endings, in genomic1/genomic2/barcode order. These
are semantic/decoded full-stream identities. They are **not encoded source-file
SHA-256 values**. Count mismatches and same-count name/order mismatches fail.

Snapshots include device, inode, size, mtime ns, ctime ns, and regular-file type.
Raw inputs, upstream artifacts, whitelist/reference/index resources, and
executables are checked across scan, execution, and publication. Source mutation
fails without retry. These are trusted-local-filesystem consistency checks,
not a claim of protection against hostile race/rollback attacks.

## Execution and canonicalization

Every processing library runs Chromap once, with all of its groups in canonical
order and one shared whitelist. Independent namespaces always run separately.
Layout A maps R1/R3/R2 to `-1/-2/-b`; B maps R1/R2/I2. I1 never becomes a barcode.

Execution uses the unchanged `chromap-atac-agent-support-v1` policy and exact
accepted executable/runtime identity. Manifest provenance includes the upstream
tag/commit/version, patch/build/executable identities, every fixed CLI flag and
implementation policy constant, including one thread, correction, representative
MAPQ filtering, cell-level deduplication, and the sole Tn5 shift.

Raw output remains private. Successful exit must produce a regular five-column
BED file with no unexpected leftover artifacts. Each row requires exact tab
separation, UTF-8 text, LF termination, no CR/header/extra fields, a known FAI
contig, canonical decimal coordinates in bounds, an exact whitelist barcode,
and positive decimal support. Agent never clips, repairs, drops, recounts, or
shifts a row. Support 255 is accepted as an exact value under the patched policy.

GNU sort receives a temporary numeric FAI rank instead of the contig string:

```text
LC_ALL=C
sort --parallel=1 -S 64M -t <TAB> -k1,1n -k2,2n -k3,3n -k4,4
     -T <managed staging> -o <sorted file> -- <ranked input>
```

Ordering is FAI rank, numeric start, numeric end, then ASCII barcode. Exact
duplicate canonical keys fail. The rank column is removed mechanically.
External sorting uses managed sibling storage, never a default production `/tmp`.
Distinct-barcode tracking uses memory proportional to observed whitelist tokens,
not reads/fragments. The whitelist candidate set is also held in memory.

## Support and byte identities

Individual support is an exact positive integer through `2**64 - 1`. Aggregate
support/count fields use checked Python integer arithmetic bounded by `2**128 - 1`;
the cross-library support total is checked too. No float conversion or narrowing
occurs. Wide storage/verification fixtures exercise aggregate support above uint64.

Support is the exact number of Chromap-generated paired mappings assigned to the
accepted cell-level group defined by corrected barcode, reference contig, fragment
start and length, including the representative. It is not necessarily the number
of individually MAPQ-passing reads, and it is not a molecule count. Filtering
uses the frozen representative-MAPQ policy. Future matrix dtype decisions do not
change this fragment contract.

Canonical record identity hashes these exact uncompressed bytes, in canonical order:

```text
chrom<TAB>start<TAB>end<TAB>corrected_barcode<TAB>support<LF>
```

Contigs are exact UTF-8 FAI names; barcode and canonical decimal integers are ASCII.
Namespace remains exclusively in the library entry. Cell identity is the tuple
`(namespace, barcode)`; final rendered cell IDs remain undefined.

The checked packaging record is `src/agent/tools/data/_fragments_toolchain.json`.
It includes exact executable/version and resolved shared-library/loader hashes.

| Program | Qualified version | Executable SHA-256 |
| --- | --- | --- |
| bgzip | htslib 1.13+ds | `41bb989daf631c58f2a576fb1ccdf0e478e309dbb3c4428fdde6e66a718ab2a4` |
| tabix | htslib 1.13+ds | `82b2381647a8491a1531cb1a84600eb59fd102de84f6175b5d144962f2dfd6d2` |
| sort | GNU coreutils 8.32 | `20def485217b069331752f5309cf5b00d9a9f9edcc6a35d4c5177eb4ce563ac5` |

Compression is `bgzip -c -l 6 -@ 1`; indexing is `tabix -p bed` (TBI). Known
0-based half-open fixtures confirm BED/query behavior, including narrow queries
and FAI ordering different from lexical contig order. Contig lengths above
`2**29` fail with `FRAGMENTS_INDEX_POLICY_UNSUPPORTED`; no CSI fallback occurs.
Two tiny same-profile compression runs matched physically. General cross-build
byte determinism is not promised. Every BGZF and TBI gets its actual SHA-256 and
byte size regardless of observed repeatability.

## Manifest and publication

The closed artifact is `agent.scatac-fragments`, schema 1, contract
`scatac-fragments.v1`. Strict loading rejects unknown/missing fields, duplicates,
nonfinite numbers, invalid enums/policies/hashes, boolean numeric impostors,
invalid namespaces, overlapping groups, invalid relative artifact paths, and
inconsistent counts/identity. JSON is bounded to 8 MiB. Ordinary loading reads
only this JSON and does not scan FASTQ, read fragments, or run Chromap.

The manifest includes all input artifact paths/digests and their exact scientific
lineage; backend/full policies; and sorted per-library entries with namespace,
group IDs, library/role binding identities, whitelist byte/set hashes, length,
scan diagnostics, BGZF/TBI hashes/sizes, canonical stream digest, record/support
statistics, and observed distinct-barcode count. The latter is neither whitelist
size nor called/QC-passed cell count. No complete barcode or fragment vectors enter
the manifest.

Portable identity is SHA-256 of `agent.scatac-fragments.v1` plus NUL plus canonical
JSON after removing its own digest, input locator paths, and per-library physical
BGZF/TBI records. It retains exact upstream artifact digests, lineage, namespaces,
membership/whitelist/role identities, semantic scan diagnostics, logical fragment
streams, counts, and policies. Physical file hashes remain protected separately
by the manifest-byte hash. Upstream M10 identity is path-sensitive, so this is not
total relocation independence.

All libraries are staged in a private sibling directory protected by a persistent
cooperating-writer flock. The independent verifier must accept the complete candidate
before fsync and atomic directory rename. Only the manifest and per-library BGZF/TBI
files are published; raw outputs, logs, and sort intermediates are removed first.
Per-library files live under `libraries/<namespace>/`, so valid namespaces such
as `manifest.json`, `libraries`, and `process.log` cannot collide with root files.
An existing destination always conflicts, even for identical content. Concurrent
identical calls produce one winner and one explicit conflict. No overwrite or
partial-stage resume is provided.

Exceptions and interruption remove the private attempt after terminating/reaping
an active stage child. Process stages never retry automatically. A final parent
directory-fsync failure can leave a complete verified artifact after rename;
it cannot expose a partial manifest/BGZF/TBI set. Stronger hostile filesystem
race hardening and orchestration cancellation belong to later work.

## Independent verification and limits

The verifier reloads strict JSON, recomputes portable identity, and freshly checks
M10 bounded sources, context/library bindings, whitelist contents, reference
resources and FASTA/FAI consistency, and actual derived-index content. It does not
rebuild the Chromap index or invoke Chromap, including its version command.
The recorded accepted Chromap identity is validated; packaging tools are freshly
identified because verification uses tabix.

It independently decodes every BGZF block, checks BGZF structure, CRC/ISIZE,
decompression limits, terminal EOF marker, complete lines, coordinates, whitelist
membership, positive support, order, duplicate keys, canonical stream SHA, counts,
sum/max support, and distinct barcodes. It imports no production fragment parser.
Every represented contig is queried through TBI and compared by exact stream digest.
The first canonical interval per contig also defines a deterministic narrow query;
an independent second stream computes expected overlaps. TBI existence/hash alone
is insufficient. Tests separately rebuild a tiny TBI and compare functional output.

This proves artifact invariants and consistency with recorded qualified execution
lineage. It does not independently authenticate historical execution, prove
alignment biological correctness/optimality/completeness, true barcode identity,
probabilistic correction correctness beyond backend qualification, or biological
duplicate truth. Rewriting a fully self-consistent manifest without a trusted
expected hash is not source authentication. The verifier does not redo the
pre-execution full FASTQ scan; those recorded diagnostics are execution provenance,
distinct from its fresh bounded M10 source checks and complete fragment checks.

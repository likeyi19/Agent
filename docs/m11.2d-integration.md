# M11.2d internal integration contract

> Historical checkpoint: M11.3d supersedes fragment-version and compatibility
> statements in this record. All current producers publish fragments v2; the
> current runtime rejects fragments v1 and does not resume its old runs/receipts.
> Scientific history below is retained. See [M11.3d](m11.3d-fragment-convergence.md).

This slice introduces exactly one registered scientific capability,
`prepare_scATAC_fragments`, for FASTQ only. M11.2b/c source, tests, qualification
records and documentation remain byte-identical. No scientific algorithm,
fragment contract version, index policy, or accepted backend identity changes.
This is not the final README/AGENTS milestone closeout.

## Public API and planning

```python
prepare_scATAC_fragments(
    intake_manifest_path, intake_manifest_sha256,
    library_context_path, library_context_sha256,
    reference_bundle_path, reference_bundle_sha256,
    output_dir,
)
```

All seven arguments are required. Artifact path arguments accept strings/Paths;
SHA arguments accept strings. Runtime scientific preflight validates the exact
artifact contents/identities. There are no scientific optional parameters and no
overwrite/retry argument. The compact result retains M11.2c's eleven fields:
status, manifest_path, manifest_sha256, artifact_type, artifact_schema_version,
contract_version, species, assembly, n_libraries, n_fragment_records, total_support.
The result contract checks exact fields, types, success identity, fixed artifact
versions, path/hash shape, species/assembly, and aggregate bounds without IO.

The reviewed semantic ports are:

| Consumer | Grouped request selector | Execution members | Upstream type |
| --- | --- | --- | --- |
| intake | intake_manifest_path | intake_manifest_path / intake_manifest_sha256 | raw_scatac_intake_manifest.v1 |
| library_context | library_context_path | library_context_path / library_context_sha256 | Request only |
| reference | reference_bundle_path | reference_bundle_path / reference_bundle_sha256 | Request only |
| output_dir | output_dir | output_dir | Existing managed-output convention |

The selector names one member of its group, as required by the existing generic
compiler. Selecting it binds both manifest members; the model does not bind
the SHA independently. One output port, `fragments`, has semantic type
`scatac_fragments.v1` and members manifest_path/manifest_sha256. New descriptive
artifact kinds distinguish fragments, library context, and reference bundles.

V4 source choices compile through unchanged generic compiler/catalog/schema code.
The intake port supports an explicitly chosen upstream inspection producer or
an explicitly supplied existing intake. Inspection is never auto-inserted.
V3's existing keyed request/ref bindings remain supported. Complete-registry
tests now account for the additional tool. The complete v3 size fixture measures
13,023 schema bytes and 17,843 prompt bytes (30,866 combined); the combined
31,000-byte ceiling is unchanged. No provider-specific representation was added.

Registry construction and PLAN_ONLY do not resolve runtime configuration, open
scientific manifests/FASTQ/reference/whitelists, or execute external tools.
Planner guidance describes the high-level capability and input compatibility,
not Chromap, role mechanics, sorting, executable paths, or flags.

## Execution-only configuration

`AGENT_CHROMAP_BIN` must explicitly name the accepted M11.2b executable. Its
existing hash/version/platform/linkage checks apply. `AGENT_CHROMAP_INDEX_ROOT`
must be an absolute existing directory containing at most 4,096 immediate child
index directories, each with a valid `manifest.json`. This is a deliberately
narrow resource catalog, not recursive filesystem discovery. Malformed entries
fail closed. Exactly one candidate must match reference portable identity,
accepted backend identity, and k17/w7 build policy; zero/multiple matches fail.
M11.2c then checks exact reference manifest binding and actual index content.

The accepted fixed `/usr/bin/sort`, `/usr/bin/bgzip`, and `/usr/bin/tabix` packaging
profile is reused without new environment overrides. No PATH fallback, automatic
index build, stock fallback, runtime substitution, or planner-selected backend
parameters exist. Configuration resolution happens only on new execution.

## Publication-before-checkpoint recovery

Existing M5 behavior refuses to rerun stale RUNNING steps because their scientific
outcome is unknown. M11.2c's ordinary existing-directory conflict is preserved.
The new registered wrapper instead runs M11.2c inside a private outer publication
envelope. After M11.2c completes, the wrapper adds a strict receipt, freshly verifies
the fragment manifest, fsyncs, and atomically publishes the complete envelope.

The deterministic durable execution identity hashes a domain separator plus
run ID, full plan fingerprint, step ID, tool name and registered recovery-policy
version. The exact final directory token additionally binds all resolved public
arguments and the policy. Its location is:

```text
<output_dir>/scatac-fragments-<token>/
    receipt.json
    fragments/manifest.json
    fragments/libraries/<namespace>/fragments.tsv.gz
    fragments/libraries/<namespace>/fragments.tsv.gz.tbi
```

The receipt binds the directory token, exact public argument digest, recovery
policy, and fragment manifest SHA. M11.2c's private writer-lock file may also
remain inside the envelope; it is not a scientific artifact or receipt authority.
Normal calls still conflict on an existing exact destination. They never recover
or silently reuse it. Calls without durable execution use a distinct identity
domain value and cannot satisfy another run's durable receipt.

`DurableToolHooks` is a small optional registry-owned pair of execution/recovery
callbacks. Only opted-in tools use it. The executor passes a run-bound identity
only while durable checkpointing is active; no new scientific argument or global
cancellation context is introduced. No generic compiler changes are involved.

For a stale RUNNING opted-in step, Runtime first requires the persisted recovery
policy fingerprint to match. It resolves arguments from the persisted plan and
freshly verifies completed dependencies in stable topological order. The recovery
callback opens only the exact derived destination, checks its receipt, invokes
M11.2c's independent verifier, and reconstructs the compact result from that
manifest. Registry validation and orchestration verification run before a
SUCCEEDED result is checkpointed. Pending work then uses the normal executor.

There is no directory scan for matching-looking output and no retry of alignment.
Absent, unrelated, conflicting, corrupt, or wrong-policy receipts fail closed.
The original INTERRUPTED/manual-reconciliation state is retained when recovery
cannot establish an outcome, with the specific recovery failure preserved as an
additional sanitized error. Durable store failures propagate without marking an
otherwise recoverable publication permanently failed. A crash before the outer
atomic rename has no accepted receipt and does not authorize automatic rerun.

These are trusted-local-filesystem recovery identities, not cryptographic proof
of historical execution against a hostile artifact author. Existing source/
artifact verification and provenance limitations remain unchanged.

## Verification, resume, retry and cancellation

`verify_step` dispatches to the public envelope verifier, which calls the accepted
independent M11.2c verifier. It verifies compact result equality against the
manifest, exact public input lineage, receipt/manifest identity, output binding,
and actual upstream intake dependency values. The registry result validator
remains a separate lightweight layer.

Completed steps in a **nonterminal** durable run are freshly verified before
reuse. Neither this verification nor crash-window recovery resolves Chromap or
the index catalog. The recorded index path/content and accepted backend identity
remain verifiable from artifacts. Packaging tools used by the M11.2c verifier
must remain available. No full FASTQ pre-scan or alignment reruns occur. Terminal
resume preserves M5's immutable stored-result return, including after later drift;
this is explicitly tested and is distinct from nonterminal resume verification.

Recovery policy is `prepare-scatac-fragments-fastq-v1`. Its identity must change
with public scientific argument meaning, backend/support/fragment policy, or
verification/recovery semantics. Retryable error codes are empty: deterministic
configuration/input/scientific/output failures execute once despite the generic
two-attempt ceiling. Storage errors require external correction. Stable domain
codes receive sanitized category/message/disposition mappings; raw stderr and
source contents do not enter public error prose.

M5 cooperative cancellation is preserved: before-step cancellation prevents
scientific execution; cancellation requested inside a registered tool call takes
effect after that call and its verification reach the existing safe checkpoint.
It does not preempt Chromap. Completed verified fragments survive cancellation,
pending downstream work is skipped, and terminal cancellation is idempotent.
Cancellation during receipt recovery uses existing terminal arbitration to retain
the recovered verified result. M11.2c child cleanup on process interruption/errors
is unchanged. No second cancellation state machine was introduced.

# M11.3c — Qualified BAM to verified fragments v2

Based on `17d66ac92ec931e0e0980e32f3dd8bbe4a063236` (M11.3b closeout).
The scientific registry adds exactly `prepare_scATAC_bam_fragments`, for fifteen
tools. This is an Agent-defined policy, **not Cell Ranger reproduction**.
Biological acceptance remains deferred to M11.8.

## Qualified source and explicit declarations

The only executable profile is `agent-cb-paired-atac.v1`: one selected BAM group,
one BAM file, one processing library and one explicit namespace; paired scATAC;
human/hg38 or mouse/mm10; matching source/target assembly; explicit `CB` source,
`corrected_identifier` interpretation and `already_corrected` policy in the
existing `LibraryProcessingContext.v1`. Context selection may explicitly select
one group from a larger intake. No record-level library demultiplexing occurs.

Selecting this required profile explicitly declares that alignment coordinates
are unshifted and duplicate pairs were retained. The tool cannot infer or prove
that history from BAM coordinates or flags. Known shifted, deduplicated or
unknown-history sources are unsupported. The source's historical export coverage
remains `source_selection=unspecified`; Agent's own eligible subset is separately
and exactly reconstructed. No original sequencing-completeness claim is made.

M10's bounded inspection is freshly reobserved, including its advisory index and
sorting observations. It is not a full BAM execution identity or qualification.
Production needs neither coordinate order nor BAI/CSI. It makes no source-index
verification claim. Arbitrary SAM/CRAM bytes are rejected even under a BAM name.

## Barcode and library semantics

Each potentially contributing primary pair needs valid string CB on both mates,
with exact equality. Preserve ASCII case, suffixes such as `-1`, and all existing
v2 safe identifier characters (printable ASCII 33–126, length 1–256). Namespace
remains separate from identifier text. Missing CB excludes the pair; malformed,
duplicate or disagreeing CB tags fail qualification before exclusion accounting.
Generic CB presence does not establish historical barcode correction.

Both primary mates have the same declared RG or both omit RG. Declared RGs must
belong to the selected processing library. Conflicting LB identities, partial LB
metadata that cannot bind to its selected library identity, undeclared RGs and
mate RG disagreement fail. Multiple RGs within that one library are supported.
RG retains its reviewed SAM string semantics, including internal spaces; CB's
v2 identifier restrictions are not applied to RG. CR, custom tags, read-name
barcodes and whitelist correction are not executable.

## Template validation and exclusion order

Template identity is `(bound BAM, exact QNAME)`, without suffix removal or
renaming. QNAME follows the SAM bounded ASCII identifier contract. Externally
sort projections by an unambiguous hex encoding of the exact name; retain only
two primary projections and scalar ancillary summaries per group.

Require exactly one primary R1 and one primary R2, both flagged paired. Missing
mates, duplicate primary ends, ambiguous repeated primary pairs, contradictory
R1/R2 bits and unpaired primary records fail. Ancillary secondary/supplementary
alignments never add support. Any supplementary record excludes its template;
secondary records alone do not disqualify an otherwise eligible primary pair.

Validate reciprocal mapped-state flags. Compare mate coordinates when defined;
mapped mates require exact reciprocal reference/position and orientation. Unknown
location/orientation for an unmapped mate does not invent contradictory metadata.
Known conflicting metadata fails. For same-contig mapped primary pairs TLEN is
either zero on both or opposite with magnitude equal to the outer reference span.
TLEN never supplies fragment coordinates.

All structural and tag errors fail before accounting. For a structurally valid
complete primary pair, count exactly the first applicable exclusion:

| Order / reason | Condition |
| --- | --- |
| 1 `unmapped` | Either primary/mate is unmapped |
| 2 `discordant` | Mates map to different contigs |
| 3 `improper` | Either lacks proper-pair status |
| 4 `qc_failed` | Either has the BAM QC-failure flag |
| 5 `split` | Supplementary template evidence or primary SA evidence |
| 6 `unsupported_cigar` | N/P or ambiguous physical 5′ endpoint |
| 7 `geometry` | Same-strand, outward or dovetail geometry |
| 8 `mapq` | Either MAPQ below 30 or equal to 255 |
| 9 `missing_cb` | Either corrected CB absent |
| 10 `short_shifted` | Valid raw span becomes invalid after +4/−5 |

Primary pair count equals template count, which equals eligible pairs plus the
sum of exclusions. Secondary/supplementary counts describe their respective flag
sets; they can overlap. No eligible pairs means an explicit empty-result error,
not publication of an empty v2 library.

## Coordinates, CIGAR, MAPQ and contigs

Validate CIGAR independently of decoder-reported `reference_end`: M/=/X/D/N
consume reference; M/=/X/I/S consume query. Validate positive operations, legal
terminal H/S placement, available SEQ length, positive mapped reference spans,
dictionary membership and exact reference bounds. No sequences/qualities are
serialized in projections. Missing SEQ does not prevent a valid CIGAR check.

Ordinary internal I/D are supported. N/splicing and P/padding are excluded. The
physical 5′ CIGAR endpoint must be M/=/X: forward first operation, reverse last
operation. No extrapolation through 5′ S/H or terminal indels. Legal opposite
3′ clipping is accepted without extending the aligned interval.

Require one forward and one reverse primary alignment, with
`forward.start <= reverse.start` and `forward.end <= reverse.end`. Overlap is
allowed. The forward supplies the left endpoint and reverse supplies the right,
regardless of R1/R2 labels:

```text
fragment_start = forward.reference_start + 4
fragment_end   = reverse.CIGAR_reference_end - 5
0 <= fragment_start < fragment_end <= exact_contig_length
```

Intervals are zero-based, half-open and shifted exactly once. No repair, clamping,
arbitrary maximum fragment length or pre-shift detection heuristic is applied.

Both mates independently require **MAPQ >= 30**, excluding 255 before aggregation.
pysam exposes the uint8 MAPQ value; this profile conservatively excludes all 255
values rather than treating them as normal confidence scores. A passing pair
cannot carry support from a failing duplicate. This differs from Cell Ranger's
documented representative-based `>30` filtering and from the FASTQ policy.

Every declared BAM SQ name/length must exactly match FAI; a dictionary subset or
different dictionary order is permitted. Check present SQ sequence MD5 against
the bound FASTA using bounded sequence reads. Absent MD5 does not prove historical
alignment-reference identity. Output uses FAI order. All exact FAI contigs are
eligible, including mitochondria and scaffolds; no regex, alias or primary-contig
inference occurs. Existing BGZF/TBI coordinate bounds remain applicable.

## Exact duplicate identity, support and strand

Collapse only the complete identical key:

```text
(namespace, barcode_identifier, contig, shifted_start, shifted_end)
```

Each distinct eligible complete primary pair adds exactly one. Duplicate-marked
and unmarked pairs both contribute. One-endpoint sharing, different barcodes or
namespaces, duplicate flags and upstream duplicate-count tags do not authorize
additional collapsing or support. No optical/PCR or molecule-count inference.

Support is the number of well-formed primary pairs **present in the bound BAM**
that individually pass this profile and produce the exact shifted key. It is not
the original sequenced-pair total, the unique fragment-record count or a molecule
count. Enforce positive uint64 per record and checked uint128 aggregates without
floating conversion. Removed upstream pairs cannot be reconstructed.

Publish five-column, strand-absent v2. The common reader yields `strand=None`.
Genomic orientation does not establish 10x adapter-origin fragment strand.

## Runtime and resource identity

Use the already installed optional `pysam==0.24.1`, with htslib/samtools `1.24`.
No standalone samtools, Sinto, SnapATAC2, aligner, GPU or checkpoint is required.
The reviewed runtime identity is
`bd198afb4f2a0faddc6f0de45dd9df236da1f3f16f88f7cb1d8a6956e7b708f5`.
`_bam_fragment_toolchain.json` pins the decoder extensions, package entry/version
files, bundled shared libraries and resolved linked-library hashes. Recompute
and compare them at execution and fresh verification. Other ABI/builds require
explicit qualification; matching version strings alone do not suffice.
Existing qualified sort/bgzip/tabix identities and packaging settings are reused.
No dependency declaration was changed.

The final acceptance audit corrected verification ordering: packaging identities
are checked before reconstruction subprocesses, and the decoder identity is
checked before binding reobserves M10 BAM contents. Two regression cases reject
changed decoder bytes and an unqualified sort executable before source processing.

Require direct source path and caller-supplied full encoded BAM SHA-256. Bind its
size, complete decode, header/SQ hashes and full ordered projection-stream hash.
Bind exact intake/context/reference identities, group, namespace and profile.
An identical intake may relocate under the existing M11.1 hash-based binding
contract; the BAM path must still equal the selected intake source exactly.

Source/stat snapshots and complete before/after hashes detect replacement,
mutation and truncation. Sources are rechecked during producer verification,
public-result verification, evidence construction and recovery. Existing stronger
hostile-filesystem race hardening remains deferred; this is not a transactional
snapshot guarantee against arbitrary adversarial changes and restoration.

`bam-fragment-production.v1` is a new closed, bounded producer record using the
already reserved v2 `bam_fragment_production` kind. It binds resolved arguments,
source/intake/context/reference resources, runtime identity, exact profile,
history declarations, full qualification counts/digests, canonical summary and
BGZF/TBI output identities. `profile.json` binds all frozen scientific and
packaging policies. No generic v2 schema or processing-status extension was needed.

## Verification and resource bounds

Production: decode bounded projections → external QNAME sort → complete pair
qualification → external exact-key sort → checked streaming support aggregation
→ canonical BGZF/TBI. Separate external barcode sorting counts distinct identifiers.

The BAM verifier independently redecodes and reconstructs pair eligibility,
CIGAR endpoints, shifts and exact support; it never imports production scientific
helpers. Shared components are physical decoding/projection, artifact binding,
reference hashing, bounded IO, schema constants and mechanical sorting. Compare
every expected canonical line and all qualification counts, not just
`sum(support) == eligible_pairs`. Then run generic v2 integrity/index verification.

The producer and independent reconstruction use 64 MiB external-sort buffers,
at most two primary records per template, bounded header/reference metadata and
post-decode projections capped at 1 MiB. No complete BAM, per-record barcode
vector or whole-barcode read group is accumulated. htslib allocation for a single
decoded record/header precedes these limits. Existing generic v2 verification
still uses memory proportional to distinct fragment identifiers for its summary.
Scratch is O(decoded projections/eligible pairs) and can exceed BAM file size;
multiple full BAM passes and external sorts are intentional verification costs.
Managed private scratch is removed after success, handled failure or interruption.
Persistent publication lock files follow the existing recovery pattern.

Verified claims are source bytes, the Agent transformation from those bytes and
output integrity. Original sequencing completeness, historical aligner accuracy,
barcode-correction truth, prior coordinate history and prior duplicate retention
remain declarations/not independently established.

## Public API, planning and durable Application execution

```python
from agent.tools.data.scatac_bam_fragments import prepare_scATAC_bam_fragments

result = prepare_scATAC_bam_fragments(
    intake_manifest_path=intake_path,
    intake_manifest_sha256=intake_sha,
    library_context_path=context_path,
    library_context_sha256=context_sha,
    reference_bundle_path=reference_path,
    reference_bundle_sha256=reference_sha,
    source_path=bam_path,
    source_sha256=full_bam_sha,
    source_profile="agent-cb-paired-atac.v1",
    output_dir=managed_output_dir,
)
```

The lightweight result contains status, manifest path/hash, artifact/schema/
contract identity, profile, species/assembly, namespace, one library, template
and eligible-pair counts, canonical record count, total support and absent strand.
Result validation is pure and performs no scientific IO.

Grouped semantic ports bind intake, library context, reference and BAM path/hash;
profile is explicit and output is managed. Intake can come from the reviewed M10
producer port. Compiler expansion supplies both StepOutputRefs and dependencies.
No compiler, executor or Application architecture changes, hidden inspection,
workflow completion, filename routing, CB/CR inference, reference/namespace
inference or planner-selected backend were added. V4 remains default; explicit
v3 is supported. PLAN_ONLY performs zero BAM/reference/scientific IO or processes
and creates no scientific artifacts; durable planning-state persistence remains.

Recovery policy is `prepare-scatac-fragments-bam-v1`. The exact destination/receipt
bind resolved arguments, profile hash and durable run/plan/step/tool identity.
Verify private staging, fsync, then publish atomically without overwriting. Exact
receipt recovery freshly verifies source, independent transformation and generic
v2 integrity without calling production. Missing/wrong receipts fail; no broad
search, first match, altered parameters or automatic rerun occurs. Existing
before/after-tool cooperative cancellation boundaries are preserved.

Application supports EXECUTE, producer-aware evidence, deterministic figureless
reports, durable resume and publication-before-checkpoint recovery. Reports show
bounded source/namespace/reference, template/exclusion/support and verification
facts. They explicitly separate verified transformation from declared history;
observed barcodes are not called or QC-passed cells.

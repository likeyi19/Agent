# M11.4a — frozen QC science and resources

M11.4a adds data-domain contracts, resource construction/reinspection, and narrow
local backend qualification. It adds no scientific tool: the registry remains
15. M11.4b per-barcode metric execution and M11.4c selection are unimplemented.

The accepted future path is verified `scatac-fragments.v2` → verified per-barcode
QC → explicit QC-threshold selection → immutable ordered selected barcodes →
M11.5 cell-by-cCRE construction. QC selection is not background-versus-cell
calling. Future selection will declare `cell_call_method=none`,
`cell_call_state=not_assessed`, `selection_method=explicit_qc_thresholds.v1`.
No selection artifact is created here.

## Scientific profile

`scatac-qc-science.v1` is the immutable `QCScientificProfile` in
`src/agent/tools/data/scatac_qc_profile.py`. Its canonical JSON SHA-256 binds the
entire profile into each QC reference bundle.

For each exact `(namespace, barcode_identifier)`, `n_fragment_records` counts
all canonical retained fragment records. `n_qc_fragment_records` counts only
records on explicitly classified primary nuclear QC contigs and is the future
selection-depth quantity. These are artifact-level producer-neutral counts,
not molecule counts or raw sequencing depth, and do not establish identical
upstream retention across producers. Preserve total depth separately. Support
remains producer-specific provenance; neither support weighting nor universal
PCR-duplicate/saturation interpretation is authorized.

### TSS enrichment

Method `agent-tss-incidence-101-200.v1` is Agent-defined and ENCODE-inspired.
It does not claim numerical equivalence to ArchR, historical Signac, fragtk, or
Cell Ranger.

Every fragment contributes two weight-one endpoint occurrences:
`[start,start+1)` and `[end-1,end)`. No additional Tn5 shift is applied. Even a
one-base fragment contributes two coincident occurrences. At zero-based TSS
base `p`, the windows are:

| Region | Zero-based half-open window | Bases |
| --- | --- | --- |
| Center | `[p-50,p+51)` | 101 |
| Left flank | `[p-2000,p-1900)` | 100 |
| Right flank | `[p+1901,p+2001)` | 100 |

An endpoint counts against **every distinct TSS** window it overlaps, including
opposite-strand TSSs at the same position. There is no sampling, merging,
unique-hit collapse, or support weighting. Left/right refer to genomic
coordinates on both strands; the symmetric combined score is strand-neutral.
Touching intervals do not overlap. Complete windows require
`2000 <= p < contig_length-2000`; construction excludes incomplete windows,
and runtime never clips them.

Retain exact integer `center`, `left_flank`, and `right_flank` counts per future
barcode. With `F=left_flank+right_flank`, the score is
`200*center/(101*F)`. It is an incidence statistic and can exceed one. If `F=0`,
return null with `ZERO_TSS_BACKGROUND`, never infinity, a fabricated zero, or a
population background. Helpers return exact `Fraction` values; future storage
must preserve integer sufficient statistics and future threshold comparisons
must use exact arithmetic, not rounded report values. Each count and combined
flank count is an unsigned integer bounded by `2**128-1`; overflow fails.

### Fragment lengths

Length is `end-start`, with one record per observation, on the primary nuclear
QC-contig scope for future selection-related metrics:

| Bin | Length |
| --- | --- |
| nucleosome_free | `1 <= L < 147` |
| mononucleosomal | `147 <= L < 294` |
| longer | `L >= 294` |

`nucleosome_signal=mononucleosomal/nucleosome_free`; a zero denominator produces
null and `ZERO_NUCLEOSOME_FREE`. The descriptive metric has no default filter
and implies no doublet inference. The frozen bounded aggregate histogram has
1,000 exact-length bins (1–1,000) and one overflow bin (`L>=1001`), using the
same scope and record counts. No histogram computation is implemented here.

## QC reference resources

`ScATACQCReferenceBundle` is separate from `ScATACReferenceBundle`; the latter's
optional annotation field is not reinterpreted. The closed frozen schema is
`agent.scatac-qc-reference-bundle`, schema 1,
`scatac-qc-reference-bundle.v1`. It binds:

- human/hg38 or mouse/mm10, exact parent manifest bytes and reference identity;
- the exact ordered contig digest and a complete ordered classification;
- scientific and construction profiles, source family/release, annotation
  bytes/size, parser profile and identity, and qualification state;
- canonical TSS and mandatory transcript/gene lineage sidecar paths, byte
  hashes/sizes, ordered TSS digest, TSS count, and exclusion summary;
- a domain-specific resource identity covering these semantics.

Every parent contig appears exactly once, in FAI order and with its exact
length. Classes are `primary_nuclear_qc`, `mitochondrial`, and `other`, with at
least one primary QC contig. Classification and its provenance identifier must
be supplied explicitly. No names, prefixes, regexes, lengths, aliases, assembly
guessing, liftOver, or annotation-driven classification is used. No hg19,
GRCh37, mm39, or GRCm39 support exists.

Resource identities hash canonical JSON prefixed by
`agent.qc-reference-identity.v1\0`, excluding the identity field and the four
resource locator paths. Byte hashes remain bound, including the exact parent
manifest hash. Relocating QC sidecars alone preserves identity; changing the
parent manifest bytes does not.

### Annotation construction

`protein-coding-all-transcript-tss.v1` selects all annotated transcript TSSs
whose transcript record declares `gene_type=protein_coding`. It does not filter
on transcript type or choose a longest transcript. Gene IDs must have consistent
contig, strand, and coding eligibility across transcript records; transcript
IDs are globally unique. The GENCODE transcript record's gene annotation is the
eligibility authority; other feature types do not supply or repair missing
transcript identities. Full source bytes, including other features, are bound.

For 1-based closed GTF coordinates `[a,b]`, pysam decodes `[a-1,b)`; plus-strand
TSS is `a-1`, minus-strand TSS is `b-1`. Invalid strand/coordinates, unknown
contigs, and out-of-reference transcript ends fail. They are not construction
exclusions. Documented mutually exclusive exclusions are counted in this order:
non-protein-coding, outside QC contigs, incomplete ±2 kb window. Eligible rows
are deduplicated by `(contig,p,strand)`; opposite strands remain distinct.

Canonical TSS is UTF-8, LF-terminated, headerless four-column tabular data:
`contig\tp\tp+1\tstrand\n`, sorted by exact FAI rank, numeric position, then
strand (`+` before `-`). This is an internal BED-like TSS resource: column 4 is
strand, **not** a BED6 strand field. The future window projection supplies
explicit TSS/window identities to BEDTools. No BEDTools strand option is used.
The ordered digest is SHA-256 of `agent.qc-ordered-tss.v1\0` followed by those
exact bytes. Empty resources are rejected. Lineage has five columns
`contig,p,strand,gene_id,transcript_id`, sorted by FAI rank, position, strand,
gene, transcript. It retains every eligible transcript. Its independent hash
binds lineage into the bundle identity without duplicating TSS incidence.

### Mature parser and qualification policy

The installed pysam 0.24.1 `asGTF` and `GTFProxy.attribute_string2iterator`
provide coordinate and attribute parsing. No generic GTF/GFF parser is added.
The explicitly selected narrow profile is
`pysam-0.24.1-gencode-transcript-gtf.v1`: plain UTF-8 GTF, transcript rows with
one each of `gene_id`, `transcript_id`, and `gene_type`; repeated `tag` is legal.
Attribute acceptance is narrower than all GTF dialects: ASCII identifier keys,
quoted string values or unquoted integer metadata, `key value;` entries
separated by one ASCII space (outer spaces allowed). String values may contain
spaces but not embedded quotes, escapes, semicolons, or control characters.
After pysam decoding, exact re-encoding must match the source attributes; this
rejects permissive repairs such as unterminated quotes, unquoted strings, and
missing terminators. All non-comment feature rows receive this syntax check;
only transcript rows contribute scientific identities. Pysam remains the
coordinate/attribute decoder; the round-trip guard is not a generic GTF parser.
The pinned runtime record `_qc_gtf_toolchain.json` binds 17 installed package
files (extensions, version/init files, bundled libraries) and the resolved
linked-library identities of the three relevant extensions. Its SHA-256 is
also bound in the annotation record. Qualification runs in the existing agent
Python 3.11 environment; other installed builds fail rather than auto-install.

The separate `synthetic-transcript-tsv.v1` parser accepts seven strict fixture
columns: zero-based `contig,start,end,strand,gene,transcript,biotype`. It is not
a GTF substitute and always records `synthetic_only`. GTF resources record
`source_declared_not_production_qualified`, with source exactly `GENCODE` and
an explicit release. Neither state claims authenticated source provenance.
Canonical production qualification requires an independently documented source
release/checksum, assembly compatibility, accepted parent bundle, explicit
authoritative classification, and successful source reconstruction. No
canonical production resource has been qualified in M11.4a; the API cannot
self-promote a source declaration into that claim.

The construction call makes those choices explicit (paths below are placeholders,
not defaults):

```python
from agent.tools.data.scatac_qc_reference import (
    GTF_PROFILE, QCContig, build_scatac_qc_reference_bundle,
)

bundle = build_scatac_qc_reference_bundle(
    parent_manifest_path=parent_path,
    parent_manifest_sha256=parent_sha256,
    annotation_path=annotation_path,
    annotation_source="GENCODE",
    annotation_release=reviewed_release,
    parser_profile=GTF_PROFILE,
    classifications=reviewed_contigs,  # tuple[QCContig, ...], complete FAI order
    classification_source=classification_provenance_id,
    output_dir=new_resource_directory,
)
```

### APIs, independent validation, and bounds

Public data-layer APIs in `scatac_qc_reference.py` are
`build_scatac_qc_reference_bundle`, `validate_scatac_qc_reference_bundle`,
`canonical_qc_reference_bundle_bytes`, `load_scatac_qc_reference_bundle`,
`publish_scatac_qc_reference_bundle`,
`reinspect_scatac_qc_reference_bundle_sources`, `iter_canonical_tss_records`,
and `ordered_tss_sha256`.

Validation is closed and IO-free. Loading performs bounded manifest-only IO
with duplicate-key and nonfinite JSON rejection. Reinspection separately checks
parent compatibility, exact resource bytes, annotation identity, and scientific
derivation. It revalidates the parent sources and uses independent SQLite
extraction/grouping/order/count queries; it never calls the builder or trusts
its summary. Shared parsing is syntax only. False self-consistent TSS, lineage,
or exclusion claims fail reconstruction. This verifies reproducible derivation,
not authenticity of biological source declarations.

`ScATACQCError.code` distinguishes contract/manifest errors, parent mismatch,
resource mismatch, derivation mismatch, changed sources, unqualified parser or
BEDTools, resource limits, and publication conflicts. No automatic source repair,
alternate parser/backend, or downgraded verification follows an error.

Construction uses disk-backed SQLite sorting. Reinspection uses a separate
temporary database. Bounds are 1 MiB manifest, 4,096 bytes per source/sidecar
row, 4,096 contigs, 1,000,000 distinct TSSs, 5,000,000 transcript rows, and 2 GiB
per annotation/tabular sidecar. SQLite cache is 8 MiB with file-backed temporary
storage. The manifest contains no per-TSS objects. No fragment matrix or
cell-by-TSS matrix is allocated. Bounds may reject future larger annotations;
they are explicit profile prerequisites, not silently relaxed limits.

The builder verifies staged outputs before publishing a new directory and
fsyncs files/directories; it refuses an existing destination. Manifest-only
publication likewise refuses overwrite. This is resource publication, not a
durable scientific-run recovery protocol. Stronger hostile-filesystem-race
hardening remains outside this milestone, consistent with M11.1.

## Qualified interval backend

Local executable `/usr/bin/bedtools`, version `bedtools v2.30.0`, SHA-256
`770cdb969bd7dea9ceb34925753601f9871514247cf436ee101c513e4611f77c`
is qualified only for `intersect -sorted -g GENOME -a INSERTIONS -b WINDOWS -wa -wb`.
`_qc_bedtools_toolchain.json` pins all eight resolved linked-library hashes.
The runtime helper requires an explicit absolute executable, validates bytes
before execution, checks version and libraries, and rechecks executable state.
There is no PATH fallback or planner-selected executable. Its fixed environment
is `LC_ALL=C`, `PATH=/usr/bin:/bin`; caller LD/Python environment settings are
not propagated to BEDTools. A future execution adapter must use this environment.

Both inputs must be sorted by exact FAI rank and start coordinate; ties retain
deterministic explicit endpoint/window identities. The genome file must be the
bound FAI's two-column names/lengths. Sorted fragments do **not** imply sorted
endpoints: endpoint projection needs its own sort. Every overlap row is retained,
including coincident insertions and opposite-strand TSS windows. Narrow tests
qualify half-open boundaries, all center/flank edges and gaps, multiple windows,
nonlexical FAI order, malformed/unknown/unsorted rejection, deterministic output,
empty intersections, and executable/library mismatches. No arbitrary BEDTools
subcommand is exposed.

Future production: validated fragment endpoint stream plus canonical windows →
qualified BEDTools → narrow exact integer aggregation. Future independent
verification: separately reconstructed endpoints plus sorted TSS positions →
repository-controlled point/window counting, potentially binary search. It must
not reuse production BEDTools results or introduce a generic interval engine.
Neither metric path is implemented by M11.4a. Generic v2 verification also does
not replace producer qualification, and the existing v2 reader retains an
all-barcode set; no constant-memory full QC pipeline is claimed here.

## Scope exclusions

No per-barcode QC tool, cell selection, default thresholds, true cell calling,
doublet inference, peak calling, true FRiP, cCRE-overlap QC, or blacklist metric
is implemented. M11.5 owns cCRE projection; any later overlap scalar needs a
distinct name and should reuse that overlap pass. Planner, compiler, PLAN_ONLY,
registry, execution, and existing scientific backends are unchanged.

## Public API and semantic composition

```python
from agent.tools.data.scatac_matrix import build_scATAC_cell_by_ccre

result = build_scATAC_cell_by_ccre(
    fragments_manifest_path="/absolute/fragments/manifest.json",
    fragments_manifest_sha256="<exact SHA-256>",
    selected_cells_manifest_path="/absolute/selection/manifest.json",
    selected_cells_manifest_sha256="<exact SHA-256>",
    reference_manifest_path="/absolute/reference.json",
    reference_manifest_sha256="<exact SHA-256>",
    output_dir="/absolute/managed/output",
)
```

All seven bindings are required. Paths must be canonical absolute paths and
hashes lowercase 64-character SHA-256 strings. The Application supplies managed
output through the existing output policy. There is no overwrite option and no
caller-selectable overlap, support, count mode, dtype, filtering or ordering knob.
`AGENT_MATRIX_BEDTOOLS` explicitly selects the existing qualified M11.5 BEDTools
runtime; no PATH discovery or silent fallback occurs. Existing QC runtime,
synthetic gate, resource catalog and producer qualification requirements still apply.

| Consumer port | Binding | Permitted upstream semantic type |
| --- | --- | --- |
| `fragments` | `fragments_manifest_path` + `_sha256` | `scatac_fragments.v2` |
| `selected_cells` | `selected_cells_manifest_path` + `_sha256` | `scatac_cell_selection.v1` |
| `reference` | `reference_manifest_path` + `_sha256` | Request-only exact reference |
| `output_dir` | Managed destination | Existing managed-output binding |

The `matrix` output port exposes manifest path/hash as `scatac_cell_by_ccre.v1`;
`dataset` exposes `matrix_path` as `scatac_matrix_h5ad.v1`. The latter connects to
the existing feature-space validator's `input_path` port. All three fragment
producer routes use the same v2 semantic channel; no producer/species routing is
introduced in matrix execution.

```text
raw input → verified fragments-v2 → QC → explicit selection-v1
                     │                         │
                     └──────────┬──────────────┘
                      exact shared reference
                                │
                    build_scATAC_cell_by_ccre
                                │
                verified full ordered matrix.h5ad
```

Existing artifacts and same-plan outputs are both supported. The generic compiler
expands paired semantic sources into exact path/hash `StepOutputRef` bindings and
induced dependencies. It retains fail-closed ambiguity and incompatible-channel
rules. No compiler algorithm, natural-language heuristic, default-planner routing,
provider adapter or execution engine is added. Scripted v3/v4 provider acceptance
proves the interface and execution DAG; it does not establish live-model planning
quality. EpiZoo is never an automatic dependency.

The complete catalog retains all tools and meanings within existing byte ceilings.
Prompt-only phrase legends share exact repeated text; a collision-free marker and
single-pass expansion preserve every original catalog value. Tests independently
expand actual v3/v4 prompts back to the public catalog. Request values are not
included in this transformation. V3 shares dependency/description schemas and
prunes unreachable definitions; fixed enum values imply their types. V4 shares the
control-dependency array schema. Accepted wire payloads and strict parsers remain
unchanged. These size changes are required by adding tool eighteen; budgets are
not raised. The standard full-catalog fixture measures v3 at 22,315 prompt +
15,480 schema = 37,795 bytes, and v4 at 18,977 prompt + 11,460 schema =
30,437 bytes.

## Bounded results, preflight and publication

`CellByCCREResult` returns status, artifact type/version, manifest path/physical
SHA, artifact logical identity, H5AD path/physical SHA, sparse logical matrix SHA,
species/assembly, cells/features/nnz/total count/zero-row count, frozen
semantics/profile, ordered selected and feature SHAs, readiness and the established
overlap diagnostic. There are no row/column lists or unbounded source manifests.
IO-free result validation checks closed fields, exact types, digests, profile,
species/assembly compatibility and count/diagnostic consistency.

PLAN_ONLY validates bindings and semantic structure without reading fragments,
reference or H5AD payloads, creating scientific scratch/H5AD, or launching BEDTools.
Execution performs fresh accepted upstream/schema/qualification/lineage binding
inside the unchanged constructor before projections, intersection or H5AD writes.
No declared species/assembly can override the exact reference. Invalid hashes,
unsupported contracts, mixed reference lineage, missing runtime and output conflicts
fail closed. The wrapper may allocate its private envelope directory before fresh
source verification; failure removes it. It does not duplicate scientific preflight
or independently invent acceptance rules.

Policy `build-scatac-cell-by-ccre-v1` hashes canonical exact arguments, the durable
execution identity and frozen matrix profile into a deterministic publication token.
The managed output contains:

```text
cell-by-ccre-<token>/
    receipt.json
    artifact/
        manifest.json
        matrix.h5ad
```

The outer envelope is lifecycle metadata. The inner matrix remains exactly the
frozen two-file M11.5b artifact, with no second scientific representation. A flock
lease serializes cooperating publishers. Construction and complete independent
verification happen in private work; the receipt and directories are fsynced before
atomic envelope rename. Existing destinations are immutable and fail closed.
The receipt binds policy, token, exact argument digest, manifest SHA and profile.
Artifact logical identity, matrix logical identity and physical manifest/H5AD
identities remain distinct.

## Recovery, cancellation and failures

Recovery finds the exact execution publication, checks the receipt and bounded
summary, and calls the accepted independent verifier. It never calls production,
rebuilds H5AD, or changes scientific settings. The existing runtime also freshly
verifies step results and evidence. Those boundaries reverify upstream authorities
and independently reconstruct matrix science using the existing interval tree and
disk aggregation. They can incur substantial IO and verification scratch; recovery
is not described as a receipt-only or constant-cost operation.

Cooperative cancellation uses the existing callback/checkpoint protocol. Accepted
production polling terminates active intersection processes (kill escalation if
needed); construction and verification checkpoints stop work and remove private
scratch. Cancellation before outer rename publishes no partial success. There is
no cancellation checkpoint after immutable publication. Existing runtime terminal
arbitration preserves a successfully checkpointed matrix if cancellation then wins
the run; downstream work stops. No global lifecycle semantics are changed.

The tool enables no scientific automatic retry codes. Matrix, upstream contract,
qualification and resource errors retain bounded sanitized codes/categories;
scientific failures are not blindly retried. Recovery rejects changed source,
receipt/policy/argument bindings or H5AD bytes. Hard process death may leave private
attempt directories for operator cleanup; it cannot expose them as published
success. Published receipts can recover a crash before the success checkpoint.

## Evidence, reporting and downstream use

Fresh verified evidence records bounded matrix facts and upstream physical/logical
identities, with separately digest-bound manifest and H5AD artifacts. Figureless
reports describe the full ordered canonical fragment-record count matrix,
species/assembly, selected cells, reference features, nnz, zero rows, readiness and
the selected-record overlap diagnostic. This diagnostic is not FRiP. Reports do not
claim unique molecules, automatic cell calling, support weighting, binary counts,
training equivalence, model readiness or completed inference.

A nonempty valid matrix enters `validate_scATAC_feature_space` unchanged using the
existing explicit request parameters below. The compiler binds the H5AD output;
these established downstream declarations remain explicit, without a new matrix
construction parameter or automatic downstream step:

```text
matrix_source = X
matrix_semantics = fragment_counts
coordinate_source = var_columns
feature_chrom_key = chrom
feature_start_key = start
feature_end_key = end
coordinate_system = zero_based_half_open
semantics_metadata_key = matrix_semantics
species / genome_assembly = exact reference species / assembly
```

Empty `(0,n_ccre)` outputs are successful M11.5 artifacts and produce evidence and
reports with `no_selected_cells`. The existing feature-space validator independently
rejects empty input. Selected zero rows and all zero columns remain present in the
public output and downstream handoff. Human and mouse use identical construction,
verification, wrapper, registry and reporting logic with different reference instances.

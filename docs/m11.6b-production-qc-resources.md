### Affected resource paths and safety

`MAX_SIDECAR_BYTES` had exactly two executable uses, both in
`src/agent/tools/data/scatac_qc_reference.py`: `_resource` metadata validation
and `_file` physical inspection. Their call paths were:

| Path | Resource and effect |
| --- | --- |
| Closed bundle validator | Parent manifest, annotation, TSS and lineage all used the same 2 GiB guard |
| Builder `_file` calls | Parent manifest, source annotation, staged TSS and staged lineage |
| Source reinspection | All four resources freshly hashed and compared before independent reconstruction |
| Manifest load/canonicalization/publication | Reuse the closed validator; no separate annotation size representation |
| Barcode-QC binding/verifier/recovery | Load and independently reinspect the bundle through these same APIs |
| Selection/matrix lineage verification | Reuse existing upstream QC verification; no separate annotation size cast |

`_qc_gtf.gencode_transcripts` receives one bounded line from `_lines`, decodes
it through the pinned pysam `asGTF`, validates exact attribute round trips, and
yields transcript tuples. It never loads or seeks within the complete annotation.
The installed `libctabix.pxd` declares the parser buffer length as C `int`; this
is the **line length**, bounded by 4,096 bytes, never the total source size.
No tabix index or htslib whole-file offset is used for this plain GTF route.
No signed/unsigned 32-bit total-file-size conversion was found in the audited
Python call chain. The 64-bit agent Python 3.11.16/stat APIs represent the exact
3,323,462,848 size. SQLite 3.53.4 integer binding round-tripped that value; source
size itself is not inserted into the transcript tables. Coordinates remain under
the frozen signed-64-bit validation and unchanged assembly dimensions.

`scatac_reference._file_hash` reads 8 MiB chunks. `_snapshot` retains Python
stat integers, including size and nanosecond timestamps. QC binding's fragment
snapshot helpers likewise retain full stat values. Python JSON preserves the
integer exactly, with strict type checks rejecting booleans/floats/strings.
Manifest identity binds resource sizes/hashes and excludes only locators; the
identity algorithm is unchanged. QC manifests remain bounded at 1 MiB, and the
parent manifest loader independently enforces its stricter 64 KiB bound.
Catalog IO remains bounded at 64 KiB and contains hashes, not source payloads.

Builder and independent reconstruction use disk-backed SQLite, an 8 MiB page
cache and `temp_store=FILE`, with streamed output/hash accumulation. Their tables
contain bounded transcript tuples rather than complete GTF rows. The source has
507,365 transcripts versus the unchanged 5,000,000 ceiling. Its TSS count cannot
exceed that transcript count, below the unchanged 1,000,000 ceiling. At most five
source-derived fields per lineage record, each bounded by the measured source
row length, give a conservative output upper bound below 2 GiB for this input;
actual output sizes remain subject to the original guard. Neither TSS nor lineage
needs a larger limit. The unchanged 4,096-byte row guard also remains sufficient.
Publication still independently verifies the complete private stage, checks source
snapshots, fsyncs and atomically renames. Recovery still reuses fresh verification;
no source copying into receipts or whole-annotation serialization was introduced.

acceptance of arbitrary larger annotations: every existing scientific and

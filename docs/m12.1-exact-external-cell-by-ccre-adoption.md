## Exact input contract

`adopt_scATAC_cell_by_ccre` requires all eight arguments, with no defaults:

```python
adopt_scATAC_cell_by_ccre(
    source_path, source_sha256,
    reference_manifest_path, reference_manifest_sha256,
    species, assembly, matrix_semantics, output_dir,
) -> AdoptedCellByCCREResult
```

Paths are absolute; SHA-256 bindings are lowercase 64-character hex. Species and
assembly must be `human/hg38` or `mouse/mm10`, matching the exact hash-bound
`scatac-reference-bundle.v1`. Existing reference APIs freshly reconstruct the
reference identity and resource identities. Feature names must match **every**
reference BED row as `chrom:start-end`, in exactly that order. Optional direct
`var` coordinate datasets must also match exactly. No sorting, filtering, alias
normalization, liftOver, missing/extra feature repair or retained-only adoption
occurs. Production use must supply the full accepted production reference
(1,355,445 hg38 or 1,341,077 mm10 features); tiny reference fixtures establish
software correctness only. A species label or matching dimension alone never
authenticates a production vocabulary.

The H5AD contract is deliberately narrower than general AnnData:

- Root AnnData encoding `0.1.0`, with `.X` as CSR encoding `0.1.0`.
- `.X.data` is signed 64-bit integer. Index/offset arrays are integer arrays;
  bounds, lengths and monotonic offsets are checked before use. Each row has
  strictly increasing unique columns. Stored values are positive; implicit zeros
  are preserved. Explicit zeros, duplicate entries, malformed CSR, negative values
  and entry/row/whole-matrix int64 overflow fail. Floats (including integral
  floats), boolean, unsigned value arrays, CSC and dense matrices are unsupported.
- `obs` contains only its string index, using dataframe encoding `0.2.0` and
  string-array encoding `0.2.0`. Cell IDs are unique nonempty UTF-8 strings, at
  most 4,096 encoded bytes each, with no leading/trailing whitespace or ASCII
  controls. Exact input row order is retained. Empty input and zero rows are legal.
- `var` contains only its string index, optionally followed by direct datasets
  `chrom`, `start`, `end` in that order. Coordinates are integer datasets; `chrom`
  is a string dataset, not a categorical group. Extra obs/var annotations are
  rejected rather than silently discarded.
- `uns` may be absent/empty or contain a subset of `species`, `assembly`,
  `matrix_semantics`, `reference_identity_sha256` as scalar strings. Present
  declarations must agree with the explicit bindings. Other metadata is rejected.
- `layers`, `obsm`, `obsp`, `varm`, `varp` may be absent or empty. `raw`, alternate
  matrices, other root content, indirect HDF5 storage, links/aliases/cycles and
  virtual datasets are rejected. Tree depth and object counts are bounded.

The source values must explicitly be declared `fragment_counts`,
`insertion_counts` or `binary_accessibility`. Binary semantics require all stored
values to equal one. These are **external declarations**, not proof of the
historical counting algorithm. No values are rounded, coalesced or recomputed.
The initial int64-only decision reuses the existing strict matrix reader and
avoids a new floating conversion path.

Existing `MatrixLimits` bound axes (2 million features, 10 million cells), scratch
(100 GiB) and elapsed work (24 hours). Source physical size is also capped at the
scratch byte ceiling. These are failure bounds, never truncation settings.
Reads/writes are chunked or at most one full sparse feature-width row; no complete
matrix is loaded or densified. Cell uniqueness uses private SQLite storage.

## Artifact and truthful provenance

The existing artifact family `agent.scatac-cell-by-ccre` gains the separate closed
contract `scatac-cell-by-ccre.external.v1` with profile
`exact-external-cell-by-ccre-adoption.v1`. The original fragment-derived v1
validator, serialization, science profile and logical digest encoding remain
unchanged. The common loader/owner explicitly dispatches by supported contract.

A publication contains `artifact/manifest.json`, `artifact/matrix.h5ad` and the
existing outer matrix receipt. The manifest records external adoption, source
path/SHA/size, exact reference binding, species/assembly, declared semantics,
shape, bounded summaries, ordered cell/feature identities, source/output logical
identities, physical output identity and `matrix_available`/`no_source_cells`.

A distinct logical digest domain binds shape, int64 dtype and the declared
semantics, followed by the ordered sparse rows and values. A separate length-
prefixed UTF-8 digest binds source cells. These never borrow the M11.5 digest's
hardcoded fragment-count meaning or selected-cell identity encoding.

The canonical output contains int64 CSR, only ordered cell and feature index
axes, and the four corroborating `uns` declarations above. Integer index storage
and permitted coordinate representation are normalized; scientific values and
axis identities do not change. No fragment, QC, selection, barcode namespace,
canonical-record overlap diagnostic or model-readiness provenance is fabricated.
In particular, adoption does not claim
`canonical-fragment-record-overlap-counts.v1`, statistical cell calling, singlet
purity or biological preprocessing qualification.

## Verification and authority

`cell_by_ccre_verifier.verify_cell_by_ccre(manifest_path,
expected_sha256=..., bedtools_path=None, limits=MatrixLimits(),
scratch_parent=None)` remains the matrix-owner entry point. External adoption
needs no BEDTools runtime. Fragment-derived verification still requires its
qualified runtime and independently reconstructed fragment counts.

The external verifier does not invoke the adoption writer. It freshly binds and
hashes the source/output, reconstructs reference identity, checks complete axes
and strict storage, then reads each source CSR row directly and compares every
column index/value to the published row. Cell rows are independently compared
against a disk-backed source identity table. Both logical identities and all
summaries must agree. File snapshots protect the operation against changes.
A rehashed 2×2 value redistribution preserving both marginals, totals and nnz
fails even when the manifest's source/output logical digest declarations are
also forged.

The existing `matrix` scientific owner and schema-2 authority carry this proof;
there is no second owner or authority type. The explicit external profile and
verifier compatibility identity prevent substitution with fragment-derived proof.
The source is historical verified provenance after accepted execution. Ordinary
Application evidence/report/resume checks still hash current artifacts/resources
but can reuse compatible proof without opening the original source. Explicit
`current_source_freshness.v1` requires current source bytes. Standalone and
nonterminal recovery verification remain deep and require the source.

## Agent integration and lifecycle

The registry has nineteen tools. The new tool has request-only source/reference
path+SHA bundles and explicit species/assembly/semantics ports. It publishes an
external matrix manifest port and the existing `scatac_matrix_h5ad.v1` dataset
port, permitting explicit existing downstream operations. The compiler adds no
workflow inference or automatic steps; neither embedding nor feature validation
is run implicitly. PLAN_ONLY performs no scientific IO.

Policy `adopt-scatac-cell-by-ccre-v1` binds exact arguments, execution identity
and profile. Adoption reuses the matrix lease, private attempt directory,
receipt, fsync and atomic rename envelope extracted from existing publication.
Cancellation cleans private work; no checkpoint is added after final publication.
A valid receipt recovers a completed publication without rerunning adoption.
Successful durable steps persist ordinary matrix authority. Terminal Application
resume reuses it with current artifact/presentation checks.

Evidence/report facts are whitelisted lightweight summaries with source and
reference digests; no source cell table is embedded. Deterministic figureless
wording distinguishes declared values and exact conservation from unestablished
historical biology.

Complete catalog byte ceilings are retained. V3 shares its repeated closed step
envelope through a JSON Schema `$ref` with specializing property siblings;
required fields and unknown-field rejection are unchanged. V4 removes enum-redundant
types and shortens one internal definition reference; its accepted payloads
and kind discriminator remain unchanged. V3/v4 prompt phrase
sharing also handles repeated underscore-separated strings and single words,
with collision-free, one-pass lossless expansion. The public catalog, executable
payloads and semantic compiler rules are unchanged. Scripted wire tests and
schema checks do not claim live hosted-provider qualification.

# M13.3 generic marker candidate scientific component

M13.3 freezes a private scientific component, `annotate_cell_groups` in
`src/agent/tools/analysis/marker_annotation.py`. It adds no registered tool,
Planner/compiler, Application, evidence/report, verification authority or recovery
integration. M13.2 remains the biological qualification; this milestone qualifies
contracts and adapters, not new biological populations.

## Inputs and ownership

The keyword-only API consumes frozen `MatrixInput`, gene/signature `Resource`
descriptors, an exact TSV group mapping and hash, explicit grouping provenance,
an operator `Runtime`, the explicit profile `maestro-enhanced-marker-candidates.v1`,
and a new output directory. Existing output directories fail; no overwrite mode.

`MatrixInput` binds the accepted canonical manifest path/hash, H5AD hash, ordered
cell and feature hashes, species, assembly and value semantics. Only the M11
`scatac-cell-by-ccre.v1` artifact with
`canonical-fragment-record-overlap-counts.v1` is initially supported. External
M12 fragment counts, insertion counts and binary accessibility are unsupported;
no equivalence qualification for those inputs is claimed. Species/assembly are
explicit and must match the canonical contract (human/hg38 or mouse/mm10).

The caller supplies an owner-accepted artifact. The component checks the closed
manifest, current H5AD bytes, dimensions, exact ordered axes, original namespace /
barcode identities, row indices and canonical int64 CSR logical identity. These
checks do not reconstruct fragment/QC/selection science or grant a new authority.
No full matrix is densified. Sparse input is loaded into host memory as required by
MAESTRO; this is not a streaming or universal throughput guarantee.

The canonical matrix is never modified. Only a private sparse copy becomes
float64 nonzero support (`X > 0`) for Enhanced RP. EpiZoo/EpiAgent preprocessing,
TF-IDF, ranking, tokenization and inference remain outside M13 ownership.

Groups are external input, with exactly `cell_id` and `group` TSV columns. Rows
must match every original cell exactly, in original order. Missing, extra,
duplicate or reordered cells fail. Labels are opaque nonempty strings (including
`NA`), with no surrounding whitespace or control characters. The component does
not infer groups or interpret numeric labels. At least two groups and nonempty
cells with positive RP totals are required for one-versus-rest statistics.

## Resource and scientific profile

Both resource descriptors require a local path/content SHA-256, source, revision,
species, assembly, explicit context (including an explicit unspecified context
where necessary), gene namespace, normalization and semantics. These declarations
are recorded, not inferred or certified as biological authority. No remote fetch,
resource-name dispatch or automatic substitution exists.

Gene resources use `maestro-refgenes-transcripts-exons.v1`, normalization `none`:
MAESTRO-compatible transcript `name`, gene `name2`, chromosome, strand, txStart,
txEnd, exonStarts and exonEnds tabular semantics. Resource revision describes the
actual supplied annotation, not the separate M11 QC GENCODE resource. Signatures
use `candidate-gene-list.v1`, normalization `uppercase`, with exactly `candidate`
and `gene` TSV columns. Candidate vocabulary/order is the first occurrence of
explicit candidate labels; no tissue vocabulary is built in. Namespaces must
match. RP gene uppercasing collisions fail. Signature duplicates retain the
original list weighting and denominator and are disclosed. Each signature needs
at least two entries for a defined log2 denominator; this is not a biological
support threshold. Missing RP genes and measured genes absent from retained
markers are reported separately, never interpreted as validated negative markers.

The frozen method is the M13.2 route:

- MAESTRO Enhanced RP, decay 10,000, full supplied canonical feature axis.
- Sparse `log1p(RP / cell_RP_sum * 10000)` normalization.
- Native Presto one-versus-rest Wilcoxon/AUC statistics, one thread; original
  MAESTRO logFC and filtering. Raw p < 0.01, absolute natural-log fold change >
  0.25, rounded expressed fraction in either population > 0.1; then adjusted
  p < 1e-5. No additional minimum-group or support-gene threshold is introduced.
- Candidate score = signed sum of matched retained marker effects, including
  duplicate signature entries, divided by log2(original signature entry count).
  Scores are native evidence values, not probabilities.

## Upstream integration and runtime

MAESTRO revision `74f10babf4125b98ef005df4186b14ab02e13bfd`, package 1.5.1,
declares GPL >= 3 (GPL-3.0-or-later). The locally retained DESCRIPTION/LICENSE and
source manifest were inspected before implementation. No upstream algorithm
source is vendored or modified. Operators supply the local pinned source slice;
the two executed files have fixed hashes in the component. Python loads only
original function AST nodes from `MAESTRO/scATAC_Genescore.py`; original Enhanced
RP/transcript/exon formulas execute unchanged. The adapted writer captures sparse
float64 values and full identities, bypassing upstream lossy numeric/fixed-width
serialization. Region syntax conversion is reversible.

Repository-controlled R glue sources hash-pinned `R/FindAllMarkersMAESTRO.R`.
Only Seurat data access is replaced with the explicit sparse RP matrix and groups;
`FindAllMarkersPresto` and native Presto execute unchanged. Candidate scoring is
the small explicit list-weighted formula qualified in M13.2, with no new biology.

The qualified R runtime is R 4.6.1, Matrix 1.7-6, dplyr 1.2.1, Presto 1.1.0;
the adapter checks these versions. M13.2 provisioned Presto from revision
`2e9764fcd986d3be7c0ce1dcdf632fc623cd771e`. This avoids installing MAESTRO's
older broad Seurat/DESeq2 dependency stack. Python uses AnnData, NumPy, SciPy and
pandas. Runtime paths are explicit operator configuration; versions, session
information, source/adapter hashes and R executable hash are retained. Supplied
runtime installations are trusted local dependencies, not a sandbox or new
runtime qualification framework. No user/planner-supplied code is accepted.

## Result, ambiguity and future boundaries

The result manifest is `agent.group-marker-candidates.v1`; its explicit method,
inputs, resources and hashed sidecars describe this private scientific result.
It is not a public artifact/recovery or annotated-H5AD contract.

`groups.json` contains group size, candidate, native top score, exact tied top
vocabulary, status, reason, null accepted identity and validation `not_assessed`.
No matched signature entries yields `insufficient_evidence`; matched evidence
with nonpositive maximum yields `unresolved`; an exact positive top tie yields
`ambiguous`. A unique positive maximum yields only `candidate`, however weak or
sparse its support. All accepted identities are null. There is no first-match
selection, score cutoff, lineage exception or hidden validation.

`cells.json` preserves exact canonical order and contains only cell/group,
candidate, status and null accepted identity. Large evidence is stored once:
`rp.npz` (cells by genes), `genes.tsv`, native full marker TSV.gz, MAESTRO-filtered
marker TSV, signature-input marker TSV, `candidate_evidence.json` (all competitors,
scores and signed matched markers), and `signature_coverage.json`. `cells.tsv`,
`groups.tsv`, group sizes and runtime details provide identity/provenance support.
Temporary Matrix Market data is removed before publication. Private stages are
cleaned on exceptions, and publication uses a new directory rename. This is not
crash recovery or a durable receipt protocol.

Future annotated H5ADs must be new derivatives preserving canonical X and both
ordered axes exactly; candidate columns must not masquerade as final `cell_type`.
Independent atlas/database/supervised validation will be a separate layer, not
an input to primary scoring. No CellMarker/PanglaoDB access or validator exists.

## Acceptance

Baseline: main at `09b4cabf13c1705e1e7ca84f616139d8324b06ed`, initially clean.
Retained M13.2 REPORT, scripts, profile, resources, RP/marker/score outputs and
grouping provenance were inspected first. Bounded acceptance is retained outside
Git at `/home/likeyi/program/agent-acceptance/m13.3/component-r1/`.

Scoring the retained M13.2 marker outputs reproduces all 336 scores exactly,
all 12 group decisions (renaming `candidate_assigned` to `candidate`), and exact
1,119-cell propagation. All accepted identities are null. The original full PBMC
RP and marker computations were not rerun. A three-region/two-cell upstream RP
check reproduces hand-derived exon and distance weights; a six-cell/two-gene
synthetic full component run executes the pinned RP/R adapters and confirms
canonical byte immutability and opaque labels. These bounded checks establish
adapter equivalence, not expanded biological acceptance.

All 19 focused component tests and 60 existing matrix-contract regression tests pass
(79 passed in 1.19 seconds). The final tiny runtime check also passes. No
full Agent regression, public integration, broad benchmarks or parameter search
was performed. PBMC is qualification evidence, not the supported tissue boundary;
other tissue/species resources need independent biological validation. The next
step is a separately scoped validation/evidence contract defining what could
support or contradict candidates before accepted identities or public integration.

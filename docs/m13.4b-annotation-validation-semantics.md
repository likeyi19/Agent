# M13.4b annotation output and validation semantics closeout

M13.4b closes the private annotation/validation semantics. Primary marker-based
annotation supplies the cell-type label. External databases, supervised models,
atlases and known labels provide optional quality evidence; they do not gate
whether the primary annotation exists. Method validity does not imply perfect
biological accuracy. Agreement does not prove truth; disagreement does not prove
that the primary method is wrong.

Baseline: clean `main`, HEAD `9ae40e6144ef7c6a07be7f5e5b975aefa5005eee`, with the
M13.4 CellMarker work committed. This closeout changes only the two private
components, their focused tests and this document. Historical M13.3/M13.4 contracts
and retained acceptance records remain unchanged. Their earlier acceptance-gate
language describes those checkpoints; this document supersedes that language for
current private outputs. CellMarker's inability to establish biological
contradiction is a scope limitation of corroboration, not a block on annotation.

## Primary output

The route remains canonical cell-by-cCRE → private binary accessibility → MAESTRO
Enhanced RP → group marker statistics → native signature scoring → primary
annotation → exact cell propagation. Scientific parameters, formulas, source
hashes, duplicate weighting, missing-marker coverage and alternatives are
unchanged. No new score, margin or supporting-gene threshold is introduced.

Group and cell rows retain `candidate`, the native selected identity, and now use
`primary_annotation` in place of the misleading `accepted_identity`. Group/cell
`status` describes the primary method:

| Native result | Status | Primary annotation |
| --- | --- | --- |
| Unique positive usable maximum | `assigned` | Native selected identity |
| No usable signature evidence | `insufficient_evidence` | null |
| Nonpositive maximum with evidence | `unresolved` | null |
| Exact positive top tie | `ambiguous` | null |

There is no first-match tie selection. Sparse but unique positive support still
assigns a primary annotation; the actual supporting genes/counts and all competing
scores remain available. Reliability evidence is separate from label existence.
Both identities are null in unassigned cases; `top_candidates` and complete
candidate evidence retain mathematical ties and alternatives.

Validation is not an argument to primary scoring. Primary group records retain
`validation_state=not_assessed`, describing evaluation at primary production time.
Later corroboration does not rewrite that historical record. Per-cell rows copy
the group's primary annotation and status in exact original canonical cell order.

## Optional CellMarker corroboration

The private API is now `corroborate_marker_annotation`. Its output distinguishes
`primary_annotation` and `primary_state` from `corroboration_state`:

- `corroborating`: positive compatible associations at the explicit mapped scope.
- `mixed`: competing/nonexclusive associations exist, with or without compatible
  associations. This is not proof of a contradiction.
- `insufficient_evidence`: no positive equivalent/broader association under the
  explicit mapping.
- `unmapped`: no declared alignment.
- `not_applicable`: the primary method has no assigned identity.

All original resource normalization, tissue/species checks, marker intersections,
coverage and source-row references remain unchanged. The old `supported` name
becomes `corroborating`; competing associations previously folded into insufficient
now have an explicit `mixed` state. No positive database membership is turned into
negative-marker evidence or calibrated confidence.

The component reads the primary artifact and returns separate corroboration. It
copies the exact primary annotation into its group result and cannot replace it.
It checks consistency between primary status, candidate and primary annotation;
malformed or historical candidate-only input fails rather than being silently
reinterpreted. Missing resources fail an explicitly requested corroboration call,
but do not erase the already-produced primary output. When no validation is
requested, annotation alone is a complete valid result.

Future supervised validation may report a different prediction, such as CD8 T
against a primary NK annotation. That prediction must remain separate evidence;
it cannot overwrite NK or fill a null primary label. EpiAgent is not executed or
integrated here. No automatic cross-validator adjudication policy is introduced.

## Small private schema migration

New primary publication manifests use `agent.group-marker-annotation.v1`; the
qualified scientific scoring profile stays `maestro-enhanced-marker-candidates.v1`
because its mathematics and parameters did not change. Scorer return structure
still separates groups, cells, candidate evidence and signature coverage.

Corroboration uses profile `external-marker-corroboration.v1` and result schema
`agent.external-marker-corroboration.v1`, with `corroboration_state` and
`corroboration_scope`. The old function name and `accepted_identity` field are
removed; no dual-runtime compatibility or automatic persisted-data migration is
introduced for this private API. Existing pinned cell-type alignment format is
unchanged; mappings for new primary artifacts must bind their new exact hashes.
Historical artifacts and scripts remain historical, without silent upgrades.

## Ownership, future cell output and scope

The canonical matrix remains immutable. M13 owns only its method-private binary
and RP preprocessing; EpiZoo retains all its existing preprocessing/inference;
EpiAgent will own its preprocessing if qualified later. Resource context remains
explicit in the supplied gene/signature descriptors and corroboration mapping.
There are no PBMC, immune-type or group-number branches in either component.

Future annotated H5ADs must be new derivatives, preserving canonical X, cell IDs,
cell order and cCRE identities/order. Their `obs` may carry primary cell type,
annotation status and group identity; exact public column names are deferred.
Large marker and validation evidence remains in group-level sidecars. The labels
are method-derived primary annotations, not candidate-only pending approval.

No ToolRegistry, Planner/compiler, Application, AnalysisEvidence, reporting,
public H5AD publication, recovery or scientific-authority orchestration changes
are made. No additional verification framework is introduced.

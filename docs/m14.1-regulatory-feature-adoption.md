# M14.1 — Neutral regulatory-feature reference and exact external adoption

M14.1 adds a data-layer path for an explicitly declared species/assembly and an
exact external matrix over an ordered regulatory-feature vocabulary. It adds no
ToolRegistry entry, Planner capability, Application projection or raw-processing
route. Existing human/hg38 and mouse/mm10 contracts coexist unchanged.

## Reference

`regulatory_feature_reference.py` defines `RegulatoryFeatureReference`, artifact
`agent.regulatory-feature-reference`, schema 1, contract
`regulatory-feature-reference.v1`. `SpeciesIdentity` contains `scientific_name`
and positive integer NCBI `taxonomy_id`; the pair and `target_assembly` are exact
caller declarations. No taxonomy lookup, assembly inference or biological
source authentication is implied. Operators must supply the intended exact
assembly accession/version and sequence resources.

APIs: `build_regulatory_feature_reference`,
`validate_regulatory_feature_reference`, `load_regulatory_feature_reference`,
`reinspect_regulatory_feature_reference`, `publish_regulatory_feature_reference`.

Construction binds FASTA/FAI bytes and ordered contigs, and reuses the existing
streaming FASTA/FAI sequence-length, offset and line-geometry verifier without
building an alignment index. Its existing ACGTN/acgtn sequence alphabet applies.
The ordered BED retains every caller row. Features use zero-based half-open
coordinates and exact `chrom:start-end` identities. Duplicate coordinates and
out-of-bounds/unknown contigs fail; overlapping intervals are separate columns.
No sorting, merging, alias repair, conversion, clipping, projection or liftOver
occurs. BED columns after the first three remain protected source bytes, not
scientific feature IDs. The 2,000,000-feature matrix bound is retained.

Feature category is explicitly `peak_set`, `curated_ccre` or
`regulatory_regions`. It is a declaration, not independent curation authority.
Existing immutable `SourceProvenance` and resource records are reused. The
ordered vocabulary uses `sha256-utf8-lf.v1`. Portable reference identity includes
species, assembly, category and resource/content/order identities; paths and
historical provenance are excluded from that portable digest, as in the legacy
reference convention. Exact manifest SHA protects those fields. Publication is
atomic, fsynced and no-clobber. Reinspection checks actual resources separately
from bounded manifest parsing.

## Matrix

`regulatory_matrix_adoption.adopt_cell_by_features(...)` accepts source H5AD
path/SHA, reference manifest path/SHA, species as the exact two-field dictionary,
assembly, declared `matrix_semantics`, and output directory. Optional
`execution_identity` binds the existing publication lifecycle.

Output artifact: `agent.scatac-cell-by-features`, schema 1, contract
`scatac-cell-by-features.external.v1`; profile
`exact-external-cell-by-features-adoption.v1`; recovery policy
`adopt-scatac-cell-by-features-v1`.

The path delegates to existing external matrix production and the existing
`matrix` owner / `verify_cell_by_ccre` conservation verifier. A private reference
field adapter bridges neutral `features` to the legacy engine's field spelling;
it neither creates a cCRE reference nor qualifies a peak set as curated cCREs.
The shared receipt/directory envelope retains its historical `cell-by-ccre`
spelling as a storage detail, while artifact/profile/recovery identities are
explicitly neutral and distinct.

Input remains constrained axis-only H5AD with canonical signed-int64 CSR,
nonnegative values, unique sorted indices, no explicit stored zeros, and checked
entry/row/total sums. There is no permissive count conversion or sparse
coalescing. Existing int64 index-storage normalization remains representation
only. Source cell IDs/order, complete feature IDs/order, all values, zero rows
and zero columns are preserved. Zero-cell input is valid. Value declarations
remain distinct: `fragment_counts`, `insertion_counts`, `binary_accessibility`.
Binary stored values must equal one. Source/output logical identity uses the
existing external regulatory sparse digest and includes declared semantics.

Neutral H5AD `uns.species` stores canonical JSON for the exact species object;
legacy H5AD scalar species serialization is unchanged. Optional supplied source
metadata must agree exactly. Source metadata is not required to fabricate
historical assertions; species/reference binding is the explicit adoption
contract. Exact conservation establishes neither raw history, fragment counting,
QC, selection, model readiness nor historical processing correctness.

## Verification, authority and durability

The same matrix owner checks complete source hash, reference resources and
identity, axes and sparse structure, and independently compares every output
entry to source. Rehashed output summaries cannot replace conservation. The
shared private-stage publication verifies before atomic rename, and reuses
receipts, leases, fsync, cancellation and cleanup. `recover_matrix` validates an
exact completed publication without repeating production; standalone recovery
remains deep.

An explicitly owned `VerificationContext` supports one owner proof across stage
publication and subsequent compatible verification. The existing
`scientific_authority.issue(context, 'adopt_cell_by_features', arguments, result,
execution_identity)` can issue a schema-2 record only after that proof and a
matching publication receipt. The new owner name is a data-layer adapter key,
not an executable registry entry. Current artifact/reference integrity is kept
separate from historical external source identity; compatible proof reuse need
not reopen the historical source. Changed artifacts/resources fail closed.

Parsed records, manifests and receipts alone confer no trusted accepted execution.
M14.1 does not introduce a standalone authority-import API or a new trust store.
Persisted RunStore admission and cross-run Application consumption of this new
route await its future registered-tool integration; existing accepted human/mouse
RunStore authority behavior remains unchanged. Without an owned context,
standalone verification performs complete conservation.

## Compatibility and validation

Legacy reference/matrix schema versions, profile specifications and digest
domains remain unchanged. Shared changes are limited to reference publication
mechanics, explicit external-contract dispatch and owner adapters. No scientific
matrix algorithm or existing registered tool signature changes.

Validation uses the `agent` Python environment with `PYTHONPATH=src`, bytecode
disabled and temporary Numba/Matplotlib caches. No biological data or model
training is involved.

- Dedicated neutral reference/adoption suite: **63 passed** (0.80 seconds).
- Initial legacy reference/external-science checks: **169 passed** (0.66 seconds).
- Combined reference, matrix contract, external adoption, matrix integration and
  authority regression: **555 passed, 2 skipped** (514.41 seconds). This run
  collected the first 57 neutral tests; the final dedicated suite includes six
  additional negative/identity tests.
- Full lightweight regression: **4,008 passed, 83 skipped, 7 warnings** in
  **1,312.48 seconds** (exit 0). All `RUN_*` gates are unset;
  discovery is restricted to `tests/`, preserving unrelated untracked `evals/`.
  Its first collection attempt found a duplicate test-module basename; the new
  files were renamed before the complete rerun.

The combined regression command selected `tests/regulatory_features`,
`tests/tools/data/test_scatac_reference.py`,
`tests/tools/data/test_scatac_reference_provisioning.py`,
`tests/tools/data/test_scatac_matrix_contract.py`, `tests/external_matrix`,
`tests/cell_by_ccre`, `tests/matrix_integration`, `tests/authority_dag`,
`tests/chromap/test_verification_authority.py` and
`tests/chromap/test_authority_dag.py`. The final full run used
`python -m pytest -q tests`. Warnings concern existing dependency deprecations,
the unavailable TBB threading layer and duplicate-name negative fixtures.

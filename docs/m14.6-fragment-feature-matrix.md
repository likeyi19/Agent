# M14.6 — External fragments to an ordered regulatory-feature matrix

M14.6 adds a data-layer scientific owner path:
verified external fragments + exact caller-ordered barcodes + an M14.1 neutral
regulatory-feature reference → independently verified raw fragment-count matrix.
It adds no registered tool, Planner metadata, Application projection or EpiZoo
change. The registry remains at 22. Technical acceptance is synthetic, not
biological qualification or model readiness.

## API and contracts

All APIs are under `agent.tools.data`:

- `neutral_fragment_import.import_external_fragments`: the existing external
  adoption arguments, but requiring a `regulatory-feature-reference.v1` reference.
  Optional `execution_identity` uses the existing durable envelope. The registered
  M11 `import_scATAC_fragments` and its durable hooks still require legacy references.
- `explicit_cells.publish_explicit_cells(cells=..., declaration=..., output_dir=...)`:
  publishes `scatac-explicit-cells.v1`. `cells` is an iterable of exact
  `(namespace, barcode)` pairs in caller order. `verify_explicit_cells` verifies
  the declaration artifact and the complete ordered sidecar.
- `fragment_feature_matrix.build_cell_by_features`: accepts
  `fragments_manifest_path/sha256`, `explicit_cells_manifest_path/sha256`,
  `reference_manifest_path/sha256`, `output_dir`, and optional `execution_identity`.
  Operator configuration supplies `AGENT_MATRIX_BEDTOOLS`; it is not a scientific
  parameter. `verify_public_result` and `recover_matrix` share the existing matrix
  receipt/publication lifecycle. Standalone scientific verification uses the
  existing `cell_by_ccre_verifier.verify_cell_by_ccre` owner entry point.

The output is `agent.scatac-cell-by-features`, schema 1, contract
`scatac-cell-by-features.v1`, with recovery policy
`build-scatac-cell-by-features-v1`. It binds exact fragments, explicit cells,
reference, axes, science/runtime profiles, matrix bytes and logical identity.
The shared receipt binds arguments and execution/publication identity; its
historical `cell-by-ccre-.../artifact` directory spelling is a storage detail.
No schema migration is performed.

## External fragments and reference compatibility

`scatac-fragments.v2` is retained. Its reference binding gains a closed neutral
variant: species is the exact `{scientific_name, taxonomy_id}` object and the
binding explicitly carries `contract_version=regulatory-feature-reference.v1`.
Legacy reference bindings retain their original keys, bytes and identities.
Only external adoption can use the neutral variant; FASTQ and BAM cannot.

The accepted `10x-atac-fragments.v1` producer profile and its bytes are unchanged:
consistent five/six columns; plain/gzip/BGZF detected from content; bounded leading
comments; already Tn5-adjusted zero-based half-open intervals; exact corrected
barcode declarations; positive uint64 read-pair support; optional supplied strand.
Canonicalization validates, sorts, serializes, BGZF-compresses and builds TBI.
Duplicate full canonical keys fail. Optional source indexes remain explicit,
hash-bound and functionally verified; output BGZF/TBI verification remains
mandatory. Historical alignment, correction and duplicate determination remain
declared rather than reconstructed.

The generic verifier still proves canonical output integrity. The external owner
separately reparses the entire source and independently proves conservation.
The neutral matrix binder requires both scopes. No source syntax, support meaning,
TBI limit or producer qualification is broadened.

Source and target references must agree exactly in scientific name/taxonomy ID,
assembly, FASTA SHA, FAI SHA, ordered contig identity and count. Both references
retain the fixed zero-based half-open convention and verified resource bounds.
Different feature vocabularies on the same exact genome are allowed; matching
chromosome strings alone is insufficient. No aliases, conversion, clipping,
liftOver, sorting or merging of the caller's features occurs. `peak_set` remains
a declared peak set; it acquires no curated-cCRE authority.

## Explicit cells and counting

QC-selected cells cannot honestly represent this input. The new minimal explicit
artifact contains only the bounded caller declaration, count, ordered identity,
sidecar identity and artifact identity. It claims no QC, thresholds, calling or
biological validity. `cells.tsv.gz` carries contiguous row indices, exact namespace
and barcode, and the existing reversible canonical cell ID. The existing ordered
namespace/barcode digest encoding is reused as an axis identity, not as evidence
of selection. Duplicate pairs and invalid/empty identifiers fail. Empty sets are
valid. Verification checks uniqueness with disk-backed SQLite.

Every requested namespace must exist in the fragment artifact. Every requested
barcode must have at least one canonical source record; completely absent barcodes
fail. Present barcodes with no feature overlap remain valid all-zero rows.
Unrequested barcodes never contribute. Caller cell and feature order remain exact.
All features, including zero columns, remain; the M14.1 vocabulary itself is
nonempty. Empty cells produce shape `(0, full_feature_count)`.

For each canonical record and feature on the same contig, a contribution is one
exactly when `max(fragment_start, feature_start) < min(fragment_end, feature_end)`.
Touching endpoints do not overlap. Overlapping features are independent columns;
a record can contribute to several columns. Support never multiplies values.
Strand is ignored for overlap, while distinct canonical records remain distinct.
There is no binarization, normalization, TF-IDF or weighting.

The old science profile explicitly names cCREs and `selected.tsv.gz`. It is not
reinterpreted. The neutral sibling profile is
`canonical-fragment-record-feature-overlap-counts.v1`, changing only the profile
ID and vocabulary/row-contract descriptions. All overlap, support, accumulation,
overflow and sparse rules remain identical. The underlying BEDTools qualification
profile and logical sparse digest encoding are reused unchanged.

## Shared engine, verification and authority

The existing `_cell_by_ccre_production` algorithm is unchanged: bounded SQLite
cell/feature lookup and record spool, pinned BEDTools incidences, duplicate
incidence rejection and checked unit accumulation. A shared private constructor
selects explicit contract/binder inputs and writes the same canonical signed-int64
CSR representation: sorted unique indices, positive stored values, no stored
zeros and checked entry/row/total sums. The complete matrix is never densified.
Neutral species metadata is canonical JSON, matching M14.1's convention.

The existing independent verifier is unchanged in its overlap reconstruction:
a separate augmented interval tree and disk accumulation reconstruct every value.
It reloads all dependencies and checks every row/column identity and entry, logical
identity, summaries and diagnostics. It consumes no production incidences.
Rehashed matrix summaries and even equal marginals cannot substitute for proof.
Diagnostics use neutral `overlapping_any_feature` names and make no FRiP claim.

The external-fragment owner proves source conservation, the explicit-cell owner
proves only the declaration, and the matrix owner proves fragment-to-feature
counts. Within an explicitly owned `VerificationContext`, publication establishes
one matrix proof; compatible subsequent verification and recovery reuse it while
checking integrity, dependencies, execution and runtime compatibility. Existing
`scientific_authority.issue(context, 'build_cell_by_features', ...)` issues schema-2
authority only after that proof and matching receipt. Neutral fragment adoption
also has a data-layer owner key, `import_external_fragments`. Neither is a registry
entry. Parsed authority records alone cannot confer trusted execution.

M14.6 requires current source/index integrity on matrix reuse, as well as fragment,
cell, reference and matrix integrity. Source/index files are therefore current
matrix dependencies; the external producer retains its separate historical source
record. This narrowly scoped adapter does not change historical-source reuse for
existing M11/M12/M14.1 routes. Mutation invalidates reuse. No historical processing
science is repeated merely to check current file integrity.

The existing staged verification, fsync, atomic rename, no-clobber locks, receipts,
cancellation and recovery envelope are reused. Standalone recovery remains deep
and never reruns production. Context-backed compatible recovery reuses its proof.
Persisted cross-run RunStore admission and public downstream consumption await
the later registered integration, as they did for M14.1; this milestone creates
no new trust store or standalone authority-import mechanism.

## Bounded technical fixture

The fixture declares `Danio rerio` / NCBI 7955, assembly `synthetic-M14.6`, with
one 100-base `chr1` of A bases. This is an artificial reference, not zebrafish
biological evidence. Features in caller order are `[30,40)`, `[0,20)`, `[10,25)`,
`[90,100)` on chr1. Namespace is `lib`; requested row order is `B, A, Z`.

| Barcode | Canonical intervals | Support per record |
| --- | --- | --- |
| A | [0,10), [10,15), [20,30) | 1,000 |
| B | [30,40), [10,20), [50,60) | 1,000 |
| Z | [60,70) | 1,000 |
| unselected | [0,99) | 1,000 |

Expected and produced matrix:

```text
       [30,40) [0,20) [10,25) [90,100)
B          1      1       1        0
A          0      2       2        0
Z          0      0       0        0
```

There are five nonzeros, total count seven, one zero row and one zero column.
Seven requested-cell records include five with any feature overlap. The
independent owner proves all entries before publication. The acceptance checks
schema-2 issuance, atomic published files, one owner reconstruction across
context-backed recovery, and one fresh reconstruction on standalone recovery.
Support/strand regression compares support 1 against uint64 maximum without
changing the logical matrix.

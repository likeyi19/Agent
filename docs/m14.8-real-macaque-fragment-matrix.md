## Project-wide scientific scope

The project owner clarified the default analysis target: canonical primary nuclear
chromosomes, including canonical primary sex chromosomes where present, excluding
mitochondrial, unplaced, unlocalized, alternate/random and other scaffold sequence.
This is species-neutral, not a universal autosomes-plus-X/Y enum. Contig names,
regular expressions, feature occurrence and sequence length do not establish
primary status.

The existing human/mouse QC reference owns an explicit complete ordered FAI
classification (`primary_nuclear_qc`, `mitochondrial`, `other`). Legacy fragment
admission instead admits exact full-FAI contigs; legacy matrix production follows
its explicit reference vocabulary. Those are different boundaries. This milestone
does not reinterpret historical full-reference fragment artifacts as scoped ones,
change existing human/mouse science or migrate their accepted identities.

`primary_contigs.py` projects that established classification model into the
neutral `primary-nuclear-contigs.v1` profile. It accepts the existing `QCContig`
representation, translating only its primary class name to `primary_nuclear` in
the new resource. The scope binds the exact original neutral reference, complete
ordered contig names/lengths/classes, a hash-bound classification review, and
explicit source-only exclusions. These exclusions authorize removal only; they
never establish coordinate equivalence or aliases. Unknown source names without
an explicit classification fail closed. Complete feature vocabulary membership
is checked against the retained set without changing the reference.

For new neutral workflows the default preparation/admission path is
`prepare_primary_fragments` → `import_primary_fragments`. Scope is mandatory on
this path. Historical `import_external_fragments` remains the explicit unscoped
M14.6 contract, and previously accepted resources are not silently upgraded.
Future neutral raw producers should consume the same reference-layer scope;
FASTQ, BAM and arbitrary-species QC are not implemented here.

## Preparation, verification and lineage

`primary_fragment_preparation.py` publishes a separate preparation record, not a
new fragment format or producer profile. It restricts the original decoded stream
to the exact primary set, preserving retained bytes and order, headers, coordinates,
barcodes, support, optional strand and multiplicity. It neither sorts nor repairs
coordinates. It uses existing pinned packaging tools and creates a new BED TBI.
A separate verification pass compares each retained original line directly with
the prepared stream and rejects any extra, missing, changed or reordered record.
The original source and historical index remain immutable resources.

Neutral admission retains `10x-atac-fragments.v1` and `scatac-fragments.v2`.
A closed optional `primary_preparation` resource pointer in the existing adoption
record binds the explicit preparation lineage. Only the neutral adapter admits
this extension; existing legacy arguments, receipts, profile bytes and artifacts
remain unchanged. Producer verification independently qualifies the prepared
source, verifies preparation conservation and requires exact source/index binding.

The matrix binder checks the target reference against that same scope. The existing
independent matrix owner still reconstructs every entry; unit-per-canonical-record
overlap counting and signed-int64 CSR serialization are unchanged. Original source,
historical index, preparation, classification review, scope and derived resources
are live dependencies of scoped authority. Recovery validates their bytes without
repeating stream restriction or matrix reconstruction when accepted authority
remains compatible. Historical external matrix adoption remains scientifically
distinct and receives no fragment-derived authority from a comparison.

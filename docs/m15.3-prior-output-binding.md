# M15.3 — Exact prior-output binding and context-aware planning

Built on the accepted, uncommitted M15.2 working tree at Git HEAD
`6999f437b9ea30941430ddcc3c227bf6f372c852`. No historical eval, biological
acceptance artifact, scientific algorithm, tool interface, or EpiZoo change is
part of this milestone. Review and validation are recorded below; no commit/push.

## API and ownership

`ResearchAgentApplication.sessions.run(..., use_active_context=True,
retain=(...))` opts into structured context. `outputs` explicitly selects new
run outputs; `retain` explicitly selects named outputs from the captured base
revision. Nothing is inherited automatically. For example:

```python
from agent.application import OutputSelection

state = app.sessions.run(
    "analysis", "select-again", request,
    outputs=(OutputSelection("selection", "new_selection", "manifest_path"),),
    retain=("fragments", "qc"),
    use_active_context=True,
    expected_generation=state.generation,
)
```

The request must supply explicit thresholds. An explicit matrix request may also
select `OutputSelection("matrix", "new_matrix", "manifest_path")`. Step identifiers
must match the actual plan; output selection is not inferred from tool names.
The original four-field `AgentRequest` and one-shot application APIs are unchanged.

Session records locate historical acceptance. Scientific RunStore records,
registered semantic contracts, publications, verifier-issued authorities and their
lineage establish executable validity. Navigation never calls the context builder.

## Persisted executable identity

`agent.schemas.prior_output.PriorOutputBinding` pins source run, step, tool,
semantic output port/type, the entire accepted-step digest, publication manifest
digest, authority digest, and actual supported verification mode.
`PriorOutputRef(binding, output_key)` selects a member of that one artifact:

```text
{"$prior_output": {
  "binding": {
    "run_id": ..., "step_id": ..., "tool_name": ...,
    "source_port": ..., "semantic_type": ...,
    "accepted_step_sha256": ..., "manifest_sha256": ...,
    "authority_sha256": ..., "verification_mode": "scientific-authority.v2"
  },
  "output_key": ...
}}
```

The authority digest binds its publication path, exact execution and scope;
complete authority payloads are not copied into plans. The accepted-step hash
uses the existing M15.2 UTF-8 locator encoding, including non-ASCII paths/IDs;
the authority retains its own unchanged hash encoding. Every member embeds the
same immutable binding. Canonical plan serialization includes these identities,
so changing the historical source changes the plan fingerprint. `StepOutputRef`
remains strictly intra-plan. Old plan representations/fingerprints and run schema
3 remain unchanged; decoding the new tagged form is additive.

The trusted source store is the application's configured scientific RunStore.
No provider/store-path argument or filesystem search exists. This milestone does
not introduce arbitrary cross-workspace discovery or a global artifact service.

## Frozen scoped-v4 context

`AnalysisSessions.active_context(session_id, turn_id)` uses the turn's captured
base revision and generation, not the later active pointer. It validates locator
anchors and accepted scientific identities/integrity, deduplicates exact semantic
publications, and builds an immutable `ActivePlanningContext` (at most 32 items).
Opaque local handles are `ctx.0`, `ctx.1`, etc. The private binding table contains
exact persisted identities; the provider projection contains only handle,
semantic type, producer tool, source port and verification mode. User-assigned
output labels, raw source paths, run IDs, digests and authority payloads are absent.

An operation-local context spans the full application planning call, including
repair/failover. Stage A adds only the sorted distinct active artifact types to
capability selection. Stage B adds the bounded enumerated items and a strict
`{"kind":"context","handle":"ctx.N"}` source alternative. Registry-derived
consumer ports still determine compatibility. Unknown/unoffered handles, injected
identity fields and incompatible ports fail closed. With no active context,
existing prompt/schema payloads do not gain any fields. The focused single-QC
selection example measures 1,813 bytes for Stage A, 3,838 bytes for the scoped
Stage B prompt, and 2,156 canonical JSON bytes for its response schema. The
registry remains 23 tools; no full-catalog fallback was introduced. Explicit v3 remains its
existing one-shot contract; contextual selection is a v4 capability.

`compile_semantic_plan` reads only this immutable table and registry contracts.
It has no RunStore access. It lowers the entire selected artifact into typed
member references, including both manifest path and SHA arguments. Scientific
numeric values continue to come from explicit request inputs.

## Consumption, authority and recovery

`prior_outputs.validate_step_references` requires complete compatible consumer
ports, identical bindings for all members, and exact member mappings. Preflight
rechecks terminal successful source execution, accepted source step, registered
output, authority/publication pins, and existing integrity/resource validation.
The registry defers literal validation only for authorized typed artifact inputs;
its ordinary validators run on resolved values. Threshold arguments cannot be
historical references.

`import_plan_sources` imports accepted contexts through the existing
`verification_authority._load_context` and `VerificationContext` machinery.
Conflicting proofs fail closed. Exact anchors remain checked throughout the
operation. The actual executor's `execution_authorities` scope receives the
imported context; argument resolution alone is not treated as authority.
Dependencies recurse only through persisted exact bindings; cycles and chains
over 64 active loads fail closed. No owner reconstruction or production is used
to construct an accepted context. Integrity validation still checks publications,
receipts, resources and scientific compatibility.

Only reusable schema-2 authority is admitted for this new historical binding.
Weak/legacy artifacts fail closed, without implicit qualification or provenance
upgrade. Existing one-shot deep-verification and annotation-specific reuse paths
remain supported. Existing producer qualification, independently verified
upstream identities, and historical-source freshness semantics remain those of
the original authority. Historical acceptance does not assert present-day raw
source freshness. Channels requiring additional explicit semantic role lineage
are rejected; M15.3 does not invent reference/query roles or expand their contracts.

Runtime resume uses the persisted plan, configured store, and reconstructed
accepted authority context. It does not need session metadata, context handles,
conversation history or a Planner. Completed steps reuse applicable authority;
pending steps execute normally under existing durability/recovery policy.

## Explicit multi-run revisions

`SessionTurn.retained_outputs` is an optional additive field. Old session bytes
omit it and remain decodable; empty retention still serializes as before.
Retained locators must exactly belong to the captured base, with names disjoint
from new selections. Revision outputs list new selections plus these explicit
retained locators, each keeping its originating run/step anchor.

Before recording application completion for a composed revision,
`validate_active_outputs` checks the owner-described dependency closure against
the selected active publications. Replacing S1 with S2 while retaining M1 derived
from S1 fails. Selection-only continuation can explicitly retain F1/Q1 and add S2;
matrix continuation can retain F1/Q1 and add S2/M2. There is no automatic matrix
rebuild. Different active publications of one owner kind require future explicit
role support and currently fail closed. Compatibility lives in orchestration and
existing scientific lineage, not session serialization.

The M15.2 atomic ready→revision/activation transaction and generation check remain.
A generation race preserves the successful scientific run and immutable stale
child, without replacing the current active state. A consistency failure leaves
the successful scientific run available without activating an incoherent revision.
Recovery and explicit navigation continue to use metadata only; presentation
completion remains a separate explicit operation.

## Evidence

For plans with historical dependencies only, evidence adds
`provenance.prior_outputs` containing the exact distinct serialized references.
Resolution trace entries identify each consumed member; run step results retain
which new steps executed and their authorities. Evidence checks resolved arguments
against these pinned historical results. Existing evidence/report fingerprints
cover the added provenance. There is no session state in AnalysisEvidence, no
arbitrary new scientific fact projection, and no unmeasured claim that scientific
reconstruction was skipped. The call accounting below establishes the tested
reuse behavior.

from the captured working-tree baseline. M15.3 extends only the session state,
store immutability checks, and session operations for explicit retention/context.

preflight/execution/recovery, accepted-authority loading and evidence gain narrow
integration branches. `tools/data/authority_context.py` changes only the executor

are deliberate fail-closed boundaries: one trusted configured store, schema-2
reuse, bounded context, and no invented multi-publication roles. The authority
loader currently validates the existing source-run context, so an invalid
accepted artifact elsewhere in that source run can also prevent reuse; it does
not search for an alternative historical result.

# M16.1 — Generic accepted scientific evidence access

M16.1 adds a read-only application boundary over existing M15 sessions and
accepted `AnalysisEvidence`. It exposes existing reviewed facts, not scientific
interpretations. No LLM, new scientific computation, persisted projection,
authority, session format, or dialogue state is introduced.

## API

```python
view = app.sessions.evidence(
    session_id,
    revision_id,       # required exact revision, including historical revisions
    output_name,       # exact OutputLocator.name within that revision
    fields=None,       # optional list/tuple of whole top-level evidence fields
)
payload = view.to_dict()
```

There is no implicit latest-result lookup, output-role inference, historical
fallback, artifact discovery, or sidecar access. This is an internal evidence
view, not a ready-made provider prompt. Later context construction remains
responsible for provider visibility and natural-language interpretation.

`DialogueEvidence` contains the requested session/revision/output identity,
captured session generation and active status, an `EvidenceSource`, immutable
`EvidenceFact` records, coverage information, unselected field names, and explicit
trust/completeness limitations. Nested values are frozen; `to_dict()` returns a
fresh JSON-compatible representation.

The source binds the exact output locator and accepted-step digest, source-run
result digest, tool/result contract/recovery identity, evidence digest/schema and
step JSON pointer. It also carries recorded verification check names, optional
recorded authority identity/scope, exact plan dependencies and prior-output
references. Those records are attribution, not newly issued or revalidated
scientific authority. Tools without reusable schema-2 authority remain readable
when their accepted evidence and session completion are present.

## Availability and completeness

- View `available`: the accepted evidence was resolved. Individual requested
  fields may still be unavailable or omitted.
- View `unavailable`: missing, ambiguous, corrupt, changed or over-limit evidence;
  no scientific facts or source binding are returned.
- View `unsupported`: unknown/incompatible evidence, tool or result contract;
  no scientific facts or source binding are returned.
- Fact `available`: the exact stored value, including an explicit null.
- Fact `unavailable`: the requested field is not in this compact accepted summary.
  This does not assert scientific absence.
- Fact `omitted`: a whole field exceeded the reader's size limit. Lists are never
  silently sliced.

The view always declares `accepted_persisted_summary` scope. It never claims to
contain the full scientific result. Annotation's existing `groups_omitted` fact
is also carried in `coverage`, even when callers select other fields. Existing
method, qualification and limitation fields in accepted evidence are copied as
facts; the reader adds no scientific definitions or conclusions.

Limits are 8 MiB for the evidence file, 128 fact/request fields, 16 KiB for a
single fact value and 64 KiB for the serialized view. An oversized whole view
fails closed; callers can request fewer fields. Invalid field-selection syntax
raises `ValueError`. These are access bounds, not scientific truncation settings.

## Trust and resolution

1. Load the existing session snapshot and resolve exactly one revision/output.
2. Use M15 revision/locator validation and the accepted source RunStore record.
3. Resolve the unique completed source turn by the locator's source run. Retained
   outputs use that source turn's completion, not the newer revision's evidence.
4. Read only the canonical evidence filename bound in that completion, under the
   existing managed workspace. Do not create missing presentation directories.
5. Validate the evidence digest, strict JSON, schema, run/plan/trace identities,
   tool contract, exact step and dependencies. Base projected facts must agree
   with the accepted lightweight result. Derived facts come only from the pinned
   existing evidence projection, never arbitrary extra result fields.
6. Return bounded facts with JSON-pointer attribution and captured visibility.

This uses the existing trusted-local session/RunStore boundary. Checksums are
not authentication against an actor who can replace the trusted stores and all
their anchors. Evidence access does not establish current raw-source freshness,
artifact integrity beyond the consumed evidence bytes, or fresh scientific
validity. Required evidence failure has no reconstruction or report fallback.

## Diagnosis

The actual path is `respond` → immutable reference capture → operational/public
dialogue context → `interpret` → existing typed decision → admission → scientific
context/generation. Clarifications from the provider were accepted directly;
operational answers did not pass through scientific generation.

Before hardening, scientific output metadata supplied handles, output names,
tool IDs, versions and relations. It supplied a durable predecessor when one
existed, but no evidence availability, field inventory, registry description,
result contract or subjects. The operational context emphasized selection
operations and matrix-recipe availability. Instructions enumerated operational
intents but gave relatively little guidance about scientific meaning versus
state, and unavailable targets versus insufficient rationale.

These are concrete context/instruction gaps, not proof of the model's internal
reasoning. The previous model had enough metadata to identify QC by name, but
could not directly know that its accepted summary was readable. Its first
clarification created no successful scientific predecessor, so the subsequent
“Why?” had no durable scientific focus. Choosing matrix provenance then was an
unsupported conversational topic choice, not evidence that persisted QC focus
had changed.

## Production changes

`scientific_dialogue.public` now projects a bounded, read-only inventory:

- existing exact offered handles, names, tool IDs, versions and relations;
- explicit current-output status;
- M16.1 evidence status and up to 32 available field names, with omission flag;
- up to 32 subject IDs, with truthful completeness, using the existing subject
  adapter (currently annotation group summaries);
- deduplicated descriptions, result-contract identities and producer role/type
  descriptors from the existing Registry;
- unchanged structured predecessor target, comparison/previous subject and user
  question, with ambiguity status.

No scientific field values, paths, digests or generated prose enter this new
projection. Descriptions are capped at 1,200 characters; subject IDs at 128
characters; target inventory at the existing 128 outputs and 128 KiB. Overflow
fails closed. This is ephemeral, not new persisted session state or authority.
M16.1 reads check accepted evidence without owner verification or reconstruction.
Later answer admission/generation retain their existing fresh evidence checks.

`turns.respond` supplies the session facade for these reads. `turn_decisions`
instructions now explicitly separate scientific interpretation, operational
state, execution, navigation and clarification. Resolvable short scientific
follow-ups use the durable focus; missing rationale is answered as insufficient
evidence rather than pretending the target is unavailable. Genuine ambiguity
still requires clarification. No capability-specific lexical router or provider
decision override was added.

A live follow-up exposed an additional narrow admission defect: the model chose
the exact focused QC handle, rather than spelling `@focus`, and the existing
multiple-output literal-name check rejected it. Admission now accepts a direct
handle matching **all three** durable target anchors: revision ID, output name
and accepted-step digest. Other direct handles still require the existing
disambiguation. No first-match or transcript inference is introduced.

## Live evidence

The same Groq `openai/gpt-oss-120b`, Agent Conda configuration, accepted PBMC
session and `respond` interface were retained. Exactly one initial QC retest
was made. Provider calls are spaced by at least 65 seconds to respect the known
TPM limit; SDK retries and fallback remain disabled.

The interpreter selected `answer_scientific`, target `r2`, current QC. Scientific
generation returned `support=supported` and a durably answered interaction.
This is the first live scientific-generation result in M16.2. Its structured
claim values and source references bind to the accepted QC result.

However, explanatory prose misinterpreted accepted facts:

- `n_qc_fragment_records` was described as fragments retained after QC filtering;
  this is a QC-contig record count, not a newly filtered selection.
- `resource_qualification=operator_qualified` became a claim that QC was performed
  by a qualified operator; it describes resource qualification.
- `nucleosome_defined`/`nucleosome_undefined` were described as numbers of fragments;
  they count observed barcodes with defined/undefined metrics.
- `tss_defined` and `tss_undefined` were framed as subsets of TSS-center counts,
  while enrichment-ratio extrema were described as TSS counts.

These are concrete unsupported interpretations, not a failure merely because
free-prose entailment is unproved. Structured claims remain exact, but surrounding
prose is scientifically misleading and dominated by raw field/ratio components.
The provider misused fields; the generation context's bare field names and
limited reviewed meanings offer insufficient unit/scope help. Precise causal
attribution between context and provider cannot be established from this sample.
No answer-generation rewrite or scientific semantics change was made in this task.

The live “Why?” retained the same QC handle but was clarified by the direct-handle
admission defect described above. That turn was not repeated live after the fix;

## Changed files and remaining limits

Incremental production changes are in `scientific_dialogue.py`, `turns.py` and
`turn_decisions.py`; the existing provider schema fix is retained. New tests are
in `tests/application/test_dialogue_intent_context.py`. Documentation changes are
this record and `docs/m16.2-scientific-dialogue.md`. Local ignored harnesses,
sanitized provider replies, isolated session records and the tiny inspection
fixture are under `outputs/m16.2-intent-hardening/`.

Scientific intent is still an LLM decision, not a deterministic keyword
classifier. The application does not guarantee rejection of every semantically
wrong operational choice. Exact offered handles and durable focus are enforced;
natural-language interpretation remains imperfect. Ordinary direct handles
among multiple outputs retain the existing explicit-name rule unless they
match the exact durable focus. Subject IDs are exact, not normalized from prose.
This task did not broaden semantic aliases, historical subject matching or
subject support beyond the existing adapter.

The first live generation now supplies concrete evidence that structured claim
binding alone does not ensure correct prose units, meaning or usefulness.
Next work should be narrowly scoped to exact subject-ID choice, adherence to
the slot contract, and reviewed field units/scope for explanatory prose, without
changing scientific algorithms or adding M16.3 evidence. Do not tune against a
large benchmark or rerun repeatedly to obtain a pass.

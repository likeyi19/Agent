# M16.2 — Multi-turn grounded scientific dialogue

M16.2 extends `AnalysisSessions.respond` with scientific `Answer` requests.
M16.1 evidence access remains unchanged. Scientific execution, verification,
authority, session revision activation, navigation and recovery keep their
existing owners. No scientific algorithm, report generator, Planner/compiler,
EpiZoo code or scientific Registry contract changes.

## Unified interface

```python
outcome = app.sessions.respond(
    session_id, turn_id, utterance,
    interpreter=model,
    # Optional integration settings, not user-facing conversation modes:
    answerer=None,                 # defaults to the interpreter's complete API
    predecessor_turn_id=None,      # explicit discussion branch when needed
    execution_inputs=None,         # structured inputs for new scientific work
)
```

Providers use the existing `complete(prompt=..., response_schema=...)` convention.
Strict-provider decision schemas use distinct wire tags `answer_scientific` and
`execute_plan` to avoid overlapping `anyOf` discriminators. Parsing normalizes
them to the existing `Answer` and `Execute` decisions before admission; existing
decision forms remain accepted. This changes neither stored intent nor grounding.
The same turn interpreter can select existing Execute/Navigate/Clarify/operational
Answer decisions, a scientific Answer, or an explicit new-science planning route.
Scientific answers call a second bounded generation request. No transcript or
previous generated prose is supplied as scientific evidence.

The interpretation inventory now includes current/historical status, read-only
M16.1 evidence availability, up to 32 available field names and 32 subject candidates
per output, and descriptions/result contracts/producer roles derived from the
existing registry. No scientific values are supplied at this stage. Truncation
is explicit; the complete inventory is capped at 128 KiB and oversized context
fails closed. The existing output-reference cap remains 128. These ephemeral
descriptors are not stored in session snapshots or treated as scientific truth.
Answer admission and generation reload exact evidence as before.

Subject candidates contain canonical IDs and bounded literal reference forms.
Reference forms include the canonical ID and, when present in the current user
utterance, a contiguous preceding word plus that exact ID (at most four forms,
128 characters each). These are quoted user spans, not inferred scientific
display names or a global alias registry. A returned form must match exactly one
offered candidate for the chosen result. Collisions and unknown forms fail
closed; only the canonical ID persists. No prefix stripping or fuzzy matching.

Decision instructions distinguish scientific interpretation from operational
state and execution, direct resolvable short follow-ups to the durable scientific
predecessor, and distinguish unavailable targets from insufficient explanatory
evidence. They do not deterministically classify natural-language questions or
override provider decisions with capability-specific rules. Provider intent
quality still needs live qualification.

`Answer('scientific', scientific=ScientificQuestion(...))` uses an output target,
optional subject, optional comparison target, and `question` versus `continue`
focus. These are reference operations, not capability-specific intent machines.
The natural-language focus remains the user's current or prior question.

## Reference and predecessor semantics

The immutable interaction snapshot gains optional `dialogue` reference metadata.
The existing session envelope/schema version and top-level storage fields remain
unchanged; the snapshot validator explicitly admits and checks this extension.
Old M15 records remain readable. No second session, focus store or projection
artifact is introduced.

Snapshots offer bounded opaque output handles. Admission resolves these to exact
revision/output/accepted-step references. Explicit subject strings must appear in
the question; `@focus`, `@previous` and `@other` have deterministic reference
semantics. Arbitrary historical targets require an explicit revision relation or
version reference. Multiple possible outputs/subjects clarify rather than using
the first result. Current output absence never authorizes a historical fallback.
The catalog allows the existing M15 bound across all three revision relations;
metadata already loaded by turn capture is reused rather than reloading each
source solely to label the catalog.

Successful interactions retain only target, comparison, previous subject,
explanatory question and predecessor identity. They retain no scientific claim
values or generated prose. Every follow-up reloads M16.1 evidence.

Without an explicit predecessor, the application captures the unique successful
scientific discussion leaf for the captured active revision. Pending answers or
multiple leaves disable implicit focus. Explicit predecessor IDs must identify
an already answered scientific interaction in the same session. Completion order
does not choose focus. Capture checks both generation and interaction history;
racing capture fails with a conflict rather than silently changing predecessor.
Reordered concurrent answers can be continued by selecting their exact branch.

Navigation/analysis changes do not silently carry an old implicit discussion into
a new active base. Explicit historical references remain available. Same-turn
retries preserve admitted targets and reload evidence without reinterpreting the
question; prose can be regenerated because it is not persisted as truth.

## Evidence and subjects

One context path reads M16.1 evidence for at most two exact targets. It offers
bounded scalar facts, including leaves of compact reviewed mappings, with their
field identities. Internal paths/hashes are not given to the language provider.
The returned application claim records retain exact revision, output locator,
evidence digest and JSON-pointer attribution.
Evidence is reloaded after generation as well. Changed evidence fails closed;
navigation during generation marks the unchanged captured target historical.

The first within-result subject selector is the existing annotation
`group_summary` keyed by exact `group`. It performs no annotation inference.
An omitted group is unavailable in this summary, never biologically absent.
`@other` is admitted only when the summary declares complete coverage and exactly
one alternative exists. Detailed marker rationale and sidecar drill-down remain
deferred. Other capabilities use whole-result targets through the same path.

Comparison is descriptive: same tool, compatible available species/assembly,
method/profile/reference/feature identities, and exact result operands. Subject
labels from different results are not silently treated as corresponding
clusters. No statistical tests, deltas, significance or causal effects are
computed in the dialogue layer. Supported comparison answers must cite both
operands.

Context is bounded to 64 claims and 32 KiB of serialized evidence context; the
existing bounded utterance and user focus are supplied separately. Coverage and
omission metadata remain explicit. Small reviewed method/scope notes live beside
the context adapter; they are not scientific engines or evidence authorities.
The TSS explanation is offered only when the accepted QC method and scientific
profile match the existing frozen owner profile; no ratio is computed here.

## Generation and the exact guarantee

Generation wire version 2 uses ordered paragraph parts: `text` with connective
prose, `claim` with an offered claim ID, or `meaning` with an offered reviewed
meaning ID. The model selects references once; it does not repeat magic strings
in prose or maintain a second list of referenced IDs. The former text-slot wire
format is rejected. Generated prose was never persisted, so durable references
and session schemas do not require migration.

The model cannot provide replacement subject, field or value members. Each claim
part renders a whole target/subject/predicate/value record. Reviewed report labels
and Registry field descriptions are transported verbatim where available;
missing metadata stays absent. The exact frozen owner QC profile is also exposed
by the existing method/profile identity check. No new field units are inferred.
Unknown IDs, extra properties, raw numeric literals,
raw supplied categorical values and missing comparison operands fail closed.
Generation failure returns no scientific response. Insufficient evidence is a
normal supported outcome and receives an explicit limitation sentence.

`outcome.scientific` contains immutable `ScientificClaim` records, support status,
explanation and limitations. Those factual records and inserted claim parts have
deterministic evidence bindings. Model-authored explanation is not scientific
authority and never feeds execution or subsequent factual context.

This does **not** prove arbitrary natural-language entailment. Literal checks
are defense in depth, not a complete detector for qualitative overclaims,
paraphrases or unsupported categorical assertions in free prose. The provider
is instructed to explain supplied claims/meanings only. Flexible explanation
therefore has a different assurance level from the structured scientific
substrate; no universal hallucination-free prose claim is made. Scripted tests
qualify the application contract, not live-provider language quality.

## New scientific computation

Explicit new-science commands may select `Execute(operation='plan', target=<a
registered tool>, base='current', delta=None)`. They use the original utterance
and caller-supplied structured inputs with the existing Planner/Application.
Before execution, the provider explicitly selects output members from the actual
plan; code validates those selections. There is no inferred terminal-output
fanout, implicit retained outputs, or workflow completion. Missing inputs or
invalid plans fail on the existing execution path. This route adds no new
scientific capability or automatic legacy-result prior-output binding.

The existing M15 threshold execution route remains unchanged and keeps its
existing exact prior-output reuse. Explicit command-language admission prevents
a result question from authorizing execution and rejects scientific-answer
misrouting for covered command forms. This is bounded command-language support,
not universal linguistic classification. Next-step discussion and autonomous
next-step execution remain deferred.

## Focused validation

The tests cover the real admission/provider/response/session APIs with scripted
providers across QC, selection, annotation, matrix, adaptation and inspection.
They cover short follow-ups, subject changes, prior-subject comparison, exact
cross-revision operands, historical references, provenance, missing/truncated
evidence, insufficient conclusions, changed evidence on reload, malformed
generation, concurrency, retries and fresh-process continuity without prose.

Tiny owner-produced tests interleave explanation, M15 threshold execution,
scientific comparison and rollback. Answer/navigation regions instrument zero
scientific production, owner reconstruction and presentation work. Separately,
an explicitly requested registered inspection executes through the ordinary
Planner/executor and publishes a normal accepted revision.

No full regression, live-provider benchmark, commit or push is part of M16.2.
M16.3 is not started. Detailed sidecar rationale, broader subject adapters,
scientific correspondence, literature, new algorithms and autonomous next-step
execution remain outside this change.

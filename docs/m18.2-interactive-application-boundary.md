## Public application contract

`agent.application.InteractiveAgentApplication` is a synchronous Python client
of the existing research application. It introduces no transport, dependency,
job queue, scientific tool, Planner, or scientific authority.

The operator supplies existing `PlanningModelProfile` values, one configured
default ID, and optionally the existing `PlanningModelFactoryRegistry`, display
labels, Registry/executor, wire mode, and explicit planning recovery settings.
Only enabled structured-output profiles with a registered factory are offered.
Admission is an operator configuration decision, not model-name syntax or live
provider qualification. SDK/credential failures are sanitized at construction.

```python
from agent.application import InteractiveAgentApplication

app = InteractiveAgentApplication(
    approved_workspace,
    model_profiles=(operator_admitted_profile,),
    default_profile_id=operator_admitted_profile.profile_id,
    planning_model_factory_registry=operator_factories,
)
session = app.create_session("analysis-1")
choices = app.model_choices()
turn = app.submit_turn(
    "analysis-1", "client-turn-1", "Inspect the supplied matrix.",
    expected_generation=session.generation,
    execution_inputs={"input_path": explicitly_supplied_local_input},
)
client_payload = turn.to_dict()
history = app.reopen_session("analysis-1")
checkpoint = app.status("analysis-1", "client-turn-1")
```

Other operations are `turn`, `recover_turn`, `cancel_turn`, `artifact_handles`,
and `resolve_artifact`. `reopen_session(limit=100)` bounds history (maximum
1,000 entries per collection) and explicitly reports truncation. It lists legacy
non-interaction turn metadata before captured interactions; this is a projection
policy, not a reconstructed chronology. Session enumeration is absent.

Client schemas are frozen explicit views: `SessionView`, `RevisionView`,
`TurnView`, `StepView`, `PresentedResponse`, `ModelChoice`, `ClientError`, and
`ArtifactHandle`. Boundary failures raise `InteractiveBoundaryError`; its
`.error` is safe JSON, with the typed internal exception retained as a cause.
No storage locations, executable bindings, resolved arguments, authority
payloads, SDK schemas, credentials, or exception prose enter these views.
User utterances remain the user's supplied text, rather than server metadata.

## Initial admission and unchanged science

An empty Session has an interaction base of `None`, generation zero, and empty
captured revision relations/outputs. No synthetic Revision is created.
The existing interpreter sees the registered tool inventory and chooses the
existing decision contract. Explicit `execute_plan` enters the ordinary
`AgentRequest` and configured scoped Planner. Existing semantic compilation,
preflight, actual-plan output selection, runtime, verification, and application
composition create the first accepted Revision.

Clarification and the existing unsupported-answer branch can complete without a
Revision. Revision-dependent questions, guidance, navigation, and QC deltas
clarify unavailable context. There is no initial tool shortcut or inferred
output selection. Explicit inputs remain required by their existing contracts.

## Durable submission and displayed history

Existing `Interaction` records gain two optional, frozen fields:

- `submission`: exact selected profile/configuration fingerprint, observed
  generation, structured inputs, and explicit predecessor. The utterance and
  turn identity remain existing immutable interaction fields.
- `presentation`: one closed, versioned, immutable displayed response, written
  before returning completion to the caller.

Absent optional fields remain absent on serialization, preserving legacy
session shapes. Existing schema-1 sessions remain readable; compatibility with
older software reading newly extended records is not claimed.

Presentation stores exact text, clarification metadata, scientific support/
limitations/scope, guidance references and rendered explanations, and safe
application errors. It stores no second structured scientific claim-value table
or authority. Guidance ordinals resolve against the persisted original inventory.
Presentation is never supplied to Planner, dialogue evidence, or guidance as
scientific truth.

The same submission ID/content returns stored presentation or the last durable
checkpoint without constructing a provider. Conflicting reuse fails closed.
Generation checks apply to new submissions; a completed retry retains its
original generation. A short nonblocking per-interaction processing lease prevents
concurrent duplicate processing across local processes. Existing scientific
run leases and generation-checked activation remain authoritative.

History reads never regenerate responses. Missing legacy presentation is
explicitly unavailable. Direct replay of an interaction with stored presentation
also returns that presentation without the answerer. Legacy low-level Session
calls without interactive records retain their pre-existing contracts.

A crash before scientific linkage does not authorize reinterpretation or
replanning. Explicit `recover_turn` reconciles existing SessionTurn records and
can render a previously undisplayed terminal execution completion without a
provider. `complete_presentation=True` explicitly invokes the existing completion
operation; it is not a polling read. Historical displayed replies remain immutable.
Runtime resume remains the existing explicit planner-free application operation.

## Status, results, and model ownership

Status projects existing interaction/turn metadata and RunStore lifecycle:
`interpreting`, `admitted`, `planning`, `validated`, `running`, `succeeded`,
`failed`, `interrupted`, and `cancelled`, with `finalizing` when scientific
success lacks accepted application completion. Safe application errors remain
visible alongside incomplete finalization. Steps retain their existing five
statuses and attempt counts. State revision is the RunStore checkpoint revision.
No percentage, ETA, heartbeat, or worker-liveness claim exists.

Revision views expose exact IDs, parent, active status, and output names.
Report/PNG handles bind exact Session completion files and accepted digests.
`resolve_artifact` checks only pinned presentation bytes and returns a safe handle;
it returns no path or raw document. Evidence/manifests and raw report delivery
remain outside this client identity interface. Reads reconstruct no science.
Existing `sessions.evidence` retains evidence ownership.

Each new semantic turn gets a separate application/model bundle through the
existing profile factory. Its single client serves interpreter, answerer/guidance,
actual-plan output selection, and Planner. Explicit configured Planner recovery
remains unchanged. Different selected profiles never mutate another turn's
Planner/client. Model selection is per-turn application configuration, not
scientific Revision state. No browser model-selector or provider registry exists.

## Validation

Focused tests are the three `tests/application/test_interactive_*.py` files.
They use scripted clients, a two-cell by three-feature sparse H5AD, the actual
scoped semantic Planner/compiler/preflight/runtime, and existing accepted metadata
fixtures. Coverage includes first execution and clarification, completed and
pending retries, conflicting IDs, stale generation, model isolation, exact
scientific/guidance history across subprocesses, cancellation/status, safe errors,
missing legacy presentation, recovery, and pinned artifact identity.

The two-process acceptance test starts an empty Session, inspects admitted choices,
executes its first request, and checks one inspection production call and four
logical model calls. A separate process reopens and retries with provider
construction forbidden, preserving the exact displayed response and usable
accepted evidence. An unoffered profile fails before provider construction.
These checks qualify application behavior, not live-provider quality or biology.

HTTP, frontend assets, session enumeration, automatic recovery of incomplete
interpretation/planning, raw artifact download, fine-grained progress, and
reporting-stage cancellation remain deferred. No full repository regression,
large scientific acceptance, commit, or push is part of M18.2 development.
